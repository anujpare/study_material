HW3 1b · Which setup model?

The sheet asks whether we can construct non-interactive zero-knowledge proofs for NP “in the standard model (without a random oracle)”. Explain why the setup model matters.

Show step-by-step solution

  1. A language is the set of true statements. NP means a true statement has a short witness that can be checked efficiently. BPP means an efficient randomized algorithm decides membership, with error at most on each input. Neither definition says every NP problem is in BPP.

  2. In the plain model, the verifier has only the statement, proof and public algorithm description. There is no trusted common reference string (CRS) and no random oracle. A NIZK simulator produces an accepted-looking proof for a true statement without its witness.

  3. Run that simulator on the input and give its output to the verifier. On true inputs, zero knowledge and completeness imply high acceptance. On false inputs, soundness bounds acceptance, because the simulator is an efficient candidate prover. A standard bounded-time simulation (with a timeout if needed) therefore gives a BPP decision procedure.

  4. Consequently, plain-model NIZKs for all NP languages would imply , which is not expected. This is the intended “likely false” answer. But standard model does not necessarily mean plain model: a CRS is compatible with the standard model, and CRS-based NIZKs for NP exist under suitable assumptions. “No random oracle” alone does not justify an impossibility claim.

HW3 1d · Hashing does not strengthen privacy

True or false: applying Fiat–Shamir to a Sigma protocol always gives statistical zero knowledge.

Show step-by-step solution

  1. A Sigma protocol has a first message, a random challenge and a response. Its honest-verifier zero-knowledge property may be only computational: efficient observers cannot distinguish a real transcript from a simulated one, but an unlimited observer might.

  2. Fiat–Shamir replaces the verifier’s challenge with a hash of the statement and first message. It changes how the challenge is obtained. It does not remove information that an unlimited observer could already recover from those messages.

  3. The claim is false. Statistical zero knowledge must hold even against unlimited distinguishing computation; computational HVZK is not enough to conclude that stronger property. Any Fiat–Shamir security claim also needs the appropriate random-oracle theorem and protocol assumptions.

HW3 2d · Can a proof be passed on?

A verifier accepts a NIZK for a statement. Can it convince another verifier? Compare this with passing on the recorded conversation from an interactive zero-knowledge proof.

Show step-by-step solution

  1. A publicly verifiable NIZK is a proof string . A second verifier with the same statement and public setup can run the same verification algorithm on that string. Copying the proof does not require knowing its witness.

  2. For an interactive ZK proof, the first verifier’s recorded view includes its challenges and the prover’s responses. Zero knowledge promises that an efficient simulator can generate an indistinguishable view without the witness.

  3. Therefore that recorded view alone does not establish to a third party that a real prover participated: it could have been simulated. The distinction is between a transferable public proof and a simulatable record of an interaction. This argument concerns recordings; it is not a claim that every live relay attack is impossible.
