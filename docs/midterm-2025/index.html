Problem 2: Private Set Intersection [ / 25 marks]

Definition 1 (Private Set Intersection). A two-party Private Set Intersection (PSI) protocol allows Alice with input set \(A\subseteq X\) and Bob with input set \(B\subseteq X\), where \(|A|\le N\) and \(|B|\le N\), to learn the intersection \(A\cap B\) and nothing else (except for the upper bound \(N\) on the size of both sets). We require the following properties:

  • Correctness: For all \(N\le |X|\) and \(A,B\subseteq X\) with \(|A|\le N\) and \(|B|\le N\), at the end of an honest execution of the protocol, Alice and Bob output \(A\cap B\) (except with negligible probability in a security parameter \(\lambda\)).
  • Semi-honest privacy for Alice’s set: there exists an efficient simulator \(\operatorname{Sim}^{\mathrm{PSI}}_{\mathrm{Bob}}\) for Bob’s view such that for all valid \(N,A,B\), we have \(\operatorname{Sim}^{\mathrm{PSI}}_{\mathrm{Bob}}(N,B,A\cap B)\approx_c\operatorname{View}_{\mathrm{Bob}}\).
  • Semi-honest privacy for Bob’s set: analogous to the above, but for Alice’s view. That is, there exists an efficient simulator \(\operatorname{Sim}^{\mathrm{PSI}}_{\mathrm{Alice}}(N,A,A\cap B)\) for Alice’s view.

Problem 2(d) · OPRF definition

Printed in the 2025 exam · Page 5

(d) Below is the definition of an Oblivious Pseudorandom Function (OPRF).

Definition 2 (Oblivious PRF). An Oblivious Pseudorandom Function (OPRF) for a PRF \(F:K\times X\to Y\) is a two-party protocol where the server samples a key \(k\xleftarrow{\$}K\) and then interacts with a client with input(s) \(x\in X\) so that the client learns \(F(k,x)\in Y\) (and nothing else about \(k\)) and the server learns nothing about \(x\). The properties of the OPRF protocol are:

  • Correctness: For all \(k\in K\) and any sequence of inputs \(x_1,\ldots,x_q\in X\), if an honest client and server run \(q\) independent instances of the protocol under the same key \(k\), then the client’s \(i\)-th output equals \(F(k,x_i)\) with probability 1.
  • (Semi-honest) privacy for the client: There exists an efficient simulator \(\operatorname{Sim}^{\mathrm{OPRF}}_{\mathrm{Server}}\) such that for all \(k\in K\) and \(q\in\mathbb N\), the output of \(\operatorname{Sim}^{\mathrm{OPRF}}_{\mathrm{Server}}(k,q)\) is computationally indistinguishable from the view of the server in an honest execution of the protocol where the client makes \(q\) queries.
  • (Semi-honest) privacy for the server: There exists an efficient simulator \(\operatorname{Sim}^{\mathrm{OPRF}}_{\mathrm{Client}}\) such that for all \(q\in\mathbb N\) and \(k\in K\), for any sequence of non-adaptively chosen inputs \(x_1,\ldots,x_q\in X\) and outputs \(y_i=F(k,x_i)\in Y\), the output of \(\operatorname{Sim}^{\mathrm{OPRF}}_{\mathrm{Client}}(x_1,\ldots,x_q,y_1,\ldots,y_q)\) is computationally indistinguishable from the view of the client in an honest execution of the protocol.

Problem 3: A Private Voting System [ / 25 marks]

Definition 3 (2-server private voting system). A 2-server private voting system is a protocol that allows an arbitrary number of voters to privately vote for one of \(N\) candidates, with a voting tally that is secret-shared across two servers \(S_0,S_1\).

The vote tally is a vector \(\mathbf v\in\mathbb Z_p^N\) (for a prime \(p\) much larger than the number of voters) that is additively secret-shared across two servers \(S_0,S_1\) as \(\mathbf v=\mathbf v_0+\mathbf v_1\pmod p\), and initially set to \(\mathbf v_0=\mathbf v_1=\mathbf 0\). A voter with vote for candidate \(i\in[N]\) should increment the \(i\)-th element of \(\mathbf v\) by 1 so that, after all votes, the servers reveal \(\mathbf v_0,\mathbf v_1\) and their sum \(\mathbf v\), which reveals the total number of votes cast for each candidate.

The system should satisfy:

  • Correctness: If all parties are honest, then after all votes, \(\mathbf v=\mathbf v_0+\mathbf v_1\pmod p\) contains the total number of votes cast for each candidate.
  • Privacy: For each server \(S_\beta\), there exists a simulator \(\operatorname{Sim}^{\mathrm{Voting}}_\beta\) that is given the final tally \(\mathbf v\) as input and generates a view that is computationally indistinguishable from the view of server \(S_\beta\) in an execution of the protocol.

(a) Argue (informally) why we cannot build such a system using a generic secure PIR, ORAM or SNARG protocol.

Given in the original exam: Problem 3 · Voting system definition

Problem 3: A Private Voting System [ / 25 marks]

Definition 3 (2-server private voting system). A 2-server private voting system is a protocol that allows an arbitrary number of voters to privately vote for one of \(N\) candidates, with a voting tally that is secret-shared across two servers \(S_0,S_1\).

The vote tally is a vector \(\mathbf v\in\mathbb Z_p^N\) (for a prime \(p\) much larger than the number of voters) that is additively secret-shared across two servers \(S_0,S_1\) as \(\mathbf v=\mathbf v_0+\mathbf v_1\pmod p\), and initially set to \(\mathbf v_0=\mathbf v_1=\mathbf 0\). A voter with vote for candidate \(i\in[N]\) should increment the \(i\)-th element of \(\mathbf v\) by 1 so that, after all votes, the servers reveal \(\mathbf v_0,\mathbf v_1\) and their sum \(\mathbf v\), which reveals the total number of votes cast for each candidate.

The system should satisfy:

  • Correctness: If all parties are honest, then after all votes, \(\mathbf v=\mathbf v_0+\mathbf v_1\pmod p\) contains the total number of votes cast for each candidate.
  • Privacy: For each server \(S_\beta\), there exists a simulator \(\operatorname{Sim}^{\mathrm{Voting}}_\beta\) that is given the final tally \(\mathbf v\) as input and generates a view that is computationally indistinguishable from the view of server \(S_\beta\) in an execution of the protocol.
Learn the prerequisites · 3 focused steps
Step 1 / 3

Reveal step-by-step solution
  1. PIR solves a different operation

    PIR privately retrieves an existing database entry. It does not, by itself, supply a private update to two servers' shares.

  2. ORAM assumes a different architecture

    ORAM hides reads and writes to a client's outsourced private memory, typically using client state and a single logical memory. That is not the stated setup of arbitrary stateless voters and a two-server shared tally.

  3. A SNARG checks a claim

    SNARGs efficiently prove that a computation or claim is valid; alone they do not secretly select and apply a tally increment. We still need a privacy-preserving update protocol.

Definition 4 (Distributed Point Function). A distributed point function (for two servers) is a pair of poly-time algorithms \((\mathrm{Gen},\mathrm{Eval})\) with the following syntax:

  • \(\mathrm{Gen}(x,y)\), where \(x\in X,y\in Y\), outputs a pair of keys \((k_0,k_1)\).
  • \(\mathrm{Eval}(k,x')\), where \(k\in\{0,1\}^{*},x'\in X\), outputs \(y'\in Y\).

Correctness: For all \(x,x'\in X,y\in Y\) and \((k_0,k_1)\leftarrow\mathrm{Gen}(x,y)\),

\[\mathrm{Eval}(k_0,x')+\mathrm{Eval}(k_1,x')=\begin{cases}y&\text{if }x'=x\\0&\text{otherwise}.\end{cases}\]

Secrecy: For \(\beta\in\{0,1\}\), there exists a simulator \(\operatorname{Sim}^{\mathrm{DPF}}_{\beta}\) such that for all \(x\in X,y\in Y\): \(\operatorname{Sim}^{\mathrm{DPF}}_{\beta}(|x|,|y|)\approx_c\{k_\beta:(k_0,k_1)\leftarrow\mathrm{Gen}(x,y)\}\).

Given in the original exam: Problem 3(b) · DPF definition

(b) Below is the definition of a distributed point function (DPF).

Definition 4 (Distributed Point Function). A distributed point function (for two servers) is a pair of poly-time algorithms \((\mathrm{Gen},\mathrm{Eval})\) with the following syntax:

  • \(\mathrm{Gen}(x,y)\), where \(x\in X,y\in Y\), outputs a pair of keys \((k_0,k_1)\).
  • \(\mathrm{Eval}(k,x')\), where \(k\in\{0,1\}^{*},x'\in X\), outputs \(y'\in Y\).

Correctness: For all \(x,x'\in X,y\in Y\) and \((k_0,k_1)\leftarrow\mathrm{Gen}(x,y)\),

\[\mathrm{Eval}(k_0,x')+\mathrm{Eval}(k_1,x')=\begin{cases}y&\text{if }x'=x\\0&\text{otherwise}.\end{cases}\]

Secrecy: For \(\beta\in\{0,1\}\), there exists a simulator \(\operatorname{Sim}^{\mathrm{DPF}}_{\beta}\) such that for all \(x\in X,y\in Y\): \(\operatorname{Sim}^{\mathrm{DPF}}_{\beta}(|x|,|y|)\approx_c\{k_\beta:(k_0,k_1)\leftarrow\mathrm{Gen}(x,y)\}\).

Learn the prerequisites · 5 focused steps
Step 1 / 5

Reveal step-by-step solution
  1. 1. Generate one point function for one ballot

    If the voter selects candidate \(i\), call \((k_0,k_1)\leftarrow\mathrm{Gen}(i,1)\). Send the first key to \(S_0\) and the second to \(S_1\). Nothing else about the chosen index is sent.

  2. 2. Each server expands its own key locally

    For server \(S_\beta\), evaluate \(\mathrm{Eval}(k_\beta,j)\) at each candidate position \(j\in[N]\) and collect these values into \(\mathbf s_\beta\). The server updates its existing tally share as \(\mathbf v_\beta\leftarrow\mathbf v_\beta+\mathbf s_\beta\pmod p\).

  3. 3. Prove correctness at every coordinate

    DPF correctness says the evaluated shares add to the point function:

    \[s_0[j]+s_1[j]=\begin{cases}1&j=i\\0&j\ne i.\end{cases}\]

    Therefore \(\mathbf s_0+\mathbf s_1=\mathbf e_i\): exactly one candidate’s count increases by one. Repeating this for all voters and adding the resulting vectors yields the correct final tally.

  4. 4. Count the actual bits sent by the voter

    Each DPF key has length \(\ell\) bits. Two keys are transmitted, so the total is \(\ell+\ell=2\ell=O(\ell)\) bits per vote. The server’s length-\(N\) vector is computed locally; the voter does not transmit it.

  5. 5. Simulate one server without the chosen candidates

    For each server \(S_\beta\), a simulator calls the DPF key simulator \(\operatorname{Sim}^{\mathrm{DPF}}_\beta\) independently once for every voter. These simulated keys reveal no indices. The simulator evaluates them and performs the same deterministic local tally updates, obtaining a simulated \(\mathbf v_\beta\).

    When the final tally \(\mathbf v\) is revealed, set the other published share to \(\mathbf v-\mathbf v_\beta\pmod p\). The given \(\mathbf v\) is the only public voting information provided to the simulator. DPF secrecy implies the simulated view of each single server is computationally indistinguishable from its real view.

(c) Let’s address the above issue by adding a validity proof to the protocol. We will have each client prove to the servers (in zero-knowledge) that their vote is well-formed (i.e., that they are updating a single entry of the tally by 1).

Let us define a fully linear Interactive Oracle Proof (IOP) for a language \(L\subseteq\mathbb Z_p^N\).

Definition 5 (Fully linear IOP). A fully linear IOP for a language \(L\subseteq\mathbb Z_p^N\) is an interactive proof system with the following syntax:

  • For any \(\mathbf x\in L\), the prover outputs a proof \(\boldsymbol\pi\in\mathbb Z_p^M\), where \(M=\operatorname{poly}(N)\).
  • The verifier consists of a deterministic query algorithm \(Q\) and a deterministic decision algorithm \(D\).
  • Query algorithm \(Q\) takes random seed \(r\in\{0,1\}^{\lambda}\) and returns \(k\) queries \(\mathbf q_1,\ldots,\mathbf q_k\in\mathbb Z_p^{N+M}\).
  • Decision algorithm \(D\) takes the \(k\) answers \(\langle\mathbf q_i,\mathbf x\Vert\boldsymbol\pi\rangle\in\mathbb Z_p\) to Q's queries, then outputs “accept” or “reject”.

The proof satisfies the standard properties of completeness and soundness. It also satisfies a strong notion of honest-verifier zero-knowledge: the verifier learns nothing about instance \(\mathbf x\) (or proof \(\boldsymbol\pi\)) beyond whether \(\mathbf x\) is in the language or not. Formally, there exists a simulator \(\operatorname{Sim}^{\mathrm{IOP}}\) taking no input that outputs a transcript identical to the verifier’s view in an accepting execution.

Step 1 / 5

Reveal step-by-step solution
  1. 1. Perfect completeness: check both permitted cases

    When \(\mathbf{x}=\mathbf e_i\), the only nonzero coordinate is \(x_i=1\). Thus the two inner products select precisely the \(i\)-th entry:

    \[\langle\mathbf e_i,\mathbf r\rangle^2=r_i^2=\langle\mathbf e_i,\mathbf r_{\rm sq}\rangle.\]

    When \(\mathbf x=\mathbf 0\), both sides equal zero. Both allowed forms pass for every random vector \(\mathbf r\), so completeness is perfect.

  2. 2. Express the test as one polynomial

    For soundness, fix any invalid vote \(\mathbf x\) before the verifier samples its random vector \(\mathbf r\). Subtract the two sides of the test and call the result \(f\):

    \[f(\mathbf r)=\langle\mathbf x,\mathbf r\rangle^2-\langle\mathbf x,\mathbf r_{\rm sq}\rangle.\]

    An invalid vote can pass only if \(f(\mathbf r)=0\). Here polynomial means a sum of products of the random coordinates \(r_1,\ldots,r_N\).

  3. 3. Expand the square, keeping every cross term

    The dot product is \(\langle\mathbf x,\mathbf r\rangle=\sum_{i=1}^N x_i r_i\). Squaring a sum creates two types of terms: squares \((x_ir_i)^2\) and cross products \(2x_ix_jr_ir_j\). Therefore:

    \[\begin{aligned}f(\mathbf r)&=\big(\sum_i x_ir_i\big)^2-\sum_i x_ir_i^2\\&=\sum_i(x_i^2-x_i)r_i^2+2\sum_{i

    Each monomial contains two factors of the random coordinates, so the total degree is at most 2.

  4. 4. Prove that an invalid vote makes f nonzero

    Case A: Exactly one coordinate \(x_i\) is nonzero, but \(x_i\ne1\). Then

    \[f(\mathbf r)=(x_i^2-x_i)r_i^2=x_i(x_i-1)r_i^2\ne0.\]

    Case B: At least two coordinates \(x_i,x_j\) are nonzero. In the expanded expression, the coefficient of \(r_ir_j\) is \(2x_ix_j\ne0\) when \(p\) is odd. No square-only term cancels it. Thus \(f\) is not the zero polynomial in either invalid case.

  5. 5. State Schwartz–Zippel and substitute its parameters

    Schwartz–Zippel lemma: A nonzero polynomial of total degree at most \(d\) evaluated at independent uniformly random elements from a finite set \(\Omega\) in a field vanishes with probability at most \(d/|\Omega|\).

    Here \(d=2\) and each \(r_i\) is uniform over \(\Omega=\mathbb Z_p\) (a set of size \(p\)). Hence:

    \[\Pr_{\mathbf r\leftarrow\mathbb Z_p^N}[f(\mathbf r)=0]\le\frac{2}{p}.\]

    That probability is exactly the soundness-error upper bound for an invalid vote.

  6. 6. Check the subtle assumption on p

    The cross-term argument uses \(2x_ix_j\ne0\), which fails for \(p=2\). Indeed in \(\mathbb Z_2\), \((a+b)^2=a^2+b^2\) and the test accepts some invalid vectors. The intended voting setup already requires a prime \(p\) much larger than the number of voters; for this proof \(p\) must be odd.

Step 1 / 7

Reveal step-by-step solution
  1. 1. State precisely what has to be validated

    The client claims its vector \(\mathbf x\) is one standard basis vector, meaning \(\mathbf x=\mathbf e_i\) for some candidate \(i\). The two servers already hold additive shares \(\mathbf s_0,\mathbf s_1\) with \(\mathbf x=\mathbf s_0+\mathbf s_1\pmod p\). They must reject invalid vectors without learning which \(\mathbf e_i\) was selected.

  2. 2. Create and secret-share the proof itself

    The voter follows the IOP prover and generates \(\boldsymbol\pi\in\mathbb Z_p^M\). Choose \(\boldsymbol\pi_0\) uniformly at random, then calculate \(\boldsymbol\pi_1=\boldsymbol\pi-\boldsymbol\pi_0\pmod p\). Send \(\boldsymbol\pi_\beta\) only to \(S_\beta\), for \(\beta\in\{0,1\}\).

    Each server now has its own pair \((\mathbf s_\beta,\boldsymbol\pi_\beta)\), but never receives the full \(\mathbf x\) or full proof \(\boldsymbol\pi\).

  3. 3. Generate all k verifier queries from the common seed

    After the client has committed to its proof shares, the honest servers agree on the same uniform \(\lambda\)-bit random seed \(r\) (one can send \(r\) to the other). Both run the deterministic query algorithm:

    \[Q(r)=(\mathbf q_1,\ldots,\mathbf q_k),\qquad \mathbf q_j\in\mathbb Z_p^{N+M}.\]

    There are k queries, not necessarily three. This is the correction to the published solution.

  4. 4. Compute only the local answers

    Each server calculates the answer to each query using only its own shares:

    \[a_{\beta,j}=\langle\mathbf q_j,\mathbf s_\beta\Vert\boldsymbol\pi_\beta\rangle,\quad j=1,\ldots,k.\]

    The symbol \(\Vert\) joins two vectors end to end: first the \(N\) vote coordinates, then the \(M\) proof coordinates. Since \(\mathbf q_j\) has \(N+M\) entries, the inner product is a single element of \(\mathbb Z_p\).

  5. 5. Reconstruct the verifier’s answers using linearity

    The two servers exchange their \(k\) scalar answers. For each query \(j\), adding both answers gives:

    \[\begin{aligned}a_{0,j}+a_{1,j}&=\langle\mathbf q_j,\mathbf s_0\Vert\boldsymbol\pi_0\rangle+\langle\mathbf q_j,\mathbf s_1\Vert\boldsymbol\pi_1\rangle\\&=\langle\mathbf q_j,(\mathbf s_0+\mathbf s_1)\Vert(\boldsymbol\pi_0+\boldsymbol\pi_1)\rangle\\&=\langle\mathbf q_j,\mathbf x\Vert\boldsymbol\pi\rangle.\end{aligned}\]

    The second equality is ordinary distributivity: \(\sum_\ell q_\ell(u_\ell+v_\ell)=\sum_\ell q_\ell u_\ell+\sum_\ell q_\ell v_\ell\). Both servers run \(D\) on the reconstructed \(k\) answers to accept or reject.

  6. 6. Verify linearity numerically

    For one toy query modulo 11, let \(\mathbf q=[1,3,2]\) and let the two secret shares be \([4,3,7]\) and \([7,9,6]\). They sum to \([0,1,2]\) modulo 11.

    \[\begin{aligned}a_0&=1\cdot4+3\cdot3+2\cdot7=27\equiv5\\a_1&=1\cdot7+3\cdot9+2\cdot6=46\equiv2\\a_0+a_1&=5+2=7\\\langle\mathbf q,[0,1,2]\rangle&=0+3+4=7.\end{aligned}\]

    No server has to reconstruct the secret vector in order to obtain its one linear answer.

  7. 7. Prove completeness and soundness

    Perfect completeness: For an honest one-hot vote, the client constructs the correct IOP proof. Step 5 reconstructs exactly the IOP verifier’s intended answers, so it accepts with probability 1.

    Negligible soundness error: Even if the client sends malicious proof shares, their sum defines some proof \(\boldsymbol\pi\). For an invalid \(\mathbf x\notin L\), the reconstructed answers are those of the actual IOP verifier applied to this false instance. The assumed soundness theorem therefore limits cheating success to negligible probability.

  8. 8. Prove the validation transcript reveals no vote

    To simulate server \(S_\beta\), start with its independently hidden shares \(\mathbf s_\beta,\boldsymbol\pi_\beta\). The assumed perfect zero-knowledge IOP simulator gives a valid verifier transcript \((r,\mathbf q_1,\ldots,\mathbf q_k,a_1,\ldots,a_k)\) without revealing \(\mathbf x\).

    Compute the server’s own answers \(a_{\beta,j}\) from its shares, then fabricate the answers received from the other server as \(a_{1-\beta,j}=a_j-a_{\beta,j}\pmod p\). These reconstruct the simulated IOP answers exactly. The extra validation transcript is therefore perfectly simulatable, conditional on the existing secret-shared vote; the underlying DPF scheme still provides only computational secrecy for its own keys.

  9. 9. Count communication in bits

    The client sends one proof-share vector of length \(M\) to each server: \(2M\) field elements, which is \(O(|\boldsymbol\pi|)\) when the proof size is measured in bits.

    The servers exchange a shared random seed of \(\lambda\) bits and \(k\) field elements in each direction. Since one element of \(\mathbb Z_p\) needs \(\lceil\log_2p\rceil\) bits, the server-to-server total is:

    \[O(\lambda+2k\log p)=O(\lambda+k\log p)\ \text{bits}.\]
