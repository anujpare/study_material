Lecture 5–8 · Interactive proof systems · Why interaction matters

Why ask the prover questions?

We've seen that an NP witness can convince a verifier by being checked. So why have a conversation at all? Because allowing the verifier to ask unpredictable questions can change what can be proved, how much must be sent, and how much the prover reveals. These are three separate advantages.

More expressive proofs: NP versus PSPACE

NP concerns problems with short, efficiently checkable YES witnesses. Another class, PSPACE, concerns problems solvable using a polynomial amount of working memory. An algorithm may reuse the same memory for many steps, so using little memory does not mean running quickly.

Make the resource distinction concrete

How much time can a tiny amount of memory represent?

Think of a counter that stores \(n\) binary digits. It can count through \(2^n\) different values using only \(n\) bits of memory. This doesn't prove anything about interactive proofs; it simply shows why time and memory are different resources.

The class \(\mathrm{IP}\) contains problems with interactive proofs checked by an efficient randomized verifier. A deep theorem says \(\mathrm{IP}=\mathrm{PSPACE}\). In other words, every problem solvable with polynomial memory admits such an interactive proof, and conversely. We use the theorem as stated in the lecture, not as something established by the counter example.

Less communication: succinctness

Another advantage is that the prover may send far less than an entire witness. That is a question of succinctness: how much information and verification work the proof needs. It is not automatically a privacy guarantee.

Less information revealed: zero knowledge

Our main interest is privacy. Suppose the prover knows a secret witness \(w\). Sending it would convince the verifier, but it would also reveal the secret. A zero-knowledge proof aims to establish the truth of the statement without teaching the verifier anything it could not learn without \(w\). We'll make that claim precise using a simulator.

Do not interchange these three goals

Keep these questions distinct: Which claims can be proved? How much work and communication does the proof require? What new information does the verifier learn?

To reason about these benefits, we'll first say exactly what it means for an interactive proof to accept an honest prover and reject a cheater.
