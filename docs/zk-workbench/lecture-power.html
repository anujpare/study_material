Lecture 5–8 · Interactive proof systems · Why interaction matters

If NP witnesses are already checkable, why interact at all?

A one-shot NP proof can send a witness and let the verifier check it. That already works for every problem in NP. Interaction is useful because it changes what the verifier can establish, how much communication may be required, and what the prover can keep secret. These are three different improvements, not three names for the same property.

More expressive proofs: NP versus PSPACE

In the previous lesson, NP meant that a YES-instance has a short witness which can be checked in polynomial time. Another complexity class, PSPACE, consists of decision problems solvable with polynomial working memory (polynomial space). Memory usage and running time are not the same: an algorithm can reuse its memory across many successive computations.

Make the resource distinction concrete

How much time can a tiny amount of memory represent?

Consider a binary counter with \(n\) bits of memory. It can visit \(2^n\) distinct values using only \(n\) stored bits. This is not an IP proof; it illustrates why a polynomial-space computation need not finish in polynomial time.

A major theorem states that \(\mathrm{IP}=\mathrm{PSPACE}\): a language has an interactive proof with an efficient randomized verifier exactly when it can be decided using polynomial space. Since NP is contained in PSPACE, this tells us that interaction can verify problems beyond the simple “send a polynomial-length NP witness” format. The lecture states this deep theorem but does not prove it; the counter is only a resource example, not a proof of the theorem.

Less communication: succinctness

A short, checkable NP witness can still be too large to transmit. Certain interactive proofs can verify a statement with communication smaller than the witness size. That property is called succinctness. It is about the size of communication (and often verification work), not automatically about privacy.

Less information revealed: zero knowledge

The most relevant improvement for the upcoming ZK construction is different again. A prover may have a valid witness \(w\), but sending \(w\) lets the verifier learn it. A zero-knowledge proof instead aims to convince the verifier that the public statement is true while revealing no efficiently learnable information beyond that truth. The verifier's ability to check and the verifier's access to the witness are separate requirements.

Do not interchange these three goals

Expressiveness: Which YES/NO statements can be proved?
Succinctness: How much must be communicated or checked?
Zero knowledge: What does a verifier learn besides the statement's truth?

We have introduced interaction because it can address meaningful limitations of one-shot proofs. Now the precise security definitions will say which parties are trusted and what probabilities each must guarantee.
