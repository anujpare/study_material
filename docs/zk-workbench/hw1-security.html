Which commitments actually hide and bind a message?

The Hamiltonicity soundness proof relies on binding, while its simulator relies on hiding. Homework 1 tests whether you can prove these properties for a concrete construction rather than infer them from the word “commitment.”

First distinguish the strengths of security

Suppose an observer sees a commitment to one of two messages. Perfect hiding means the distributions of the two commitments are identical, even to an observer with unlimited computing power. Statistical hiding means the distributions are so close that even an unlimited observer can distinguish them only with negligible advantage. Computational hiding permits a difference in distributions but says no efficient adversary can detect it with non-negligible advantage.

Binding concerns a cheating committer, rather than an observer. Perfect binding means a fixed commitment never has valid openings to two different messages. Statistical binding permits only a negligible probability of such a violation, even against unlimited computation. Computational binding requires finding two openings to be infeasible for an efficient adversary. In a deterministic, fixed-parameter scheme, perfect binding is the strongest property, and the lower notions require specifying the experiment and randomness.

HW1 · Problem 1(a)

Is a random-oracle hash commitment hard to open dishonestly?

Claim: in the random-oracle model, we can arrange that recovering a hidden committed message or breaking binding with non-negligible probability requires exponentially many oracle queries. Decide whether this is true.

Solution · identify the randomness and the attacker’s task

True in the intended random-oracle setting. Choose a uniformly random \(\lambda\)-bit salt \(r\) and publish \(C=H(m\mathbin\Vert r)\), where \(\Vert\) means unambiguous concatenation and \(H\) is an ideal random function with \(\lambda\)-bit output. To test a candidate \(m\), an adversary generally needs to guess the hidden salt \(r\); each independent guess hits the chosen salt with probability \(2^{-\lambda}\). With polynomially many guesses, the chance is negligible.

To find two different openings to the same commitment, an attacker must find a hash collision involving differing messages. For a random \(\lambda\)-bit output, the birthday phenomenon requires about \(2^{\lambda/2}\) evaluations for constant collision probability—still exponential in \(\lambda\). Thus the scheme provides computational security in the ROM. It is not perfectly binding: collisions exist for an unbounded adversary, so this cannot automatically replace the perfectly binding scheme assumed in the lecture’s Hamiltonicity theorem.

HW1 · Problem 1(d)

Can we replace the random oracle by SHA-3 and call the result proved?

Solution · distinguish a model theorem from a real-function assumption

False. The proof above relied on the outputs of \(H\) being independent uniform random values at fresh inputs. SHA-3 is one specific deterministic algorithm, not literally a random oracle. Implementing \(H\) with SHA-3 may be reasonable, but the ROM proof alone does not establish the same theorem for this particular hash function.

Two schemes that split hiding and binding

HW1 · Problem 2(a)

\(C=H(r)^m\): is it statistically hiding or statistically binding?

Here \(m\in\mathbb Z_q\), the hash \(H(r)\) is modeled as an element of a cyclic group \(\mathbb G\) of prime order \(q\), and exponentiation uses the group's operation.

Solution · establish a counterexample to each property

Not statistically hiding: when \(m=0\), the commitment is \(H(r)^0=1\), the group identity, for every salt. When \(m\ne0\), the commitment is typically a random group element. Seeing the identity therefore distinguishes a commitment to 0 from one to a nonzero message with substantial advantage.

Not statistically binding: fix a nonidentity group element \(C\). Because a cyclic prime-order group has a discrete logarithm with respect to any nonidentity base, an unbounded committer can choose two salts \(r_1,r_2\) with nonidentity \(H(r_i)\) and compute messages \(m_i=\log_{H(r_i)} C\). For suitable choices with \(m_1\ne m_2\), both openings satisfy \(H(r_i)^{m_i}=C\). Statistical binding cannot rely on discrete logarithms being difficult.

HW1 · Problem 2(b)

\(C=m\oplus r\): can perfect privacy coexist with no binding?

The symbol \(\oplus\) denotes bitwise XOR: each output bit is 1 precisely when the two input bits differ. Take a uniformly random salt \(r\) of the same length as \(m\).

Solution · show both claims explicitly

Perfectly hiding: for any fixed message \(m\), XOR with uniform \(r\) produces a uniformly random \(C\). Thus the commitment distributions are identical for all messages.

Not binding: after publishing any \(C\), the committer can choose any desired opening message \(m'\) and set \(r'=C\oplus m'\). Then \(m'\oplus r'=C\). In particular, the same \(C\) can be opened to two different messages with certainty.

The next two subparts examine the opposite trade-off with group commitments. We will calculate an alternative opening of a Pedersen commitment when a discrete-log relation between its public generators is known.
