Homework: which commitments hide and bind?

Our graph proof will need both hiding and binding. Before trusting a commitment scheme, we should prove those properties from its formula. The homework gives us several schemes to test.

First distinguish the strengths of security

Think of hiding as a guessing game: an observer sees a commitment and tries to tell which of two messages was used. Perfect hiding means both messages give exactly the same commitment distribution. Statistical hiding allows only a negligible difference even for an unlimited observer. Computational hiding makes the messages hard to distinguish for an efficient observer.

Binding asks a different question: can the committer open one value in two different ways? Perfect binding makes double openings impossible. Statistical binding rules them out except with negligible probability even with unlimited computing power. Computational binding rules them out for efficient adversaries.

HW1 · Problem 1(a)

Is a random-oracle hash commitment hard to open dishonestly?

First try a random-oracle hash commitment. Can we choose its randomness so that recovering the message or finding two different openings needs exponentially many oracle queries?

Solution · identify the randomness and the attacker’s task

In the random-oracle model, choose random \(\lambda\)-bit salt \(r\) and publish \(C=H(m\mathbin\Vert r)\), where \(\Vert\) means an unambiguous encoding of two bit strings. The random oracle acts as an ideal random function. Without knowing \(r\), an attacker trying a particular message must guess its hidden salt. A random guess succeeds with probability \(2^{-\lambda}\).

To open one commitment to two different messages, the attacker must find two distinct encoded inputs with the same hash output. That's a collision. For an ideal \(\lambda\)-bit hash, a birthday attack needs on the order of \(2^{\lambda/2}\) evaluations for a constant collision chance. This is exponential in \(\lambda\), so the scheme can be computationally binding—but not perfectly binding, because an unbounded attacker can find collisions.

HW1 · Problem 1(d)

Can we replace the random oracle by SHA-3 and call the result proved?

Solution · distinguish a model theorem from a real-function assumption

False. SHA-3 is a particular deterministic function. A proof that treats (H) as a perfectly random function does not automatically become a proof for SHA-3. The random-oracle model is an assumption about the function's behavior, not a property proved for every real hash.

Two schemes that split hiding and binding

HW1 · Problem 2(a)

\(C=H(r)^m\): is it statistically hiding or statistically binding?

For \(C=H(r)^m\), the message \(m\) is an exponent in a prime-order group \(G\), and \(H(r)\) is a group element. Check hiding and binding separately; the two answers turn out to be negative.

Solution · establish a counterexample to each property

It is not statistically hiding. If \(m=0\), every commitment equals \(H(r)^0=1_G\), the group identity. For a nonzero \(m\), the result is normally spread across the group. The identity therefore gives an observer a strong clue about the message.

It is not statistically binding either. An unlimited committer can choose two salts whose hashes are nonidentity group elements, then solve the discrete logarithm equations \(H(r_1)^{m_1}=C=H(r_2)^{m_2}\). With suitable distinct \(m_1,m_2\), one commitment has two openings. This only requires computation that a statistical attacker is allowed to perform.

HW1 · Problem 2(b)

\(C=m\oplus r\): can perfect privacy coexist with no binding?

In \(C=m\oplus r\), the operation \(\oplus\) means bitwise XOR, and the salt \(r\) is a uniformly random bit string as long as \(m\). Think about what the verifier sees if the salt is completely random.

Solution · show both claims explicitly

For every fixed message \(m\), XOR with a uniform \(r\) produces a uniform commitment \(C\). Both messages therefore lead to exactly the same distribution. That's perfect hiding.

But it has no binding at all. To open any fixed \(C\) as a chosen message \(m'\), pick \(r'=C\oplus m'\). Then \(m'\oplus r'=C\). The same commitment can be opened to every possible message.

Next we'll compare two group-based commitments. One remains perfectly hiding but loses binding when a secret relation is known; the other remains binding but reveals information.
