Lecture §5 · Non-interactive zero knowledge

Why can't we simply publish a simulated proof?

A Sigma protocol still makes the prover wait for a verifier challenge. We want one non-interactive proof \(\pi\) that anyone can verify using only the public statement \(x\). Before removing interaction, consider an obstacle: if anybody can efficiently simulate a convincing proof without a witness, why wouldn't that also let anybody decide whether the claim is true?

Suppose we had a zero-knowledge, non-interactive proof system in the plain model: no trusted setup, no special oracle, and no shared secret. The zero-knowledge definition supplies an efficient simulator \(\mathrm{Sim}(x)\) producing a proof that looks like a real one for every true statement. Non-interactivity means that simulation requires no conversation.

Now imagine an algorithm that receives an arbitrary statement \(x\), calculates \(\pi\leftarrow\mathrm{Sim}(x)\), and checks it with the public verifier \(V(x,\pi)\). If \(x\in L\), the simulated proof is indistinguishable from an honest, accepted proof, so the verifier accepts with high probability. If \(x\notin L\), soundness prevents any efficient algorithm, including \(\mathrm{Sim}\), from producing an accepted proof with more than the allowed soundness error.

We have therefore obtained a randomized decision algorithm for \(L\), one that decides true versus false statements efficiently with bounded error. Languages with such an algorithm belong to the class BPP. Consequently, plain-model NIZKs for every NP language would imply \(\mathrm{NP}\subseteq\mathrm{BPP}\), a consequence not believed likely.

Homework 3 · Problem 1(b)

Explain the obstruction to plain-model NIZK for all NP

Use simulation and verification to construct a randomized language-decision algorithm. Why does soundness matter on a false input?

Derive the complexity consequence

Run \(\mathrm{Sim}(x)\), then \(V(x,\mathrm{Sim}(x))\). For \(x\in L\), zero knowledge makes the simulation accepted almost as often as an honest proof. For \(x\notin L\), soundness bounds acceptance of any efficiently generated proof. The resulting algorithm decides \(L\) with bounded error. If this worked for every \(L\in\mathrm{NP}\), it would put NP inside BPP.

This argument assumes the plain model. A common reference string (CRS) is an additional public setup value that can support NIZK constructions under assumptions; absence of a random oracle does not by itself mean a protocol is plain-model. The lecturer instead changes the model by giving both parties access to an ideal random oracle, which behaves as one consistent, randomly selected function.

In that new model, the simulator in a security proof can sometimes choose a response to a previously unanswered oracle query. This extra ability is called programming the oracle. It is the ingredient that lets Fiat–Shamir remove the verifier's message without giving the simulator exactly the same capabilities as an ordinary prover.
