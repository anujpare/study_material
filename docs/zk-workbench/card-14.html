Homework 2: prove the composition claims

The exam-relevant task is not to repeat “parallel is harder.” It is to identify which security property we are proving, the exact message schedule, and the simulator that justifies the property. These three distinctions decide the answers.

Homework 2 · Problem 2: Composing ZK Protocols

Consider the Hamiltonian-cycle zero-knowledge protocol from the lecture. It has perfect completeness and soundness error \(1/2\). We repeat the protocol \(\lambda\) times, and the verifier accepts only when every instance accepts, so the combined soundness error is at most \(2^{-\lambda}\).

(a) First run the protocol \(\lambda\) times in sequence. Show that the resulting protocol is still zero knowledge.

(b) Next run the protocol \(\lambda\) times in parallel. Can you still show that the resulting protocol is zero knowledge? Why or why not?

(c) Show that honest-verifier zero knowledge is preserved under parallel composition for this protocol (and, more generally, for Sigma protocols).

Work through the solutions in their logical order

(a) Sequential composition · construct the simulator

What we must prove: For any efficient possibly malicious verifier \(V^\ast\) controlling all \(\lambda\) rounds, produce an efficient simulated complete view indistinguishable from its real view.

Construction: First save \(V^\ast\)'s state at the start of the first round. Run the one-round simulator, which may rewind \(V^\ast\) within that round until it produces a successful transcript. Keep that transcript and the resulting verifier state. Then proceed to the next round and do the same. At round \(i\), use the verifier's state and history produced by the preceding completed rounds.

Why efficient: Each round requires an expected constant number of one-round attempts (up to negligible differences), so \(\lambda\) polynomially many rounds require expected polynomial total work. No earlier completed round must be guessed again.

Why indistinguishable: Replace the real rounds by simulated ones one at a time. The one-round zero-knowledge guarantee applies to the malicious verifier with its current state and previously produced history. Each replacement changes the view by only a computationally negligible amount. A polynomial number of such changes remains negligible. Thus the full sequential transcript is computationally indistinguishable from a real execution.

(b) Parallel composition · identify what the old argument cannot do

Message rule: The prover sends all \(\lambda\) first commitments, then the verifier sends one vector of \(\lambda\) challenges, then the prover sends all responses. The simulator cannot finish or rewind instance 1 before preparing the first message for instance 2.

Using the straightforward Hamiltonicity simulator, it guesses the entire challenge vector before sending its commitments. Even against an honest verifier, the probability of a full match is \(2^{-\lambda}\), so the expected number of whole-protocol attempts is \(2^\lambda\), exponential when \(\lambda\) grows.

With a malicious verifier, the challenges can also depend on all first messages and on one another. We cannot claim that each single-round simulator still works independently as a black box. Therefore the standard construction does not establish general malicious-verifier zero knowledge of the parallel protocol. This is a failure of the proposed proof, not an impossibility theorem for every alternative construction.

(c) Parallel honest-verifier ZK · show why the restriction changes everything

Under an honest verifier, the challenge vector is sampled uniformly and independently of the commitments. Honest-verifier zero knowledge for each Sigma protocol gives a simulator that, when supplied a desired challenge \(c_i\), directly outputs an accepting-looking transcript \((u_i,c_i,z_i)\) without the witness.

Construction: Sample all \(\lambda\) challenges independently; invoke the honest-verifier simulator for each challenge; concatenate the \(\lambda\) commitments, challenges and responses in the parallel message order. There is no need to guess what a malicious verifier will do, because we control the simulation of an honest uniformly random challenge vector.

Each single-instance simulated transcript is indistinguishable from its honest counterpart. Combining polynomially many independent simulated transcripts preserves computational indistinguishability, by a hybrid argument. Thus parallel honest-verifier zero knowledge holds.

A distinction to retain for the exam

The phrase “zero knowledge survives parallel repetition” requires specifying which notion of ZK is meant. General ZK protects against a malicious verifier; honest-verifier ZK protects only when the verifier follows the challenge rule. Their simulation requirements are different, even when the protocol diagram contains the same number of commitments and challenges.

Zero knowledge establishes that the verifier learns no witness. The next question reverses the direction: how can a security proof establish that a successful prover must know a witness? The simulator cannot reveal it; a different algorithm, an extractor, gets to rewind the prover.
