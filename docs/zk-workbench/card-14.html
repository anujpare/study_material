Homework: prove exactly which repetition works

We have the timing difference in front of us. Now the homework asks for three different conclusions. Each answer needs to name the simulator and show why it works or why the usual construction fails.

Homework 2 · Problem 2: Composing ZK Protocols

The Hamiltonian-cycle protocol has perfect completeness and soundness error \(1/2\). Run it \(\lambda\) times and accept only if every instance accepts. This reduces the soundness bound to \(2^{-\lambda}\) under the repeated challenge rules.

(a) First run the protocol \(\lambda\) times in sequence. Show that the resulting protocol is still zero knowledge.

(b) Next run the protocol \(\lambda\) times in parallel. Can you still show that the resulting protocol is zero knowledge? Why or why not?

(c) Show that honest-verifier zero knowledge is preserved under parallel composition for this protocol (and, more generally, for Sigma protocols).

Work through the solutions in their logical order

(a) Sequential composition · construct the simulator

For sequential general zero knowledge, take any efficient malicious verifier \(V^\ast\) that runs the \(\lambda\) sessions. We need to generate its complete view without the witness.

Start at session 1 with the verifier in its current state. Run the one-session simulator, rewinding as needed until it produces that session's transcript. Keep the completed transcript and the resulting verifier state. Then run the simulator for session 2 from that state, and continue. A session may depend on previous conversations, but we simulate them in exactly the same order.

Each one-session simulation takes constant expected work, up to negligible differences, so \(\lambda\) sessions take expected polynomial work. A failure in a later session doesn't force us to guess earlier completed sessions again.

Why does the entire view look real? Imagine replacing the real sessions by simulated ones, one at a time. Each replacement is indistinguishable even given the verifier's current state and past messages. If the full real and simulated conversations differed noticeably, one of those neighboring replacements would also differ noticeably. The one-session ZK guarantee rules that out.

(b) Parallel composition · identify what the old argument cannot do

Parallel repetition sends all \(\lambda\) first commitments before receiving the challenge vector, so we cannot finish one session before preparing the next.

The straightforward simulator must guess all \(\lambda\) challenge bits at once. For an honest verifier, one guess succeeds with probability \(2^{-\lambda}\), requiring \(2^\lambda\) full attempts on average.

A malicious verifier may make the challenges depend on all the commitments. The usual independent one-session simulators therefore do not directly give a simulation of the parallel protocol. That does not prove parallel zero knowledge impossible; it tells us this argument is insufficient.

(c) Parallel honest-verifier ZK · show why the restriction changes everything

For honest-verifier zero knowledge, the situation is easier. The verifier's challenge bits are independent and uniform, so a simulator can choose the entire challenge vector itself.

Sample \((c_1,\ldots,c_\lambda)\) independently. For each challenge \(c_i\), run the original honest-verifier simulator to produce \((u_i,c_i,z_i)\) without a witness. Then arrange all first messages, challenges, and responses into the parallel three-message transcript.

Each simulated copy has the correct honest-verifier distribution. Replacing one copy at a time shows that the whole vector of transcripts is indistinguishable from a real parallel honest-verifier execution. So parallel HVZK is preserved.

A distinction to retain for the exam

The answer depends on which verifier is being simulated. General ZK must handle arbitrary efficient malicious verifiers. HVZK only needs the verifier that chooses its challenges honestly.

Now turn the tables. In zero knowledge we rewind the verifier to make a transcript without the secret. Could rewinding a dishonest prover instead reveal the secret? That's the next idea.
