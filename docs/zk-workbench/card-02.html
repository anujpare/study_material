Part I · What counts as a proof?

NP concerns checking evidence, not necessarily finding it

Suppose the prover provides a route around a map. Checking the route is straightforward: walk through the list once and test each claimed road. But if the prover provides nothing, a simple search algorithm may need to consider a great many possible routes.

Compare the two tasks using the same graph problem

For \(n\) cities, we can fix city 1 as the start. The other \(n-1\) cities can be listed in \((n-1)!\) orders, where the exclamation mark denotes a factorial: multiplying all positive integers up to a given number. For example, \(4!=4\cdot3\cdot2\cdot1=24\).

This gives a simple exhaustive search strategy: try those orders and reject each that uses a missing road. In contrast, checking one proposed route needs only \(n\) road checks, including the last road back to the start.

There is an important logical limit to this comparison: counting the possibilities shows that this naive search could be expensive. It does not prove that every algorithm must search through all of them. The famous P versus NP question asks whether every problem whose solutions are efficiently checkable can also be solved efficiently.

Now state NP precisely

Let \(L\) denote a language, meaning a set of yes-instances encoded as strings of bits. The expression \(x\in L\) means that the statement represented by \(x\) has the answer YES. The class NP consists of languages for which there is an efficient deterministic checker \(M\) and a witness \(w\) of polynomial length satisfying:

\[x\in L \quad\Longleftrightarrow\quad \exists w:\ M(x,w)=1\]

The symbol \(\exists\) means “there exists”; \(\Longleftrightarrow\) means “if and only if”. The checker runs in polynomial time in the length of \(x\), and the witness has polynomial length.

Both directions matter. If \(x\in L\), some suitable witness must exist and pass verification. If a witness passes verification, the instance must genuinely belong to \(L\); the checker is not permitted to accept fake evidence for a no-instance.

Why this applies to Hamiltonian cycles

For a graph with \(n\) vertices, a witness lists only \(n\) vertex labels, so the witness is short. The checker verifies that each vertex appears exactly once, that every consecutive pair is an edge, and that the last vertex returns to the first. Each test requires at most a polynomial number of elementary operations. Hence the yes/no problem “Does this graph have a Hamiltonian cycle?” belongs to NP.

Ordinary NP proofs can send the witness directly. We will now give the verifier a second way of checking a claim: instead of merely receiving a certificate, it can ask an unpredictable question.
