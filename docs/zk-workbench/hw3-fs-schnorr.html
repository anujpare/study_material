Homework 3 · Problem 2(a,b) · Fiat–Shamir applied to Schnorr

Homework: publish a one-message Schnorr proof

We already know the Schnorr conversation. Now we want one proof string that any verifier can check. The homework asks us to specify exactly what the prover sends and what the verifier must recompute.

(a) Construct the proof without a challenge message

We have public generator \(g\) of a prime-order group \(G\), its order \(q\), and public \(h=g^x\). The prover knows secret \(x\). Both sides use the same random oracle \(H\), with outputs interpreted as challenges in \(\mathbb Z_q\).

ProverChoose fresh \(r\in\mathbb Z_q\); compute \(u=g^r\). The first message is now fixed.
Local hashCompute \(c=H(h,u)\in\mathbb Z_q\). No verifier message is needed.
ProverCalculate \(z=(r+cx)\bmod q\), then send the single proof \(\pi=(u,z)\).
\[\boxed{\pi=(u,z)\,,\quad u=g^r,\quad z=r+H(h,u)x\pmod q}\]

The prover doesn't send \(c\), because anyone can compute it from \(h,u\). The notation \(H(h,u)\) means hashing a unique encoding of the public values and relevant protocol parameters.

(b) Write the verifier without access to the witness

The verifier first checks that \(h,u\) are valid group elements and \(z\in\mathbb Z_q\). It recomputes \(c=H(h,u)\), then checks the single group equality written below. No secret \(x\) is needed.

\[\boxed{g^z\stackrel{?}{=}u\,h^{\,H(h,u)}}\]

The question mark over the equality asks whether the two expressions give the same group element.

Prove completeness, not merely that verification seems plausible

For honest \(z=r+cx\), exponent laws give \(g^z=g^{r+cx}=g^r(g^x)^c=u h^c\). Since both sides use the same hash-derived \(c\), verification always passes. This proves completeness; soundness and zero knowledge need separate arguments.

HW3 · Problem 2(a,b) · Knowledge check

What if the prover sends \((u,c,z)\) instead?

Why the verifier must not trust a transmitted \(c\)

If a verifier trusted a challenge \(c\) chosen by the prover, cheating would be easy: choose \(c,z\) first and set \(u=g^zh^{-c}\), making the equation true without knowing \(x\). The verifier must instead recompute \(c=H(h,u)\) itself. Including \(c\) in the proof is harmless only if that supplied value is checked against the hash.

That suggests the next attack to study: fix (u,z), then hope the hash returns the one challenge that would make them pass.
