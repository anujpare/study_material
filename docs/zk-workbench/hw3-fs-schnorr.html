Homework 3 · Problem 2(a,b) · Fiat–Shamir applied to Schnorr

Construct a non-interactive Schnorr proof and its verifier

We already know how an interactive Schnorr conversation is checked. The homework asks for a different object: a single publicly verifiable proof string. The construction must specify exactly what the prover sends and what the verifier recomputes, rather than simply saying “hash the challenge.”

(a) Construct the proof without a challenge message

Public inputs are a generator \(g\) of a prime-order group \(\mathbb G\), its order \(q\), and the public element \(h=g^x\). The prover knows the private exponent \(x\in\mathbb Z_q\). Both parties agree on the same random-oracle function \(H\), mapping an unambiguously encoded public input to \(\mathbb Z_q\).

ProverChoose fresh \(r\in\mathbb Z_q\); compute \(u=g^r\). The first message is now fixed.
Local hashCompute \(c=H(h,u)\in\mathbb Z_q\). No verifier message is needed.
ProverCalculate \(z=(r+cx)\bmod q\), then send the single proof \(\pi=(u,z)\).
\[\boxed{\pi=(u,z)\,,\quad u=g^r,\quad z=r+H(h,u)x\pmod q}\]

The challenge is not included in \(\pi\): it is reproducible from the public value \(h\) and the transmitted \(u\). The expression \(H(h,u)\) abbreviates hashing a canonical encoding of those public values and the protocol parameters.

(b) Write the verifier without access to the witness

First reject malformed proofs: check group membership for \(h,u\), confirm the accepted parameters, and verify that \(z\in\mathbb Z_q\). Then reconstruct the challenge using precisely the same hash input, \(c=H(h,u)\). Finally check one group equation:

\[\boxed{g^z\stackrel{?}{=}u\,h^{\,H(h,u)}}\]

The question mark asks whether the equality holds as group elements. Every quantity on both sides is public or transmitted; the verifier does not use the secret exponent \(x\).

Prove completeness, not merely that verification seems plausible

The honest prover computes \(z=r+cx\pmod q\), so \(g^z=g^{r+cx}=g^r(g^x)^c=u h^c\). Because the verifier recomputes the same \(c=H(h,u)\), this is exactly its test. Thus every honest proof verifies. This argument proves completeness; soundness and zero knowledge require additional reasoning in the random-oracle model.

HW3 · Problem 2(a,b) · Knowledge check

What if the prover sends \((u,c,z)\) instead?

Why the verifier must not trust a transmitted \(c\)

A dishonest prover could choose \(c,z\) first, define \(u=g^z h^{-c}\), and pass the equation even without knowing \(x\). Fiat–Shamir prevents treating that self-chosen \(c\) as authoritative: the verifier always replaces it with \(H(h,u)\). The prover's challenge must be bound to its already-fixed first message by the random oracle. Sending an extra \(c\) would be redundant if correctly checked and unsafe if trusted without recomputation.

Now analyse the strongest restricted strategy suggested by that last calculation: the cheater deliberately chooses \(z\) and \(u\), then hopes the random oracle outputs the unique challenge that makes its precomputed response pass.
