Part III · Graph Hamiltonicity

Two questions about the same hidden graph

The prover knows a Hamiltonian cycle in the public graph \(G\). It commits to a randomly relabeled graph \(B\) without revealing it. The verifier needs evidence that \(B\) is a relabeling of \(G\) and that \(B\) contains a cycle. The protocol arranges these two checks so that the verifier asks for only one per execution.

Prover \(P(G,\mathrm{HamCycle})\)Has a cycle in \(G\), and picks secret random permutation \(\Pi\).
Verifier \(V(G)\)Knows the public graph \(G\), not the cycle.
Construct relabeled graph \(B\). Commit to its adjacency bits \(B_{ij}\) and to \(\Pi\).
\(P\longrightarrow V:\mathrm{Commit}(B_{ij}),\mathrm{Commit}(\Pi)\) See commitments, not hidden values.
\(V\longrightarrow P:c\) Receive a bit \(c\).
Sample uniform \(c\in\{0,1\}\).
If \(c=0\), open all graph entries and \(\Pi\). If \(c=1\), open the committed cycle edges.
\(P\longrightarrow V:\mathrm{Openings}\) Check relabeling if \(c=0\); check a cycle if \(c=1\).
Two hypothetical challenges · fixed first message

What exactly does the verifier inspect?

Try both challenges in the diagram. We are changing what the verifier asks to reveal, not changing the committed graph. A real verifier sends just one challenge in any execution.

Nothing is open yet. Every entry is fixed by its commitment, but the verifier cannot read it.

The verifier can inspect only the values whose commitments the prover opens. All unopened values remain concealed.

Why two challenges?

If \(c=0\): isomorphism

For challenge \(c=0\), the prover reveals the permutation \(\Pi\) and every graph entry. The verifier checks \(B_{ij}=1\ \Longleftrightarrow\ \{\Pi(i),\Pi(j)\}\in E\): was this graph obtained by renaming the public graph correctly? This check does not require revealing a Hamiltonian cycle.

If \(c=1\): cycle

For challenge \(c=1\), the prover reveals only the committed edge values along a cycle in \(B\). The verifier checks that every claimed edge exists and the cycle visits each vertex once. It does not learn \(\Pi\) or the remaining graph entries.

Notice the limitation of each question. The \(c=0\) question checks that \(B\) is the right graph, but not that it contains a cycle. The \(c=1\) question checks that \(B\) has a cycle, but not that it is a renamed copy of \(G\). Neither check alone proves everything.

Why is that good enough? On a false claim, a cheater must fix a graph before the challenge. We will prove that no single fixed graph can make both answers valid. The verifier catches the cheater with probability at least one half.

We'll now prove the two promises: an honest prover passes both challenges, and a cheater claiming a cycle in a graph without one can pass at most one of the two equally likely challenges.
