Part III · Graph Hamiltonicity

The two challenges test different claims about the same commitments

The prover sends commitments to a permuted graph \(B\) and its permutation \(\pi\). It must do so before learning which of two challenges the verifier will choose. The verifier then checks either that \(B\) is truly a relabeling of \(G\), or that \(B\) contains a Hamiltonian cycle.

ProverSelects one random \(\pi\), computes \(B=\pi(G)\), and sends \(\mathrm{Commit}(\pi)\) plus commitments to every \(B_{ij}\).
VerifierSamples a single fair bit \(c\in\{0,1\}\). Only one branch is requested in any real execution.
ProverProvides the openings requested by the chosen \(c\), without altering the original commitments.

Why two challenges?

If \(c=0\): isomorphism

The prover opens all adjacency entries and the permutation. The verifier checks that the opened graph is exactly \(B=\pi(G)\). This ensures the committed graph is a true relabeling of the public input.

If \(c=1\): cycle

The prover opens only the commitments for edges on a cycle in \(B\). The verifier checks that these edges form a Hamiltonian cycle covering all five vertices. It does not learn \(\pi\) or all edges of \(B\).

Crucially, \(c=0\) does not require revealing a Hamiltonian cycle of \(G\); it just checks the graph's identity. Challenge \(c=1\) proves that the sealed graph contains a cycle, but by itself does not prove that this sealed graph was actually constructed from \(G\).

That apparent weakness is intentional: an honest prover can pass either challenge, but a cheating prover attempting to prove a false graph statement cannot prepare commitments that answer both challenges successfully. The next card establishes this claim.
