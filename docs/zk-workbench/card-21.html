Part IX · Non-interactive zero knowledge

How can a hash replace the verifier's question?

A Sigma proof has three messages because the verifier must send an unpredictable challenge. Suppose both parties can calculate that challenge from the public statement and the prover's first message. Could the prover then publish a proof that anyone checks later?

Compare the two verification rules

Let \(u\) be the first message, \(c\) the challenge, \(z\) the response, and \(x\) the public statement. In the interactive version, the verifier draws and sends \(c\). In Fiat–Shamir, the prover fixes \(u\), then calculates \(c=H(x,u)\), where \(H\) is modeled as a random oracle.

Change the source of the challenge

Who chooses \(c\), and what is sent?

Switch between the two message flows. The verifier checks the same final equation in both; only the way it gets the challenge changes.

Choose one protocol to see which information is exchanged and how the challenge is generated.
\[\begin{aligned}c&=H(x,u),\\ \pi&=(u,z),\\ V_{\mathrm{NI}}(x,\pi)&=\mathrm{verif}(x,u,H(x,u),z).\end{aligned}\]

The prover publishes \(\pi=(u,z)\). No challenge needs to be sent, because the verifier can recompute \(c=H(x,u)\).

Prove completeness

Why an honest proof is accepted

Why does an honest proof still pass? The prover constructs \(u\), derives \(c=H(x,u)\), and computes the response \(z\) for that challenge. The verifier derives the same \(c\) and runs the original acceptance test. Perfect completeness therefore survives.

Where does zero knowledge come from if the simulator cannot know \(c\) in advance?

Soundness and zero knowledge need more work. In the random-oracle model, (H) behaves as a consistent random function: new inputs get fresh random answers, and the same input always gets the same answer. A simulator in a security proof can sometimes program an oracle answer at a chosen input.

Informal zero-knowledge simulator

To simulate a Fiat–Shamir proof, choose a random challenge \(c\), run the Sigma protocol's honest-verifier simulator to obtain an accepting triple \((u,c,z)\), and program \(H(x,u)=c\). Then output \((u,z)\). The verifier recomputes the programmed challenge and accepts, even though the simulator never knew the witness. A full random-oracle proof must justify the programming conditions.

Why programming also helps extraction

For knowledge extraction, the extractor can watch a cheating prover query \(H(x,u)\), answer with \(c\), then rewind to that same query and give a different \(c'\). Two accepting responses for the same \(u\) let special soundness recover a witness. This is the idea behind a forking argument; we have not proved the full theorem here.

Why the model assumption matters

A real hash such as SHA-3 is a fixed deterministic algorithm. Nobody can secretly reprogram it for a verifier. Oracle programming is a mathematical technique in the idealized security proof, not a feature of real hashes.

Why not use an empty non-interactive proof for every language?

For a language in P, the verifier can decide membership itself, so an empty non-interactive proof works. For hard NP languages, a witness-free simulator for a plain-model NIZK would be far more powerful. The homework asks what complexity consequence that would have.

Homework 3 · Problem 1(b)

Are NIZK proofs for all NP languages possible in the standard model?

Answer · first specify what “standard model” allows

In the plain model, there is no random oracle and no trusted common reference string. If an efficient NIZK simulator could create accepted-looking proofs for every true NP statement without a witness, we could run it and verify its output to decide the statement probabilistically. Completeness and simulation give high acceptance for true inputs; soundness keeps acceptance low for false inputs. This would put NP inside BPP.

But no random oracle does not necessarily mean no setup. A common reference string (CRS) is public information generated before the proof. Standard-model constructions with a CRS can have NIZK for NP under suitable assumptions. We must say which setup model is being discussed.

Homework 3 · Problem 1(d)

Does applying Fiat–Shamir always give statistical zero knowledge?

Answer · distinguish changing the challenge from strengthening privacy

False. Fiat–Shamir does not automatically turn computational zero knowledge into statistical zero knowledge. Replacing the challenge with a hash doesn't prove that an unlimited observer learns nothing.

What have we actually learned? Binding fixes the first message. A random challenge tests it. Simulation proves privacy. Two accepted challenges can yield a witness. Fiat–Shamir changes how the challenge is supplied, but each security guarantee still needs its own proof.
