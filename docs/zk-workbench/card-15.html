Lecture §3 · Proofs of Knowledge

Soundness is not the same as knowing a witness

So far we have proved soundness: a dishonest prover cannot convince the verifier of a false statement, except with a small probability. But that leaves an important case unanswered. If the statement is already true, how do we establish that the person sending the proof actually knows a witness?

Consider identification using a cyclic group \(G\) with generator \(g\). The server stores a public value \(X=g^\alpha\), and the client is meant to know the secret exponent \(\alpha\). The statement “there exists an \(\alpha\) such that \(X=g^\alpha\)” is true for every \(X\in G\), since \(g\) generates the group. Merely proving that statement is true does not authenticate the client. We need evidence that the client can actually provide the exponent.

Define knowledge by the ability to extract a witness

Checking whether a secret is stored in a prover's memory is not a meaningful general definition: an algorithm might store the secret indirectly, or compute it only when necessary. Cryptography instead defines an efficient knowledge extractor \(\mathrm{Ext}\). It is given access to a potentially dishonest prover \(P^\ast\) and must recover a witness from a prover that can convince the verifier sufficiently often.

For an NP language, let \(M(x,w)=1\) mean that the efficient, deterministic checking algorithm accepts witness \(w\) for public statement \(x\). A protocol is a proof of knowledge with knowledge error \(\varepsilon\) if there is an efficient extractor such that, for every statement \(x\) and every dishonest prover \(P^\ast\),

Write \(p_{\rm accept}=\Pr[\langle P^\ast,V\rangle(x)=1]\) for the probability that the verifier accepts, and \(p_{\rm extract}=\Pr[M(x,w)=1:\ w\leftarrow\mathrm{Ext}^{P^\ast}(x)]\) for the probability that the extractor returns a valid witness. The superscript \(P^\ast\) means the extractor can run that same prover. The knowledge guarantee is

\[\boxed{p_{\rm extract}\ge p_{\rm accept}-\varepsilon.}\]

Both probabilities include the algorithms' randomness. The extractor is a security-analysis algorithm, not an action performed by the ordinary verifier. A knowledge error \(\varepsilon\) says that extraction is guaranteed to be nearly as successful as convincing the verifier, with at most that much loss.

If \(x\notin L\), no valid witness exists, so the probability on the left is zero. The displayed inequality then forces the acceptance probability to be at most \(\varepsilon\). Thus knowledge soundness also implies ordinary soundness with at most that error; the reverse implication does not follow.

How could an extractor recover a witness without contradicting zero knowledge? It has one special capability that the ordinary verifier does not: it can rewind the prover to the same state and ask a different challenge. The Hamiltonicity protocol shows precisely how that works.
