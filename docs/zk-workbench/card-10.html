Part IV · Proving zero knowledge

The simulator prepares for a challenge it has not yet seen

To establish zero knowledge, we must produce an efficient algorithm \(\mathrm{Sim}\) that manufactures a convincing verifier view without a Hamiltonian cycle of \(G\). It cannot simply behave like the honest prover, because that prover needs the witness.

Construct a response to one guessed challenge

The simulator first picks a guess \(\hat c\in\{0,1\}\) uniformly. Its first message is crafted so that it can convincingly answer that challenge, even though the simulator does not know a Hamiltonian cycle of the public graph.

Guess \(\hat c=0\)

Choose a random permutation \(\pi\), build the genuine relabeled graph \(B=\pi(G)\), and commit to all its entries and to \(\pi\). If the verifier asks \(c=0\), open everything and demonstrate a correct isomorphism. No cycle was needed.

Guess \(\hat c=1\)

Commit instead to a complete graph on the same vertices, which certainly contains a cycle, and commit to any auxiliary permutation. If the verifier asks \(c=1\), reveal any Hamiltonian cycle of that complete graph. It need not be related to \(G\).

A complete graph has an edge between every pair of different vertices. The simulator can therefore construct a cycle immediately, without knowing a cycle of \(G\). However, that prepared graph generally could not pass \(c=0\): it might not be isomorphic to \(G\).

A lock is a committed but unopened bit. The matrix changes to visible bits only when the guessed challenge matches the verifier’s actual challenge.

The simulator must send its first message before receiving \(c\).

If \(c=\hat c\), the simulator knows the required openings and outputs the verifier's view. If \(c\ne\hat c\), it aborts and restarts from a saved state of the verifier, with fresh commitments and a fresh guess. Rewinding here means that the simulator can run the simulated verifier again from the same saved earlier state; it does not mean a real-world prover gets to undo a message already sent.

\[\hat c\ \xleftarrow{\$}\ \{0,1\},\qquad \text{keep attempt only if }\hat c=c\]

The arrow with a dollar sign means that \(\hat c\) is sampled uniformly at random. The simulator sees \(c\) only after sending its commitments; it keeps an attempt only on a match.

We have built the algorithmic skeleton. Two difficult questions remain: Why does the surviving transcript look like a real conversation, and why does the simulator finish in polynomial time?

The next card answers both by separating correctness of the simulated distribution from efficiency of repeated guessing.
