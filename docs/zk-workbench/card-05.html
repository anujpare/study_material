Part II · Zero knowledge

What would it mean to learn nothing?

An ordinary NP proof reveals the witness. We want the verifier to accept the statement without learning the witness—or any other useful information that depends on it. Simply hiding the witness text is not enough, because the protocol's messages might still leak it. How can we make “learns nothing” into a condition we can prove? We will compare the verifier's real conversation with a simulated one generated without the witness.

The verifier’s view is what it actually sees

The verifier's view includes the public statement \(x\), everything the verifier sees in the conversation, and its own random choices and internal state. In a real run, prover \(P\) knows witness \(w\) and interacts with verifier \(V^\ast\). In a simulated run, an algorithm \(\mathrm{Sim}_{V^\ast}\) must produce a comparable view using only \(x\), without \(w\). The star means the verifier may behave maliciously.

Real interaction

Public statement \(x\) is given to both parties. The honest prover additionally knows a private witness \(w\).

Prover \(P(x,w)\)↔ messages ↔Verifier \(V^\ast(x)\)

The verifier records everything it sees and its own random choices. This is its real view.

Simulation (security proof only)

The simulator is given the same public statement \(x\), but not witness \(w\).

Simulator \(\mathrm{Sim}^{V^\ast}(x)\)↔ simulated exchange ↔Runs \(V^\ast\)

The simulator produces a verifier view for comparison with the real one.

The star in \(V^\ast\) means that the verifier may be malicious, rather than following the prescribed verification steps. The simulator can run this verifier as a subroutine; its job is to produce a complete believable view without receiving \(w\). The simulator exists for the security argument; the honest prover does not run it in an ordinary proof.

If an efficient observer cannot reliably distinguish the simulated view from the real one, then the real conversation cannot provide a useful, efficiently detectable signal that the simulator could not already produce from public information.

\[\operatorname{View}\!\left[\langle P,V^\ast\rangle(x)\right]\;\approx_c\;\mathrm{Sim}_{V^\ast}(x)\]

The notation \(\approx_c\) says the two distributions are computationally indistinguishable: no efficient test distinguishes them with more than negligible advantage. We require this for true statements \(x\) and for every efficient verifier \(V^\ast\), even one that chooses its messages dishonestly.

A negligible advantage becomes smaller than \(1/\lambda^k\) for every fixed positive integer \(k\), when the security parameter \(\lambda\) is large enough. We need that strong condition because a small constant information leak would still count as learning something.

Why simulation implies privacy

Here's why simulation means privacy. Imagine a verifier can efficiently detect a secret property from the real transcript that it cannot detect from public information alone. Then that same detection procedure would distinguish real transcripts from simulated ones. But zero knowledge says no such efficient distinguisher exists. The supposed extra information therefore contradicts the definition.

We still have to build the simulator. That will be the interesting part: it must respond convincingly to a verifier that can choose its challenges, despite not knowing the witness.

Homework 2 · Problem 1(a) and 1(c)

How far does simulation go for easy problems?

(a) If \(P=NP\), do zero-knowledge proofs exist for every NP language?

True. Under the assumption \(P=NP\), every NP statement can be decided efficiently by the verifier itself. The prover can send nothing; the simulator can reproduce that empty communication exactly. Because the verifier decides correctly, completeness and soundness also hold.

(c) Without random oracles, do non-interactive ZK proofs exist for languages in P?

True. For a language in P, the verifier can compute the answer itself in polynomial time. An empty proof is non-interactive, reveals nothing, and is trivially simulatable. Later we will see why nontrivial NP languages are more challenging.

Next we'll construct the simulator for Hamiltonian cycles. But first we need a way to make information fixed before the challenge while keeping it hidden: a commitment.
