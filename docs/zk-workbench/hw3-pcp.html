Homework: make a long PCP proof succinct

We already know how Fiat–Shamir replaces a verifier's challenge. This homework applies that trick to a different proof system: a PCP, whose verifier needs only a few bits from a long, specially encoded proof.

Prerequisite: what the verifier can do with a PCP

Let the statement length be \(n\) and the PCP proof length \(M=\operatorname{poly}(n)\). A PCP test chooses random positions before seeing their bits, reads only a constant \(k\) bits, and checks them. True statements have proofs that always pass; for a false statement, any fixed proof passes a test with probability at most \(1/2\).

A Merkle tree commits to all \(M\) bits using one \(\lambda\)-bit root \(c\). To open position \(i\), the prover reveals the bit and the sibling hashes on its path, which takes \(O(\lambda\log M)\) bits.

(a) Construct the three-message succinct argument

P → VConstruct the full PCP string, commit to it with a Merkle tree, and send only root \(c\). The committed bits are now fixed.
V → PChoose fresh randomness for \(\lambda\) independent PCP tests. Send the resulting requested positions in one batch.
P → VReturn all requested bit values and their authenticated Merkle paths. V checks every path and every PCP predicate.

Prove completeness and soundness

Completeness. For a true statement, every PCP test on the honest encoded proof passes. The matching Merkle authentication paths also verify, so the combined protocol accepts.

Soundness. For a false statement, the prover must fix root \(c\) before the verifier chooses its queries. Merkle binding makes the opened bits behave like positions of one fixed PCP string, except with negligible failure probability. With \(\lambda\) independent PCP tests, the chance they all accept is at most \(2^{-\lambda}\). Including cryptographic failure gives \(2^{-\lambda}+\operatorname{negl}(\lambda)\).

Prove the communication bound

There are \(k\lambda\) positions to open. Each needs \(O(\lambda\log M)\) bits, so the openings cost \(O(k\lambda^2\log M)\). Since \(k\) is constant and \(M\) is polynomial in \(n\), this is \(O(\lambda^2\log n)\). The root and indices do not change the leading bound.

(b) Remove the challenge message using Fiat–Shamir

Now replace the verifier's random coins with \(H(x,c,\text{protocol parameters})\). The prover fixes root \(c\) first, derives all PCP test positions, and sends one proof containing \(c\), the requested bits, and their Merkle paths. The verifier derives the same positions and performs the same checks.

The commitment fixes the proof before the hash determines the queries. In the random-oracle model, polynomially many guessed roots have only negligible chance of making a false statement pass the amplified tests. This yields a succinct non-interactive argument, not necessarily a zero-knowledge proof.

What is and is not part of the ZK lecture

The important connection to our ZK lecture is that Fiat–Shamir removes interaction; it does not by itself give privacy, knowledge extraction, or small proof size. Those need their own constructions.
