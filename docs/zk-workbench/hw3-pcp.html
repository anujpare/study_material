Use a Merkle commitment and Fiat–Shamir to make a succinct argument

The preceding ZK lecture ends with Fiat–Shamir. Homework 3 also applies this transformation to a different kind of proof, a probabilistically checkable proof (PCP). This construction belongs to the later SNARG material, but it is included here to make every potentially overlapping HW3 exercise available in the same tutorial.

Prerequisite: what the verifier can do with a PCP

Let \(n\) be the input size and \(M=\operatorname{poly}(n)\) the length of a PCP proof string. A PCP verifier chooses random coins, then reads only \(k\) selected bit positions of the string, where \(k\) is a constant, and checks a predicate of those bits. In this exercise, a correct proof passes with probability 1, while an incorrect statement causes any fixed proof string to pass with probability at most \(1/2\). Importantly, the positions are nonadaptive: the verifier chooses them before seeing the bit values.

A Merkle commitment uses a binary tree of hashes to compress all \(M\) indexed bits into one root value \(c\) of \(\lambda\) bits. An opening of position \(i\) reveals its bit and the sibling hashes along the tree path, allowing verification of that position against the fixed root. The opening needs \(O(\lambda\log M)\) bits.

(a) Construct the three-message succinct argument

P → VConstruct the full PCP string, commit to it with a Merkle tree, and send only root \(c\). The committed bits are now fixed.
V → PChoose fresh randomness for \(\lambda\) independent PCP tests. Send the resulting requested positions in one batch.
P → VReturn all requested bit values and their authenticated Merkle paths. V checks every path and every PCP predicate.

Prove completeness and soundness

Completeness: On a true statement the honest PCP satisfies every query, and each Merkle path authenticates the correct bit under \(c\). All checks accept.

Soundness: Fix a false statement and an efficient cheating prover's root \(c\) before the challenges. Except with negligible probability of breaking Merkle position binding, that root defines one fixed proof string. Every independent nonadaptive PCP test on that fixed string accepts with probability at most \(1/2\), so all \(\lambda\) tests accept with probability at most \(2^{-\lambda}\). The total error is \(2^{-\lambda}+\operatorname{negl}(\lambda)\).

Prove the communication bound

There are \(k\lambda\) queried positions. Each opening costs \(O(\lambda\log M)\) bits, so all openings together cost \(O(k\lambda^2\log M)\). Because \(k\) is constant and \(M=\operatorname{poly}(n)\), we have \(\log M=O(\log n)\). The root and query indices contribute at most comparable terms. Thus the total communication is polynomial in \(\lambda\) and \(\log n\), rather than polynomial in the full PCP length \(M\).

(b) Remove the challenge message using Fiat–Shamir

The prover fixes the Merkle root first, then computes a domain-separated challenge \(H(x,c,\text{protocol parameters})\) with enough output to determine all \(\lambda\) PCP test positions. The single proof contains the root \(c\), all requested bits and all their Merkle authentication paths. The verifier recomputes the same positions, verifies the paths and runs every PCP predicate.

Binding prevents changing already committed bits after seeing the hash-derived queries. In the random-oracle model, the intended soundness argument bounds polynomially many candidate roots against the exponentially small per-attempt error. This establishes a succinct non-interactive argument, not a zero-knowledge proof: opened PCP bits may reveal information, and no simulator or knowledge extractor was constructed.

What is and is not part of the ZK lecture

This is the transition to the SNARKs chapter, where PCPs, Merkle openings and succinctness become central. For understanding the lecture on zero knowledge itself, the essential takeaway is that Fiat–Shamir can remove a public-coin challenge, but it does not automatically provide privacy, knowledge extraction, or short proofs.
