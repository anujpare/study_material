Part I · Interactive proofs

What does it mean for a proof to work?

The surprise-challenge experiment showed why a prover that prepares for only one of two questions can be caught. But one example does not tell us whether a protocol works for every true or false statement. We need two separate guarantees: honest provers must succeed on true statements, and cheating provers must fail on false statements. A proof system can make two mistakes. It might reject an honest prover with a true statement, or accept a cheating prover with a false statement. We give those failures different names because they protect against different things.

Completeness · true statement

For completeness, assume \(x\in L\): the statement is true. An honest prover \(P\) talking to the honest verifier \(V\) must be accepted with high probability.

\[\Pr[\langle P,V\rangle(x)=1]\geq\tfrac23\]

The probability includes any random choices made by the protocol. Perfect completeness means the honest prover is accepted every time.

Soundness · false statement

For soundness, assume \(x\notin L\): the statement is false. Then any cheating prover \(P^\ast\) must have only a small chance of making the honest verifier accept.

\[\Pr[\langle P^\ast,V\rangle(x)=1]\leq\tfrac13\]

We must consider every cheating strategy, not just the first one we can imagine.

Here \(\Pr\) means probability, \(L\) is the set of true statements, and \(P^\ast\) can be any dishonest prover. The lecture uses \(2/3\) and \(1/3\) as convenient completeness and soundness bounds. They are not laws of nature; we can often improve them by repetition.

Completeness makes a promise about an honest verifier. A malicious verifier could reject every proof. Soundness protects the verifier from a cheating prover; it doesn't stop that prover from deliberately revealing its secret. Zero knowledge will be a separate promise.

Homework 2 · Problem 1(b)

Two common traps

Assume a zero-knowledge protocol has perfect completeness and soundness error \(1/3\). Decide whether each statement is true.

(i) “A malicious verifier interacting with an honest prover will always accept a true statement.”

False. Perfect completeness concerns the honest verifier. A malicious verifier could always output “reject”, violating the quoted statement without violating the proof system's definition.

(ii) “An honest verifier interacting with a malicious prover will learn nothing besides validity.”

False. Zero knowledge protects an honest prover's secret from a possibly malicious verifier, not a cheating prover's deliberate disclosures. A malicious prover can send the secret witness in clear text.

Why can’t we always amplify by accepting only if every repetition accepts?

Be careful with repetition. If honest acceptance is only \(2/3\) and we demand that every one of three runs accepts, the honest prover would pass with probability \((2/3)^3=8/27\), worse than before. For this situation we can instead use a majority vote.

Let \(p\) be the probability that one independent run accepts. Exactly two of three accept in three possible orders, each with probability \(p^2(1-p)\); all three accept with probability \(p^3\). So majority acceptance has probability \(3p^2(1-p)+p^3\).

\[\begin{aligned}p=\tfrac23&:\quad 3(\tfrac23)^2(\tfrac13)+(\tfrac23)^3=\tfrac{20}{27},\\p=\tfrac13&:\quad 3(\tfrac13)^2(\tfrac23)+(\tfrac13)^3=\tfrac7{27}.\end{aligned}\]

Use that expression for the honest and dishonest cases. It improves the gap in this independent-run example. With an adaptive dishonest prover, a full amplification proof must also control the conditional chance of passing each new run.

Our later Hamiltonian-cycle protocol has perfect completeness, so an honest prover passes every repetition. There we can safely require all repetitions to pass while reducing soundness error.

We now know how to judge whether an interactive proof is convincing: honest claims pass, while false claims rarely do. Before introducing privacy, it helps to see what interaction buys us. Then we can ask the important question for this course: what does the verifier learn while being convinced?
