Part I · Interactive proofs

Completeness and soundness quantify two different failures

A useful proof system must avoid rejecting a truthful prover and accepting a liar. These are different risks, so cryptography defines them separately and specifies exactly who is honest in each guarantee.

Completeness · true statement

If \(x\in L\), an honest prover \(P\) interacting with the honest verifier \(V\) must be accepted often enough.

\[\Pr[\langle P,V\rangle(x)=1]\geq\tfrac23\]

The probability includes the parties' random choices. Perfect completeness strengthens this bound to 1.

Soundness · false statement

If \(x\notin L\), every cheating prover \(P^\ast\) must have only a small chance of fooling the honest verifier \(V\).

\[\Pr[\langle P^\ast,V\rangle(x)=1]\leq\tfrac13\]

The upper bound applies to all possible cheating strategies, not just a particular one.

The symbol \(\Pr\) means probability; \(L\) is the set of true statements; and \(P^\ast\) denotes an arbitrary, possibly malicious prover. The bounds \(2/3\) and \(1/3\) are standard convenient constants in the lecture, not absolute properties of every protocol. Appropriate repetition can amplify the gap.

Notice that soundness protects the verifier against a cheating prover. It does not say that an honest verifier learns no secrets from a cheating prover: a malicious prover might reveal its own witness. Similarly, completeness constrains an honest verifier, not a malicious verifier that deliberately rejects everything.

Homework 2 · Problem 1(b)

Two common traps

Assume a zero-knowledge protocol has perfect completeness and soundness error \(1/3\). Decide whether each statement is true.

(i) “A malicious verifier interacting with an honest prover will always accept a true statement.”

False. Perfect completeness concerns the honest verifier. A malicious verifier could always output “reject”, violating the quoted statement without violating the proof system's definition.

(ii) “An honest verifier interacting with a malicious prover will learn nothing besides validity.”

False. Zero knowledge protects an honest prover's secret from a possibly malicious verifier, not a cheating prover's deliberate disclosures. A malicious prover can send the secret witness in clear text.

Why can’t we always amplify by accepting only if every repetition accepts?

If a protocol has only completeness probability \(2/3\), requiring three honest repetitions all to accept would succeed with probability only \((2/3)^3=8/27\), worse than the original guarantee. For this generic situation, one possible amplification uses a majority: accept when at least two of three independent repetitions accept.

Let \(p\) be the independent acceptance probability in each repetition. Exactly two of three accept in three possible positions, each with probability \(p^2(1-p)\); all three accept with probability \(p^3\). Thus the majority-acceptance probability is \(3p^2(1-p)+p^3\).

\[\begin{aligned}p=\tfrac23&:\quad 3(\tfrac23)^2(\tfrac13)+(\tfrac23)^3=\tfrac{20}{27},\\p=\tfrac13&:\quad 3(\tfrac13)^2(\tfrac23)+(\tfrac13)^3=\tfrac7{27}.\end{aligned}\]

The first value is the honest-prover case and exceeds \(2/3\); the second is the false-statement cheating case and lies below \(1/3\). This is an illustrative independent-round calculation; a general adaptive-adversary amplification proof requires the corresponding conditional probability argument.

The later Hamiltonicity protocol has perfect completeness: an honest prover always succeeds, so requiring every repetition to pass does not reduce its completeness. This is why Homework 2 uses AND repetition safely there.

Even a proof that is complete and sound may simply reveal its secret witness. Our next goal is to define a third property that rules this out without sacrificing verification.
