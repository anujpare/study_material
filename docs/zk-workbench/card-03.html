Part I · Interactive proofs

Why the verifier asks a surprise question

An interactive proof lets the verifier ask questions instead of receiving only a single completed proof. The lecture's definition allows several messages. We first inspect one three-message example, which later becomes the structure of Hamiltonicity and Sigma protocols. The important issue is the order in which information becomes known.

The order of the messages creates the security

Prover \(P\)Knows public statement \(x\), prepares first message.
Verifier \(V\)Knows \(x\), chooses challenge after first message.
Prepare first message \(u\) without seeing the challenge.
\(P\longrightarrow V: u\) Receive fixed first message.
\(V\longrightarrow P: c\) Receive challenge \(c\).
Choose fresh challenge \(c\in\{0,1\}\).
Compute response \(z\) to that challenge.
\(P\longrightarrow V: z\) Check \((x,u,c,z)\).

The symbols \(u\), \(c\), and \(z\) label the first message, challenge, and answer. This is one example of an interactive proof, not a requirement that every interactive proof has exactly three messages.

That's the useful feature of interaction. The prover sends a first message that it cannot change. The verifier then chooses a challenge using fresh randomness. Only then may the prover answer. The order matters because the challenge was unknown when the first message was fixed.

Toy challenge game

Make one preparation before the verifier draws its challenge

For this toy experiment, assume the cheater can answer either question 0 or question 1, but not both. This is a model of the timing rule, not yet a real cryptographic proof.

Which challenge will the cheater prepare to answer?

First choose a preparation. The challenge comes only afterward.

If we choose 0 or 1 fairly, the cheater has probability \(1/2\) of getting the one question they prepared for. No clever wording changes that arithmetic: one answerable choice out of two equally likely choices gives \(1/2\).

How to understand the formal definition

We write \(\langle P,V\rangle(x)\) for a complete interaction between prover \(P\) and verifier \(V\) about public input \(x\). The verifier returns 1 for accept and 0 for reject. The standard definition requires the verifier to run in polynomial time; the prover can be computationally unlimited.

Of course, an honest prover should be able to pass the test, while a dishonest one should rarely pass a false claim. We need to state both requirements precisely.

The surprise challenge is useful because the first message is already fixed. Next we'll turn that idea into completeness and soundness.
