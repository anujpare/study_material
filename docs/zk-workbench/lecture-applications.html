Lecture 5–8 · Why we need zero knowledge

When do we actually need zero knowledge?

Not every proof needs to keep a secret. Before asking for zero knowledge, first ask: what information would the verifier learn if the prover gave it an ordinary witness?

Identify the secret in each application

Password-based authentication

For a password, the secret is \(p\). A server may know a verifier derived from it, such as \(H(p)\), but shouldn't learn \(p\) during authentication. A ZK-based authentication scheme might help, though a secure password protocol must also deal with guessing and active attacks. Zero knowledge alone does not solve those problems.

Private payments

A payment system might need to check that a transaction is valid while hiding an amount or the identities involved. The private transaction details form part of the witness; the public statement says the validity rules are satisfied.

Proof of an undisclosed exploit

A researcher might know an input \(w\) that makes a public program behave in a particular way. The statement says such an input exists. A ZK proof could establish that fact without publishing \(w\).

Outsourced computation

Now consider a public calculation that a server performs for a client. If the inputs and the answer are already public, there may be no witness to keep private. The important goal may simply be to check the computation cheaply. That's verifiable computation, not necessarily zero knowledge.

Reasoning check · Choose the necessary property

A server claims that it correctly multiplied two public matrices. Must its proof be zero knowledge?

Solution · identify what could be leaked

No. If both matrices and their output are public, the verifier doesn't need privacy for them. A short proof of correct matrix multiplication might be useful, but adding zero knowledge would not solve a privacy problem in this example.

In the privacy examples, the same pattern appears: a public claim is supported by a private witness. We'll now define what it means for the verifier to learn nothing extra from the proof.
