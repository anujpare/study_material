Lecture 5–8 · Why we need zero knowledge

When is hiding the witness essential—and when is it not?

Before constructing a complicated ZK protocol, decide what problem the protocol is actually solving. Merely checking a computation is not necessarily a privacy problem, and a privacy guarantee does not by itself make the proof short.

Identify the secret in each application

Password-based authentication

A user knows a secret password \(p\), while a server may know a public or stored verifier derived from it, such as a password hash \(H(p)\). The goal is to demonstrate authorization without revealing \(p\) to the server. A suitable ZK-based authentication or PAKE (password-authenticated key exchange) construction can help, but a real authentication system also needs protections against offline guessing and active attacks. Zero knowledge alone is not a complete password protocol.

Private payments

A public system needs assurance that a payment is valid while hiding information such as amounts or ownership. The witness can include private transaction data, and the ZK proof establishes that the public validity checks hold without disclosing that data. Privacy and transaction validity are separate obligations.

Proof of an undisclosed exploit

A researcher may know a secret input \(w\) that triggers a specified behavior in a program. The public statement can assert that such an input exists; a ZK proof can convince a verifier without revealing the exploit itself. The relevant witness is the private input, not the publicly known program.

Outsourced computation

A client delegates an expensive computation to a server and wants to check that the result is correct without re-running the entire calculation. If the input and computation contain no secrets, the key requirement is succinct or efficiently verifiable computation, not necessarily zero knowledge. ZK becomes relevant only when some witness or data must remain hidden.

Reasoning check · Choose the necessary property

A server claims that it correctly multiplied two public matrices. Must its proof be zero knowledge?

Solution · identify what could be leaked

No. If both matrices and their output are public and there is no private witness, there is no additional secret to protect. A short proof that the multiplication was performed correctly may be valuable, but that concerns verifiable computation or succinctness. Requiring ZK would not solve a privacy problem in this example.

The common theme of the other applications is a true public claim with a private witness. To formalize “the verifier learned no useful additional information,” we will compare the real conversation with one a simulator produces without that witness.
