Part VIII · Combining Sigma protocols

Prove that a circuit has a satisfying assignment

A Boolean circuit takes input bits and evaluates gates, finally outputting 0 or 1. We want to prove that some input makes the output 1 without revealing the input or all intermediate wire values. The homework constructs a proof by combining Sigma proofs for individual XOR and AND gates.

Begin with one gate, then connect the wires

An XOR gate outputs 1 if exactly one input is 1. An AND gate outputs 1 only if both inputs are 1. Write the two input bits as \(a,b\), and the output as \(d\). The relation is \(d=a\oplus b\) for XOR or \(d=a\land b\) for AND.

Understand the local statement

What must a gate-level proof establish?

Choose the gate and inputs. The verifier should not need to learn their bits directly; it receives commitments and a Sigma proof that the hidden bits satisfy the gate's truth table.

In a larger circuit, an output wire of one gate may be an input wire of another. It is essential to make one commitment per wire and reuse that same commitment everywhere that wire appears. Otherwise the prover could claim one hidden value at the output of the first gate and another at the input of the next.

Homework 2 · Problem 4(a)

Construct a Sigma protocol using \(N\) parallel gate proofs

Assume perfectly binding and computationally hiding commitments to bits, and Sigma protocols that prove the XOR and AND relations among triples of committed bits. Describe a Sigma protocol proving that an entire Boolean circuit \(C\) is satisfiable.

Protocol · commitment, challenge, response and verification

Commitment stage. Starting from a satisfying input, the prover calculates every intermediate wire bit \(m_w\), selects random \(r_w\), and sends one commitment \(c_w=\mathrm{Commit}(m_w;r_w)\) for each wire \(w\). For each gate \(j\in\{1,\ldots,N\}\), it constructs the first Sigma message \(u_j\) for the appropriate gate relation using the commitments to that gate's input and output wires. All \(u_j\) are sent together.

Challenge stage. The verifier samples fresh independent challenges \(e_1,\ldots,e_N\), one for each gate proof, and sends them together.

Response stage. The prover returns all gate responses \(z_1,\ldots,z_N\) and an opening of the final circuit-output commitment to the bit 1.

Verification. The verifier checks that the output really opens to 1, then checks every XOR or AND Sigma transcript against the same previously sent wire commitments. It accepts if and only if all checks pass.

Homework 2 · Problem 4(b)

Prove soundness, not merely that gate checks exist

Why a false circuit must cause a false gate statement

Suppose \(C\) is unsatisfiable: no input assignment causes output 1. Perfect binding fixes one value for each committed wire. If the final output commitment opens to 0, verification rejects immediately. Otherwise it opens to 1.

Assume, seeking a contradiction, that all gate relations were also satisfied by those fixed wire values. Starting from the input wires, evaluate the circuit gate by gate. Every committed output would then equal the correct XOR/AND of the committed inputs. The final committed output would equal the actual circuit output, namely 1. That would supply a satisfying input for \(C\), contradicting unsatisfiability.

Therefore at least one of the \(N\) gate statements is false. Let \(\epsilon\) be the probability that the complete protocol accepts an unsatisfiable circuit. Whenever that happens, at least one gate proof for a false relation must also have been accepted. Select one of the \(N\) gate indices uniformly as a target; conditional on complete acceptance, this selects a false accepted gate with probability at least \(1/N\). Thus an adversary with success \(\epsilon\) yields an attack on an underlying gate-proof soundness guarantee with probability at least \(\epsilon/N\).

What assumption finishes the proof? If \(N\) is polynomial in the security parameter and the individual gate protocols have negligible soundness error \(\delta(\lambda)\), then \(\epsilon/N\) cannot be non-negligible. Equivalently, the combined error is at most \(N\delta(\lambda)\), which remains negligible. If the underlying Sigma protocols only have one-bit challenges and constant soundness error \(1/2\), that does not establish negligible soundness of the whole circuit protocol. Their error must first be sufficiently reduced, or a weaker constant-error claim must be stated.

Homework 2 · Problem 4(c)

The intended honest-verifier simulation—and its subtle assumption

Sketch the simulator; identify what a fully rigorous proof still needs

The supplied homework solution proposes committing to 1 on every wire, using fresh randomness. The final output then genuinely opens to 1. For each gate, invoke a simulator for the gate's Sigma protocol and collect the transcripts. Hiding would make the commitments to these fake wire values look like commitments to honest wire values.

The logical gap: an all-1 assignment makes some gate relations false—for example, XOR(1,1)=0, not 1. But the standard Sigma definition provides an honest-verifier simulator only for true public statements. We therefore cannot simply invoke that definition to simulate a false committed-gate statement.

What would make the suggested construction valid? Assume an additional, explicitly stated ability: each gate simulator can manufacture an accepting transcript for a chosen honest challenge even for the artificial commitments used here, and can do so efficiently. Under this stronger property, replace real gate transcripts by simulated ones one at a time while their commitments are still honest, using HVZK; then replace real wire commitments with artificial ones one at a time, updating the simulated gate transcripts, using computational hiding and the extra simulation property. These are hybrid steps: if adjacent steps are indistinguishable, the initial real view and final fabricated view are indistinguishable. The final output commitment opens honestly to 1. Without the additional simulation guarantee, the homework's informal sketch is not a complete proof from the given Sigma axioms alone.

We have now built interactive protocols whose verifier selects challenges. The final topic asks whether a challenge can be computed from the prover's first message, eliminating the interaction altogether.
