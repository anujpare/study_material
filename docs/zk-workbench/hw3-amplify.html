Homework 3 · Problem 3(a,b) · Soundness before Fiat–Shamir

Why a one-bit Fiat–Shamir challenge is not enough

The random-oracle model can make a challenge unpredictable, but unpredictability alone does not make a one-bit challenge secure. A cheater with success probability \(1/2\) still succeeds on a constant fraction of attempts. The solution is to amplify soundness before removing interaction.

(a) Show what goes wrong without amplification

Suppose the interactive Sigma protocol has a cheating strategy against some false statement \(x\) that succeeds with probability \(1/2\). The cheater runs that strategy to prepare its first message \(u\), then computes the Fiat–Shamir challenge \(c=H(x,u)\) and supplies the corresponding response. For an unqueried input, the random-oracle challenge is uniform, just like an honest interactive verifier's challenge.

Prove the non-interactive soundness failure

Under the exercise's assumption that the interactive cheating strategy actually achieves success probability \(1/2\), the transformed cheating strategy also succeeds with probability \(1/2\) on this first attempt. This is a constant, not a negligible function of the security parameter \(\lambda\). Consequently the directly transformed protocol does not satisfy the negligible soundness error required for a NIZK argument. Merely knowing an upper bound of \(1/2\) would not establish such an attack; the exercise assumes an attainable cheating probability.

(b) Build a new three-message protocol with negligible soundness error

Run \(\lambda\) independent instances in parallel, but batch their messages into the same three communication steps: send all first commitments \(\boldsymbol{u}=(u_1,\ldots,u_\lambda)\); receive a fresh uniformly random challenge vector \(\boldsymbol{c}=(c_1,\ldots,c_\lambda)\); return all responses \(\boldsymbol{z}=(z_1,\ldots,z_\lambda)\). Accept only when every instance accepts.

For a false statement, special soundness ensures that each fixed first message \(u_i\) permits at most one accepting challenge bit. Therefore, for the entire fixed vector \(\boldsymbol{u}\), at most one of the \(2^\lambda\) challenge vectors permits all \(\lambda\) checks to pass. Since the honest verifier chooses uniformly:

\[\Pr[\text{false statement accepted}]\leq 2^{-\lambda}\]

Here \(\lambda\) is the number of repeated instances and the security parameter; \(2^{-\lambda}\) becomes negligible because it shrinks faster than every inverse polynomial in \(\lambda\).

Check the three Sigma properties after parallel repetition

Perfect completeness: Each honest instance accepts every challenge, so accepting only if all instances accept still has probability 1.

Special soundness: Take two accepting batch transcripts with exactly the same first-message vector \(\boldsymbol{u}\) but different challenge vectors \(\boldsymbol{c}\ne\boldsymbol{c}'\). At least one coordinate \(i\) has \(c_i\ne c'_i\). The two accepting responses for that coordinate share \(u_i\), so the original Sigma extractor produces a valid witness. Thus the batch still satisfies special soundness.

Honest-verifier zero knowledge: For a given uniformly sampled honest challenge vector, invoke the original HVZK simulator on each coordinate, then concatenate the resulting commitments and responses. A polynomial number of hybrid replacements shows that the joint view is indistinguishable from the real honest-verifier view. These are the reasons the batch remains a Sigma protocol rather than merely a protocol with a favorable numerical soundness bound.

Then apply Fiat–Shamir to the entire batch

After fixing all commitments, compute the challenge vector from one domain-separated hash of \((x,\boldsymbol{u})\) with enough output bits. The prover sends \((\boldsymbol{u},\boldsymbol{z})\), and the verifier recomputes \(\boldsymbol{c}\) and checks every Sigma response. Hashing only one commitment or letting the prover change some commitments after seeing the hash would invalidate the fixed-first-message argument.

Turn an abstract bound into an attack budget

How often can a cheater guess the whole challenge vector?

For a fixed first-message vector and a fresh random-oracle output, only one of \(2^\lambda\) vectors can pass. The panel compares this one-shot bound with the union-bound limit for \(Q\) different attempts.

This is the counting argument for a fresh-hash guessing attack. A complete Fiat–Shamir security theorem against an arbitrary malicious prover additionally needs an appropriate random-oracle reduction. The security improvement from parallel repetition is compatible with honest-verifier ZK because the honest challenge vector can be simulated coordinate by coordinate; that does not assert general malicious-verifier ZK of the parallel interactive protocol.

Fiat–Shamir changes the source of randomness, not the definition of secrecy or the extractor's obligation. The next optional exercises show how the same hashing technique is used later in the course for succinct arguments, where zero knowledge is not automatically provided.
