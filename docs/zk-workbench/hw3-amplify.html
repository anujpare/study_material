Homework 3 · Problem 3(a,b) · Soundness before Fiat–Shamir

Homework: make the challenge hard to guess first

Making the challenge unpredictable doesn't help much if there are only two possibilities. A cheater who can answer one of them still has a one-half chance. We need to reduce that chance before using Fiat–Shamir.

(a) Show what goes wrong without amplification

Suppose a cheating strategy for a false statement \(x\) succeeds with probability \(1/2\) against a uniformly random one-bit challenge. The cheater fixes its first message \(u\), then asks the random oracle for \(H(x,u)\). This hash gives a uniform bit, just as the honest verifier would have done.

Prove the non-interactive soundness failure

The problem assumes the cheating strategy really achieves success probability \(1/2\). So after Fiat–Shamir, one attempt still succeeds with that same probability. A constant error is not negligible. Simply knowing an upper bound of \(1/2\) would not, by itself, prove an attack exists.

(b) Build a new three-message protocol with negligible soundness error

Run \(\lambda\) copies of the Sigma protocol in parallel. The prover sends all first messages \(\boldsymbol u=(u_1,\ldots,u_\lambda)\) together. The verifier sends independent challenge bits \(\boldsymbol c=(c_1,\ldots,c_\lambda)\). The prover returns all responses \(\boldsymbol z\). Accept only if every copy passes. There are still three messages, each now a batch.

Fix the batch of first messages on a false statement. Special soundness tells us that each individual first message \(u_i\) can answer at most one of the two challenge bits; otherwise two accepted answers would reveal an impossible witness. Thus the whole batch can answer at most one challenge vector among \(2^\lambda\) equally likely vectors.

\[\Pr[\text{false statement accepted}]\leq 2^{-\lambda}\]

So false acceptance is at most \(2^{-\lambda}\). This becomes negligible as \(\lambda\) grows, because an exponential denominator eventually beats every fixed polynomial.

Check the three Sigma properties after parallel repetition

Completeness. Every honest copy passes, so requiring every copy to pass still accepts every honest prover.

Special soundness. Two accepting batch transcripts with the same \(\boldsymbol u\) and different challenge vectors must differ at some coordinate \(i\). The two accepted answers for that coordinate share \(u_i\), so the original extractor recovers a witness.

Honest-verifier zero knowledge. Simulate each independent honest challenge and its response using the original simulator, then combine the transcripts. A sequence of hybrid replacements shows the joint distribution remains indistinguishable from real independent executions.

Then apply Fiat–Shamir to the entire batch

Now derive the whole challenge vector by hashing the statement and all first messages. Publish \((\boldsymbol u,\boldsymbol z)\). The verifier recomputes \(\boldsymbol c\) and checks every response. Hashing only part of the first-message batch would leave other commitments outside the binding of the challenge.

Turn an abstract bound into an attack budget

How often can a cheater guess the whole challenge vector?

For a fixed first-message batch, at most one of \(2^\lambda\) random-oracle challenge vectors can pass. The interactive panel shows this one-shot bound and what happens across \(Q\) attempts.

The numerical guessing bound alone is not a full Fiat–Shamir security theorem for every malicious prover. A complete random-oracle proof needs a reduction that handles adaptive oracle queries and other prover strategies.

Fiat–Shamir removes a challenge message. It does not automatically prove privacy or knowledge. The next exercises use the same idea with succinct arguments.
