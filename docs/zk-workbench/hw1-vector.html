Homework: prove the value at one place in a long list

The graph protocol committed to each matrix entry separately. But a later SNARG will need to commit to an enormous proof and open only a few selected positions. Can we do that without sending the whole list?

Define the property before designing the scheme

Let \(\boldsymbol m=(m_1,\ldots,m_n)\) be a list of messages. A vector commitment gives one public commitment \(c=\operatorname{Commit}(\boldsymbol m)\). Later the prover opens index \(i\) by supplying \(m_i\) and an authentication proof \(\pi_i\). Position binding means a cheater cannot feasibly make the same \(c,i\) verify with two different messages.

\[\mathrm{Verify}(c,i,m_i,\pi_i)=1\]

The verifier checks the index, the claimed value, and the opening proof. This homework doesn't require the values to remain hidden.

Homework 1 · Problem 4(a)

Large commitment; essentially free opening

First, make a commitment of \(n\lambda\) bits with a constant-size opening, using a random-oracle hash \(H\) that returns \(\lambda\) bits.

Construction and proof of position binding

The simplest idea is \(c=(H(m_1),\ldots,H(m_n))\). To open \(i\), reveal \(m_i\); the verifier checks \(H(m_i)=c_i\). The opening needs no extra proof bits, because the expected hash is already stored. If distinct messages \(m_i,m_i'\) both passed, we'd have \(H(m_i)=H(m_i')\), a hash collision. That's why the construction is position binding.

Homework 1 · Problem 4(b)

Tiny commitment; reveal the entire vector

Construction and proof of position binding

For a short commitment, hash the entire encoded list: \(c=H(\operatorname{Encode}(m_1,\ldots,m_n))\). To open one position, reveal the whole list. Two different lists with the same root would be a collision, so binding holds. But the opening now takes \(O(n|m|)\) bits if every message has \(|m|\) bits.

Problem 4(c): find the middle ground with a Merkle tree

For a better trade-off, make a Merkle tree. Hash each message as a leaf using a unique leaf encoding; hash pairs of child values up the tree using a distinct node encoding. Only one \(\lambda\)-bit root remains. Opening a leaf needs the sibling hash at each level, not every leaf.

Prove the size bound and position binding

For eight leaves there are three levels, so the proof uses three sibling hashes. For \(n\) leaves the tree height is \(O(\log n)\). Each hash is \(\lambda\) bits, making the opening \(O(\lambda\log n)\) bits and the root \(\lambda\) bits.

Why is it binding? Suppose two different messages at the same leaf both led to the same root. If their leaf hashes match, that's already a collision. Otherwise, follow the two hash paths upward. Somewhere two different child inputs must produce the same parent hash to end at one root. That's also a collision. Thus a feasible double opening would break collision resistance.

Now we have exactly what the PCP argument needs: fix a long proof using one small root, then authenticate only the positions the verifier asks for. The prover must send the root before seeing the positions.
