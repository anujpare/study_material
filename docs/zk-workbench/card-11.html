Part IV · Proving zero knowledge

Why does the simulator’s output look real—and why is it efficient?

A simulator does not establish zero knowledge merely by producing accepting-looking messages. We must justify two separate statements: the simulated view is indistinguishable from a real one, and producing it takes only polynomial expected time.

First obligation: explain the verifier's view in each branch

When \(c=0\)

The real prover commits to a random relabeling \(B=\pi(G)\), then reveals \(\pi\) and every matrix entry. The simulator's \(\hat c=0\) preparation does exactly that. After a successful guess, the opened graph and permutation have the same distribution as in an honest execution. No secret cycle is exposed in this branch.

When \(c=1\)

The real prover opens only a relabeled Hamiltonian cycle of \(B\). Because \(\pi\) is random, the labels of this revealed cycle are uniformly relabeled. The simulator commits to a complete graph and reveals a cycle with the same relabeled-cycle distribution. All other graph entries remain unopened. Computational hiding makes commitments to those other entries indistinguishable from commitments in a real execution. The verifier therefore cannot efficiently detect which underlying graph supplied the unopened bits.

A malicious verifier \(V^\ast\) may choose \(c\) depending on the commitments. This does not invalidate the argument: because the unopened contents are computationally hidden, an efficient \(V^\ast\) cannot reliably distinguish which simulator preparation it received before choosing its challenge. A fully formal proof packages these comparisons as hybrids, replacing hidden commitments one by one.

Second obligation: show the simulator finishes efficiently

For an honest verifier, \(c\) is an independent uniformly random bit. The guess \(\hat c\) matches it with probability \(1/2\) on each attempt. If \(N\) is the number of attempts until the first match, then \(N\) has a geometric distribution: to require more than \(k\) attempts, all first \(k\) attempts must fail.

\[\Pr[N>k]=\left(\tfrac12\right)^k,\qquad \mathbb E[N]=\tfrac{1}{1/2}=2\]

Here \(k\) counts consecutive failed attempts, and \(\mathbb E[N]\) is the average number of attempts across repeated simulations.

We can derive the average rather than memorizing it. An attempt is always necessary, contributing 1. With probability \(1/2\), the first attempt fails and the simulator starts afresh; that remaining work has the same average \(E\) as the original problem. Therefore \(E=1+\tfrac12E\). Subtracting \(\tfrac12E\) from both sides gives \(\tfrac12E=1\), hence \(E=2\). This constant expected cost is why ordinary one-bit rewinding can be efficient.

Against an efficient malicious verifier, hiding implies that its challenge cannot depend on whether the simulator secretly prepared the \(\hat c=0\) or \(\hat c=1\) branch with more than negligible advantage. Thus the simulator's match probability stays \(1/2\) up to negligible error, giving polynomial expected running time.

What these arguments establish

Perfect binding already gave soundness; an honest prover passes both challenges, giving perfect completeness; and the witness-free simulator produces a computationally indistinguishable verifier view in expected polynomial time, giving computational zero knowledge. These are the three distinct claims required by the theorem.

One execution has soundness error \(1/2\). Repetition can decrease it. But repetition creates a new question: can a simulator still succeed efficiently if the verifier requests many challenges at once?
