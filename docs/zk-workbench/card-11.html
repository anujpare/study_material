Part IV · Proving zero knowledge

Why does the simulator really prove zero knowledge?

The preceding lesson constructed a simulator for either challenge, but constructing a transcript that passes the verifier is only a starting point. A fake transcript could have a visibly different distribution from a real one, or require exponential time to produce. Either would invalidate the claimed zero-knowledge guarantee. A simulator that sometimes makes the verifier accept has not yet proved anything about privacy. We must show two facts: the verifier cannot efficiently distinguish its output from a real conversation, and the simulator finishes in expected polynomial time.

First obligation: explain the verifier's view in each branch

When \(c=0\)

Suppose challenge \(c=0\) is asked. In the real protocol, the honest prover reveals a randomly relabeled graph \(B_{ij}=1\iff\{\Pi(i),\Pi(j)\}\in E\) and its permutation. The simulator prepared the very same kind of graph and opens it the same way. The revealed information has the same distribution.

When \(c=1\)

For \(c=1\), the verifier sees only a randomly relabeled Hamiltonian cycle and commitments to the other graph entries. The honest prover applies a uniform vertex permutation to its fixed cycle. Each possible labeled cycle has the same number of permutations producing it, so the revealed cycle is uniform. The simulator can sample that same distribution without knowing the witness. It commits to a complete graph, allowing it to open every edge of its sampled cycle. Because the other entries remain hidden, computational hiding prevents an efficient verifier from telling whether those unopened commitments contain the honest graph or the simulator's different graph.

What if the verifier is malicious and chooses its challenge after inspecting the commitments? It might try to tell which preparation the simulator used. But if those unopened commitments revealed that choice with noticeable advantage, the verifier would distinguish commitments to different hidden values, breaking the hiding assumption. A formal proof makes this comparison through a sequence of hybrids.

Second obligation: show the simulator finishes efficiently

Now check efficiency. Against an honest verifier the simulator guesses one uniformly random bit, and the verifier independently asks one uniformly random bit. The guess matches with probability \(1/2\) per attempt. Let \(N\) be the number of attempts before the first match. Then \(N>k\) precisely when the first \(k\) guesses all fail.

\[\Pr[N>k]=\left(\tfrac12\right)^k,\qquad \mathbb E[N]=\tfrac{1}{1/2}=2\]

The event that the simulator needs more than \(k\) attempts has probability \((1/2)^k\). The notation \(\mathbb E[N]\) means the average number of attempts.

We can calculate the average directly. Call it \(E\). Every run uses one attempt. Half the time that attempt fails, and then the simulator must start over, expecting another \(E\) attempts. Therefore \(E=1+\tfrac12E\), so \(E=2\). A constant expected number of attempts is efficient.

Against an efficient malicious verifier, hiding keeps its ability to detect the simulator's preparation negligible. Its chance of matching \(\hat c\) therefore stays \(1/2\) up to negligible error, and the simulator still has polynomial expected running time.

What these arguments establish

Now we can close the argument. The soundness proof used binding. The honest prover passes either challenge, giving completeness. And we just built an efficient witness-free simulator whose view is computationally indistinguishable from the real one. That is the promised computational zero-knowledge property.

One run has soundness error \(1/2\). To reduce it, we will repeat the protocol. But the timing of the repeated challenges will matter to the simulator.
