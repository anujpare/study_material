Homework 3 · Problem 2(c,d) · Soundness and transferability

How many Fiat–Shamir guesses can a cheater afford?

A cheater who does not know the Schnorr secret can manufacture a response that would work for one particular challenge. Fiat–Shamir forces the challenge to come from an unpredictable hash of the first message. We will prove the chance of a match and then explain why a public proof can be copied, unlike a verifier's private interactive transcript.

(c) Prove the bound for a prescribed guessing strategy

The cheater fixes \(z\) and \(u\) before querying \(H(h,u)\). It would be accepted only if the hash value \(c\) satisfies \(g^z=u h^c\). Assume \(h\ne1\) in the prime-order group \(\mathbb G\). Then \(h\) is itself a generator, so its \(q\) distinct powers \(h^0,\ldots,h^{q-1}\) cover the whole group exactly once.

Exactly one challenge can be accepted

Rearrange the equation to \(h^c=g^z u^{-1}\). The right-hand side is now a fixed group element. Because exponentiation by a nonidentity element of a prime-order group maps the \(q\) possible exponents one-to-one onto its elements, exactly one \(c\in\mathbb Z_q\) satisfies the equality. A fresh random-oracle output is uniform, so the probability it hits that unique \(c\) is \(1/q\).

For \(Q\) distinct candidate hash inputs, let \(E_i\) be the event that the \(i\)th guess succeeds. Even if the cheater picks candidates adaptively, each fresh query has conditional success probability at most \(1/q\). The union bound says \(\Pr[E_1\cup\cdots\cup E_Q]\leq\sum_i\Pr[E_i]\), hence:

\[\Pr[\text{at least one successful guess}]\leq\min\{1,Q/q\}\]

Here \(Q\) counts fresh tested candidate hashes, not repetitions of the same query. A random oracle gives the same answer when an identical input is requested again.

Derive the attack, not just the bound

Every candidate has one winning hash value

Use the small order-11 subgroup modulo 23 with public \(h=8\). A cheating prover selects a response \(z_i\) and aims for challenge \(c_\star=2\). Without using the secret exponent, it can calculate \(u_i=g^{z_i}h^{-2}\), then query \(H(h,u_i)\).

This argument bounds the restricted guessing strategy in the exercise. It does not by itself establish full non-interactive proof of knowledge against all possible oracle-using adversaries. If an adversary is allowed \(Q\) prior queries and then one new, unqueried final candidate, count that candidate too, giving \((Q+1)/q\) by the same reasoning.

The condition (h\ne1) is essential. If (h=1), then (h^c=1) for every challenge and the one-winning-challenge argument fails. In that degenerate case the exponent (x=0\) is already a public witness; the intended unknown-secret attack question does not arise.

(d) Why a non-interactive proof can convince a third party

NIZK proof string

Someone who receives a publicly verifiable proof \(\pi=(u,z)\) can give the same string and statement \(h\) to another verifier. The second verifier independently computes \(H(h,u)\) and runs the same check. No interaction with the original prover is required.

Recorded interactive transcript

An interactive ZK verifier's saved messages are not equivalent to a publicly transferable proof that the real prover participated. The verifier could have simulated an indistinguishable view without the witness. A third party seeing only that recording cannot infer that a real prover took part.

The distinction concerns proof strings versus recordings, not live forwarding of authentication messages. Zero knowledge alone does not prevent real-time relay attacks. This is why the lecture distinguishes interactive proofs, their simulators, and non-interactive publicly verifiable proofs.

Even if one guess succeeds with probability only \(1/q\), a very small challenge space—particularly a single challenge bit—may still be too weak for a secure non-interactive argument. The next exercise derives the required amplification.
