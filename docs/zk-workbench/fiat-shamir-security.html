Lecture §5 · Fiat–Shamir security arguments

What does the random-oracle model make possible?

We have a one-message proof \((u,z)\). To use it as a non-interactive zero-knowledge argument of knowledge, we must still justify both privacy and witness extraction. These are two different constructions in the security proof, not operations that an ordinary verifier can perform.

Zero knowledge: program a challenge after simulating

Recall the honest-verifier simulator for a Sigma protocol. Given public statement \(x\) and a challenge \(c\), it can produce an accepting transcript \((u,c,z)\) without the witness. The non-interactive simulator chooses \(c\) uniformly, runs that simulator, and then programs the random oracle so that \(H(\operatorname{Encode}(x,u))=c\). It publishes \((u,z)\). Anyone verifying against that simulated oracle gets the same challenge \(c\), so the reconstructed transcript is accepting.

The subtlety is that the simulator must program a previously unanswered query while keeping the entire oracle transcript indistinguishable from genuinely random answers. The lecture gives this construction informally rather than a full security reduction.

Knowledge extraction: rewind an oracle query

An extractor watches a prover request \(H(\operatorname{Encode}(x,u))\), supplies challenge \(c\), and obtains a successful response \(z\). It rewinds the prover to the same query state, supplies a different challenge \(c'\), and aims to obtain \(z'\) for the same first message \(u\). If both transcripts are accepted, Sigma special soundness computes a witness from \((u,c,z)\) and \((u,c',z')\).

Like the Hamiltonicity extractor, this argument must be supplemented by a probability and runtime analysis for provers that do not always answer successfully. The original notes give only the informal extractor.

Why the original error must be negligible

Before Fiat–Shamir, a prover who could answer one of two possible challenges might succeed with probability \(1/2\). With hash-derived challenges, it can try many proposed first messages \(u\) and retain one with a favorable hash. For a constant error, that search may be easy. A suitable repetition or amplification argument must first make the success probability for a fixed first message negligible; the precise transformed security depends on the model and protocol.

Homework 3 · Problem 1(d)

Does Fiat–Shamir automatically give statistical zero knowledge?

Explain why not

No. A protocol may offer only computational zero knowledge, meaning efficient distinguishers cannot tell simulation from reality. Replacing its challenge with a random-oracle output does not automatically strengthen that promise to statistical indistinguishability, which must hold even for unlimited distinguishers.

Ideal model versus implementation

A real hash function is deterministic, and nobody can actually reprogram it. Programming and rewinding are techniques for proving properties of an ideal random oracle. Replacing it in an implementation with a concrete hash, such as SHA-3, is a heuristic modeling step, not the same as proving a universal theorem for every hash and every Sigma protocol.
