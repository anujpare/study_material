Part V · Repeating a proof

What changes when we repeat the proof in parallel?

The Hamiltonicity proof has soundness error (1/2) in one execution. To make a false claim less likely to pass, we need repeated independent challenges. But we have two requirements to preserve: soundness against a cheating prover and efficient simulation without the witness. The way we schedule repeated messages can affect the second requirement. Suppose we repeat the same proof three times. We could finish one proof before starting the next, or send all three first messages together. These may sound equivalent, but a simulator has very different information at each moment.

First fix what one execution looks like

One execution has the order \(u\to c\to z\): commitment, challenge, response. The first message \(u\) contains the committed graph information. The verifier must choose \(c\) only after receiving \(u\).

\[\underbrace{P\rightarrow V:u}_{\text{commit}}\quad\longrightarrow\quad\underbrace{V\rightarrow P:c}_{\text{challenge}}\quad\longrightarrow\quad\underbrace{P\rightarrow V:z}_{\text{response}}\]

For repetition \(i\), write these messages as \(u_i,c_i,z_i\). The subscript \(i\) simply tells us which copy of the protocol we are discussing.

Now identify the mathematical difference

Sequential: \(u_1,c_1,z_1,u_2,c_2,z_2,\ldots\). The simulator can finish, including any rewinds, the first session before constructing the first message of the second.

Parallel: send all \((u_1,\ldots,u_n)\) first, then receive all \((c_1,\ldots,c_n)\), then send all \((z_1,\ldots,z_n)\). Now the simulator has to prepare every first message before learning any challenge.

Why “three challenges” alone is not a complete description

The number of repetitions hasn't changed. The difference is precisely which messages must be fixed before the verifier reveals its questions.
