Part V · Repeating a proof

Sequential and parallel repetition differ in the rules of communication

Running the same proof three times should be familiar. What is less obvious is that running those three proofs sequentially or in parallel changes when the verifier can see the commitments and when it can send its challenges. That timing difference becomes decisive for simulation.

First fix what one execution looks like

Our Hamiltonicity protocol has three communication stages: the prover sends committed graph data \(u\); the verifier sends a challenge \(c\); the prover sends openings \(z\). For convenience, call the entire first committed message \(u\), even though internally it contains many commitments.

\[\underbrace{P\rightarrow V:u}_{\text{commit}}\quad\longrightarrow\quad\underbrace{V\rightarrow P:c}_{\text{challenge}}\quad\longrightarrow\quad\underbrace{P\rightarrow V:z}_{\text{response}}\]

Each \(u_i,c_i,z_i\) below belongs to repetition \(i\); different repetitions use fresh randomness. This is a pattern of messages, not an equation about their values.

Now identify the mathematical difference

In sequential repetition, the messages follow \(u_1,c_1,z_1,u_2,c_2,z_2,\ldots\). The prover does not have to commit to instance 2 until instance 1 is over. A simulator may complete and, if necessary, rewind instance 1 before moving on to instance 2.

In parallel repetition, the prover first sends \((u_1,\ldots,u_n)\) all at once; only then does the verifier send \((c_1,\ldots,c_n)\); and finally the prover returns \((z_1,\ldots,z_n)\). The simulator must prepare all its committed graphs before seeing any challenges.

Why “three challenges” alone is not a complete description

Both schedules involve three challenge bits and three responses when \(n=3\). They are not the same protocol, because the messages that must be fixed before the challenges arrive are different. You cannot infer simulation difficulty merely from the number of repetitions.

Soundness can improve in both schedules. What changes is the number of guesses a simulator must get right at the same time. We will calculate those costs explicitly.
