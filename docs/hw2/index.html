HW2 · Prerequisite: Languages, witnesses and zero knowledge

HW2 moves beyond the uploaded commitment lecture into zero-knowledge (ZK) proofs. Here are the foundations needed for its exercises.

A language is a set of yes-instances. For example, the language of satisfiable circuits consists of all circuits for which some input makes the output 1. A witness is information demonstrating a yes-instance: here, an input producing 1.

A prover tries to convince a verifier that a statement belongs to the language. Three different guarantees are important:

  1. Completeness: an honest prover can convince an honest verifier of a true statement.
  2. Soundness: a dishonest prover cannot convince an honest verifier of a false statement, except with small probability.
  3. Zero knowledge: a verifier learns no extra information from an honest prover's proof beyond what it could already establish, in the formal sense that its view can be simulated without the witness.

These conditions concern different choices of honest or dishonest parties. Mixing them up leads to wrong answers on the first exercise.

HW2 · Prerequisite: Interactive transcripts and simulation

In an interactive proof, a transcript records the messages exchanged: what the prover sent, what the verifier challenged, and how the prover responded.

A verifier's view can include its random coins and messages it sees. The ZK requirement says that a simulator , given the public statement but no secret witness, can create a view that is indistinguishable from a real interaction.

  • For honest-verifier ZK (HVZK), the simulator only needs to reproduce the view of a verifier that follows the protocol.
  • For full ZK, the simulator must handle any efficient, potentially malicious verifier.

A Sigma protocol is a three-move structure: prover's first message ; verifier's random challenge ; prover's response . Completeness, soundness/knowledge, and HVZK can often be studied through these three messages.

A useful intuition: simulation is a test of what information the verifier could have generated by itself. If it can make a convincing transcript without the witness, the transcript does not demonstrate it learned the witness.

There are two arrangements:

  • Sequential: finish proof 1 before starting proof 2.
  • Parallel: send all first messages, receive all challenges, then send all responses.

Both may improve soundness, but their zero-knowledge proofs can differ substantially. Being able to simulate one interaction is not automatically enough to simulate many interactions against a malicious verifier.

  • AND: exactly when both are 1.

A wire carries one bit, and a gate relates three wire values: its two inputs and its output. A circuit is satisfiable if there exists an assignment to its input wires making the final output .

HW2 · Prerequisite: Hybrid arguments and simulated proofs

A hybrid argument proves that two complicated random experiments are indistinguishable by changing one small component at a time.

For example, if a circuit has gate transcripts, define:

  • World 0: all gate transcripts are real.
  • World 1: the first transcript is simulated; the rest are real.
  • World 2: the first two are simulated.
  • … until every transcript is simulated.

If each neighboring pair is computationally indistinguishable, no efficient observer can reliably tell the first world from the last (as long as there are polynomially many steps).

Important technical distinction: a Sigma protocol's HVZK guarantee normally concerns true public statements. An argument that simulates proofs for false gate statements needs a simulator that can produce accepting-looking transcripts for those statements too, or another rigorous hybrid argument supporting the change. The supplied exercise's solution presents this last step informally, and the next card labels that limitation explicitly rather than assuming it away.
