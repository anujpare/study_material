First, we need numbers we can divide

Our first construction checked bits in a fixed PCP string. To build the polynomial version, we need to store calculation values in one polynomial and test equations about them. What makes a random polynomial test reliable? A simple fact about roots—but only when we use the right arithmetic.

A polynomial is an expression such as \(f(X)=3X^2-7X+6\). The symbol \(X\) stands for a number we can substitute. For instance, \(f(2)=3\cdot4-7\cdot2+6=4\). The largest exponent here is 2, so the polynomial has degree 2. A root is a number \(a\) for which \(f(a)=0\).

Instead of using the real numbers, cryptography often uses a small arithmetic world called a finite field. For a prime number \(p\), the field \(\mathbb F_p\) contains \(0,1,\ldots,p-1\). We add and multiply normally, then keep the remainder after division by \(p\).

For example, in \(\mathbb F_{17}\), we have \(15+5=20\equiv3\pmod{17}\). The symbol \(\equiv\) means the two sides leave the same remainder when divided by 17.

What matters about a field?

Every nonzero number has a multiplicative inverse: another number you can multiply it by to get 1. In \(\mathbb F_{17}\), the inverse of 5 is 7, because \(5\cdot7=35\equiv1\pmod{17}\).

That gives us a simple but powerful rule. If \(ab=0\) and \(a\ne0\), then multiplying both sides by \(a^{-1}\) gives \(b=0\). In other words, two nonzero field elements cannot multiply to zero.

Keep that rule in mind. It's the reason the polynomial root proof works.

II · Polynomial reasoning · Lecture §3

How can one polynomial remember a list of values?

The polynomial oracle we want will store values from a computation. A computation produces a list—one result after another. Can we arrange for a single polynomial to remember that list, so the verifier can ask for any chosen entry by evaluating the polynomial?

Start with a tiny list: the values 2, 5, and 10 at positions 0, 1, and 2. We'd like to make one polynomial that gives exactly those three answers. This will show how the general encoding works.

Let's begin with just the first two conditions. Try the simplest polynomial with two unknown coefficients, \(f(X)=aX+b\). Asking for \(f(0)=2\) gives \(b=2\). Asking for \(f(1)=5\) gives \(a+b=5\), so \(a=3\). We obtain \(f(X)=3X+2\).

But this polynomial gives \(f(2)=8\), not 10. We need a little more freedom. Add a term that is zero at both 0 and 1, so it won't spoil what we already fitted:

\[f(X)=2+3X+cX(X-1).\]

At \(X=0\), the last term is zero. At \(X=1\), it's also zero. At \(X=2\), the condition becomes \(10=2+6+2c\), so \(c=1\). Our polynomial is

\[f(X)=2+3X+X(X-1)=X^2+2X+2.\]

Check all three points: \(f(0)=2\), \(f(1)=5\), and \(f(2)=10\). We've made a single degree-two polynomial hold three specified numbers.

This process is called interpolation: given values at certain points, construct a polynomial that takes those values.

Change the values the polynomial must remember

Choose three outputs over \(\mathbb F_{17}\). The displayed polynomial changes to fit all three.

Why do we care?

We could place the outputs of a long computation at points \(0,1,2,\ldots\) and choose a polynomial that matches them. Suppose there are \(N\) values in the computation list. We use \(N\) here to count those values; it is not the \(M\) that counted the bits of a PCP proof earlier. At \(N\) distinct field points, there is exactly one polynomial of degree at most \(N-1\) that fits the prescribed values.

There is a reason it is unique. If two degree-at-most-\((N-1)\) polynomials agreed at all \(N\) points, their difference would have \(N\) roots. We're about to prove that a nonzero polynomial of that degree cannot have so many roots. The two polynomials must therefore be the same.

We're not claiming that the coefficients magically compress the list. The advantage is different: once the values are encoded in a polynomial, we can test mathematical relations among them by asking for only a few evaluations.

Interpolation gives us the representation we wanted: a computation's values can live inside a polynomial. But a dishonest prover can represent a wrong list just as easily. To verify anything, we need a way to test polynomial equations without reading every coefficient. That is why the root-count fact matters next.

II · Polynomial reasoning · Lecture §3, Theorem 1 and Lemma 1

How can one random point catch a false equation?

We can now encode a whole list in one polynomial, but so can a cheater. To decide whether the claimed calculation is right, we'll need to check equations involving that polynomial. Can we check one equation without reading every coefficient?

Let's begin with the simplest case: the prover says two polynomials \(f(X)\) and \(g(X)\) are identical. If we evaluate both at one random number, how likely is a false claim to slip through?

Of course it might fail sometimes. Two different polynomials can happen to agree at one point. The question is: how often? We can answer that exactly enough to build a proof system.

Theorem 1: a nonzero degree-\(d\) polynomial has at most \(d\) roots

First, if \(a\) is a root of a polynomial \(h\), the factor theorem lets us write \(h(X)=(X-a)k(X)\). This comes from polynomial division: dividing \(h\) by \(X-a\) leaves remainder \(h(a)\), and a root makes that remainder zero.

Now suppose \(b\) is another root, distinct from \(a\). Substitute it into our factorization:

\[0=h(b)=(b-a)k(b).\]

Because \(a\ne b\), the field number \(b-a\) is nonzero. A field has no product of two nonzero elements equal to zero. So \(k(b)=0\). Notice what happened: after removing the factor for root \(a\), the remaining polynomial still has root \(b\).

Every different root lets us remove one more linear factor, reducing the degree by one. We cannot remove more than \(d\) such factors from a nonzero polynomial of degree \(d\).

Therefore a nonzero polynomial of degree \(d\) has at most \(d\) distinct roots. The argument works because field arithmetic lets us cancel every nonzero factor. \(\square\)

Now use the theorem to test equality

Assume both \(f\) and \(g\) have degree at most \(d\). The verifier picks a uniformly random point \(r\) from the field \(\mathbb F\) and accepts if \(f(r)=g(r)\).

If \(f=g\), the verifier always accepts. That's perfect completeness. For soundness, suppose the claim is false: \(f\ne g\). Define

\[h(X)=f(X)-g(X).\]

Because \(f\) and \(g\) are different, \(h\) is not the zero polynomial. Its degree is at most \(d\), since subtraction cannot increase the largest exponent.

The verifier accepts by mistake exactly when \(f(r)=g(r)\), which is exactly when \(h(r)=0\). So a false acceptance corresponds to a root of this nonzero polynomial. Our theorem says there are at most \(d\) such points among the \(|\mathbb F|\) equally likely choices.

\[\boxed{\Pr[f(r)=g(r)\mid f\ne g]\le\frac{d}{|\mathbb F|}.}\]

Here \(|\mathbb F|\) is the number of field elements. For example, if the field has 17 elements and the difference has degree 2, at most two choices of \(r\) can make the false equality pass.

Find the bad random choices yourself

Over \(\mathbb F_{17}\), compare \(f(X)=X^2+1\) with \(g(X)=f(X)+(X-1)(X-4)\). They're different, but at two points they agree.

This completes the EqualityTest proof: a false claim gives a nonzero polynomial; the verifier is fooled only at its roots; and there are few roots. That is why one random test works. \(\square\)

One condition is essential: both polynomials must be fixed before the random point is chosen. If the prover learned \(r\) first, it could arrange for two different polynomials to agree at that point. The commitment scheme will later enforce this order.

We have our first cheap check: a false polynomial identity can hold at only a few random points. The lecture next extends that idea to equations with several variables, which we'll need for a midterm problem. Then we'll return to our original computation: how to require an equation to hold at every step of a long list.

II · Polynomial reasoning · Lecture §3, Lemma 2

What if the equation has several variables?

Our random test relied on one fact: a nonzero polynomial can be zero at only a limited number of points. But some verification equations involve several random numbers at once. Does the same reasoning still protect us?

It does. Schwartz–Zippel is the extension of the same root argument to several variables. The proof below reduces the many-variable case to the one-variable fact we already proved.

Take \(h(X,Y,Z)=3X^2Y^3Z+2XY^2\). In the first term the exponents add up to \(2+3+1=6\); in the second they add to \(1+2=3\). The largest sum, 6, is the total degree.

Schwartz–Zippel lemma. Let \(h(X_1,\ldots,X_m)\) be a nonzero polynomial of total degree at most \(d\) over a field. Choose each \(r_i\) independently and uniformly from a finite subset \(\Omega\) of the field. Then

\[\boxed{\Pr[h(r_1,\ldots,r_m)=0]\le\frac d{|\Omega|}.}\]

The bound looks exactly like the one-variable bound. That's no accident. Here's why it works.

Proof: treat the last variable separately

We'll prove the result by adding one variable at a time. With one variable, we already know the root theorem, so the result is true.

Now suppose we've proved it for \(m-1\) variables. Write our polynomial by collecting the powers of its last variable \(X_m\):

\[ h(X_1,\ldots,X_m)= g_0(X_1,\ldots,X_{m-1})+\cdots+ g_t(X_1,\ldots,X_{m-1})X_m^t. \]

The coefficient \(g_t\) is not the zero polynomial, because \(t\) is the highest power of \(X_m\) that actually occurs. And since the entire expression has total degree at most \(d\), the total degree of \(g_t\) is at most \(d-t\).

Choose random values for the first \(m-1\) variables. Two things can happen.

First case: the leading coefficient \(g_t\) evaluates to zero. By the induction assumption, that happens with probability at most \((d-t)/|\Omega|\).

Second case: the leading coefficient is nonzero. Now the first \(m-1\) values are fixed, leaving a nonzero polynomial of degree \(t\) in the single variable \(X_m\). The root theorem says a uniform value for \(X_m\) makes it zero with probability at most \(t/|\Omega|\).

Every way the full polynomial can become zero belongs to one of these cases. Adding their probability bounds gives

\[ \Pr[h(\mathbf r)=0]\le \frac{d-t}{|\Omega|}+\frac t{|\Omega|} =\frac d{|\Omega|}. \]

That's the lemma. We reduced the multivariable problem to a smaller multivariable problem plus the one-variable root bound. The degrees add to \(d\), so the probability bounds do too. \(\square\)

Before using the lemma in an exam, check one thing above all: is your polynomial really nonzero when the statement is false? A zero polynomial evaluates to zero at every point, so no random test could distinguish it.

Whether an equation has one variable or several, soundness comes from the same chain: a false claim makes a nonzero polynomial, and the degree limits the chance that a random evaluation is zero. Exam problem: can a vector hide more than one vote?

This problem is important because the arithmetic is simple but the logic must be exact. You have to prove that every invalid vector gives a nonzero polynomial—not just the invalid examples you can think of.

Previous midterm · Problem 3(c.1) · Four marks

We work in \(\mathbb Z_p\), for an odd prime \(p\). A vector \(\mathbf x=(x_1,\ldots,x_N)\) is allowed to be either all zero, or a standard basis vector \(\mathbf e_i\), which has exactly one entry equal to 1 and all others zero.

The verifier chooses \(\mathbf r=(r_1,\ldots,r_N)\) uniformly at random and makes \(\mathbf r_{\mathrm{sq}}=(r_1^2,\ldots,r_N^2)\). It accepts if

\[ \langle\mathbf x,\mathbf r\rangle^2= \langle\mathbf x,\mathbf r_{\mathrm{sq}}\rangle. \]

The angle brackets mean \(\langle\mathbf x,\mathbf r\rangle=\sum_i x_i r_i\): multiply matching entries and add. Prove perfect completeness and soundness error at most \(2/p\).

Show every step of the proof

1. An allowed vector always passes

If \(\mathbf x=\mathbf0\), both sums are zero. If \(\mathbf x=\mathbf e_j\), the left inner product picks out \(r_j\), and squaring it gives \(r_j^2\). The right inner product also picks out \(r_j^2\). So every allowed vector passes for every choice of \(\mathbf r\). That's perfect completeness.

2. What would make an invalid vector pass?

Put both sides of the acceptance equation on one side:

\[ h(\mathbf r)=\left(\sum_{i=1}^N x_i r_i\right)^2 -\sum_{i=1}^N x_i r_i^2. \]

For the fixed vector \(\mathbf x\), this is a polynomial in the random numbers \(r_i\). The verifier accepts exactly when \(h(\mathbf r)=0\). It has total degree at most 2. We still need to show it is nonzero for every invalid vector.

3. Every invalid vector falls into one of two cases

Case A: exactly one entry is nonzero. Say \(x_j=a\). Since the vector is invalid, \(a\ne1\); since it's the nonzero entry, \(a\ne0\). Then

\[ h(\mathbf r)=(ar_j)^2-ar_j^2 =a(a-1)r_j^2. \]

Neither \(a\) nor \(a-1\) is zero, so their product is nonzero in a field. Thus \(h\) is not the zero polynomial.

Case B: two or more entries are nonzero. Choose two, \(x_i\ne0\) and \(x_j\ne0\), with \(i\ne j\). Squaring the first sum creates the term \(2x_ix_jr_ir_j\). The second sum contains only squared terms \(r_k^2\), so it cannot cancel a term containing \(r_ir_j\) with two distinct indices. Since \(p\) is odd, \(2x_ix_j\ne0\). Again \(h\) is nonzero.

These cases exhaust the invalid possibilities. The all-zero vector is valid; any other invalid vector has either one nonzero entry that is not 1, or more than one nonzero entry.

4. Apply Schwartz–Zippel

For every invalid vector we've proved that \(h\) is nonzero and has total degree at most 2. Each random coordinate comes from the \(p\)-element field. So

\[ \boxed{\Pr[\text{invalid vector passes}]= \Pr[h(\mathbf r)=0]\le\frac2p.} \]

That's the soundness proof. We established the precise polynomial whose zero means acceptance, showed it can't be identically zero for an invalid vote, and then used its degree to bound false acceptance. \(\square\)

The assumption that \(p\) is odd matters. If \(p=2\), the coefficient 2 in Case B becomes zero, and that argument no longer works.

II · Polynomial reasoning · Lecture §3, Theorem 2

What if we need the equation to hold at many specific points?

We've learned to test whether one polynomial equation is true everywhere. But checking a computation requires something slightly different: a rule must hold at each step in a long list. The rule need not hold at arbitrary points between those steps. How can we turn many separate conditions into one polynomial identity?

Suppose we need a polynomial \(f\) to be zero at every point in a set \(\Omega\). Make a new polynomial that is guaranteed to be zero at exactly those designated points:

\[\boxed{Z_\Omega(X)=\prod_{a\in\Omega}(X-a).}\]

The symbol \(\prod\) means multiply all the listed factors. For example, when \(\Omega=\{1,2\}\), we have \(Z_\Omega(X)=(X-1)(X-2)\). The product is zero at 1 and at 2 because one factor becomes zero in each case.

Now here's the useful fact: \(f\) is zero at all points of \(\Omega\) exactly when \(f\) is divisible by \(Z_\Omega\). Divisible means there is some polynomial \(q\) with \(f(X)=Z_\Omega(X)q(X)\).

Theorem 2: prove both directions

If \(f=Z_\Omega q\): pick any \(a\in\Omega\). One factor of \(Z_\Omega(a)\) is zero, so \(f(a)=Z_\Omega(a)q(a)=0\). Therefore divisibility makes \(f\) zero at every required point.

Now the other direction. Suppose \(f(a)=0\) for every \(a\in\Omega\). List the distinct points as \(a_1,\ldots,a_k\). Because \(a_1\) is a root, the factor theorem gives \(f(X)=(X-a_1)q_1(X)\).

Substitute \(a_2\). We get \(0=(a_2-a_1)q_1(a_2)\). The points are different, so \(a_2-a_1\ne0\); field cancellation tells us \(q_1(a_2)=0\). Thus \(q_1\) also has factor \(X-a_2\). Continue through all the points. We obtain \(f(X)=(X-a_1)\cdots(X-a_k)q(X)=Z_\Omega(X)q(X)\). If \(f\) is the zero polynomial, the same conclusion holds by taking \(q=0\).

\[ \boxed{f(a)=0\ \forall a\in\Omega \iff f(X)=Z_\Omega(X)q(X)\text{ for some }q.} \]

We have both implications, so the two conditions are equivalent. Checking that \(f\) vanishes at many places can now become checking one polynomial equation. That's exactly the kind of thing a random equality test can handle. \(\square\)

Try a concrete factorization.

Let \(f(X)=X^3-7X+6\). Then \(f(X)=(X-1)(X-2)(X+3)\). For \(\Omega=\{1,2\}\), the vanishing polynomial is \((X-1)(X-2)\), and the quotient is \(q(X)=X+3\).

The many required zeros have become one equation: \(f=Z_\Omega q\). We haven't actually checked that equation yet. But we already know how to do so: fix the polynomials, choose one random point, and compare their values. That gives us ZeroTest.

II · Polynomial reasoning · Lecture §3, Lemma 3

One random check for many required zeros

We have two pieces that now fit together. Vanishing polynomials turn many step-by-step requirements into a single identity \(f=Z_\Omega q\). EqualityTest tells us how to test a fixed polynomial identity at one random point. Put them together and we can check all the required steps cheaply.

Suppose \(f\) has degree at most \(d\) and \(\Omega\) contains \(k\le d\) distinct field elements. The prover gives the quotient polynomial \(q\), claiming that

\[f(X)=q(X)Z_\Omega(X).\]

The prover must fix both polynomials first, with \(\deg q\le d\) as required by the lecture's protocol. The verifier then picks a uniform random field element \(r\), queries \(f(r)\) and \(q(r)\), computes the known value \(Z_\Omega(r)\), and checks

\[\boxed{f(r)=q(r)Z_\Omega(r).}\]

Try it with \(\Omega=\{1,2\}\), \(q(X)=X+3\), and \(f(X)=(X-1)(X-2)(X+3)\). You can also choose a false claim obtained by adding \(X-3\) to \(f\).

Which random choices catch the cheat?

Choose the challenge and switch between the honest and dishonest polynomial.

Why ZeroTest works

Completeness. If \(f\) is zero on \(\Omega\), Theorem 2 guarantees a polynomial \(q\) satisfying \(f=qZ_\Omega\). The equation holds at every point, so the verifier always accepts the honest prover.

Soundness. Suppose \(f\) fails to be zero at some required point. Theorem 2 says no polynomial \(q\) can satisfy the claimed identity everywhere. So, for any cheating quotient, the difference

\[h(X)=f(X)-q(X)Z_\Omega(X)\]

is a nonzero polynomial. The verifier accepts a false claim exactly when \(h(r)=0\).

How many roots can it have? The degree of \(f\) is at most \(d\). The degree of \(Z_\Omega\) is \(k\), and the prover's quotient has degree at most \(d\). Thus the product has degree at most \(d+k\), and subtraction cannot increase this bound:

\[\deg h\le\max(d,d+k)\le2d.\]

Our root theorem now says a uniform random \(r\) is one of the at most \(2d\) roots with probability at most \(2d/|\mathbb F|\).

\[\boxed{\Pr[\text{false acceptance}]\le\frac{2d}{|\mathbb F|}.}\]

That proves ZeroTest soundness. A false claim makes \(h\) nonzero; the degree limit keeps the number of roots small; and an error occurs only when the random challenge hits one of those roots. \(\square\)

II · Polynomial reasoning · Lecture §3

Can a verifier check the hundredth Fibonacci number cheaply?

So far we've proved mathematical tools, not a complete proof of a computation. Let's use them together on one long calculation. We'll choose Fibonacci because its next value depends only on the previous two, giving us an easy rule to turn into a polynomial identity.

The Fibonacci rule is simple: each value is the sum of the two before it. With the standard initial values

\[F_0=0,\quad F_1=1,\quad F_{i+2}=F_{i+1}+F_i,\]

the hundredth value is \(F_{100}=354\,224\,848\,179\,261\,915\,075\).

Notation correction in the lecture example: the official notes use initial values 1 and 1 but give the number corresponding to the 0, 1 convention. We use 0 and 1 here so the example is arithmetically consistent; the proof method is the same.

We ask the prover to construct a polynomial \(f_{\mathrm{fib}}(X)\) whose value at each integer \(i=0,\ldots,100\) equals the claimed Fibonacci number at that step. Interpolation gives a polynomial of degree at most 100. We work over a prime field large enough that these integers remain distinct from any modular wraparound in the computation.

Which claims must we check?

Two initial conditions, the proposed result, and the rule at every intermediate step:

\[ \begin{aligned} f_{\mathrm{fib}}(0)&=0,\quad f_{\mathrm{fib}}(1)=1,\\ f_{\mathrm{fib}}(100)&=354\,224\,848\,179\,261\,915\,075,\\ f_{\mathrm{fib}}(i+2)&=f_{\mathrm{fib}}(i+1)+f_{\mathrm{fib}}(i), \qquad i=0,\ldots,98. \end{aligned} \]

Checking the first three values is easy: ask the polynomial oracle at 0, 1, and 100. The difficulty is the 99 recurrence equations. Define one polynomial measuring how much each equation fails:

\[ R(X)=f_{\mathrm{fib}}(X+2)-f_{\mathrm{fib}}(X+1)-f_{\mathrm{fib}}(X). \]

The recurrence holds at step \(i\) precisely when \(R(i)=0\). Thus all 99 steps are right precisely when \(R\) is zero on \(\Omega=\{0,1,\ldots,98\}\).

But we just proved what that means: there must be a quotient \(q\) with

\[ R(X)=q(X)Z_\Omega(X),\qquad Z_\Omega(X)=\prod_{i=0}^{98}(X-i). \]

The prover puts \(f_{\mathrm{fib}}\) and \(q\) in the ideal polynomial oracle. The verifier asks for the fixed initial and final evaluations, then chooses a random \(r\) and checks

\[ f_{\mathrm{fib}}(r+2)-f_{\mathrm{fib}}(r+1)-f_{\mathrm{fib}}(r) =q(r)Z_\Omega(r). \]
See why the initial values determine the rest

Walk through a shorter sequence using exactly the same rule.

Does this actually prove the claimed result?

Suppose the conditions hold. We know the values at positions 0 and 1. The recurrence at \(i=0\) forces the value at 2 to be \(0+1=1\). The next recurrence forces the value at 3 to be \(1+1=2\). The same reasoning continues: once two consecutive values are known, the next is forced.

So by induction the polynomial's values at every integer step must equal the Fibonacci sequence defined by \(F_0=0,F_1=1\). In particular its value at step 100 is the true \(F_{100}\). The separate final check makes sure it equals the number the prover claimed.

If the claim is false, the prover cannot satisfy all the equations, so the ZeroTest has a nonzero discrepancy polynomial. Its root bound controls the probability of a false acceptance.

We have connected the random polynomial test to the original calculation: it checks the recurrence at all required steps, and the initial values then force the entire sequence. \(\square\)

What have we accomplished?

We can check a long calculation without checking every step. Interpolation puts the results in one polynomial; the recurrence becomes a vanishing-polynomial identity; and a random evaluation tests that identity with a proved soundness bound.

What is still missing before this becomes a SNARG? Our polynomial oracle is imaginary, the verifier still sends a random challenge, and Fibonacci has a special recurrence rather than arbitrary program logic. There's also an efficiency problem: directly calculating \(Z_\Omega(r)\) requires multiplying 99 factors. The next chapters will solve these specific problems in turn.

Start with the most immediate missing piece. Just as Merkle trees replaced the ideal PCP bit box, a polynomial commitment will replace our ideal polynomial box so that a dishonest prover cannot change the values after seeing the random query.
