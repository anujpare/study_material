Lecture §3 · The Magic of Polynomials

Why would a polynomial help us verify a calculation?

The PCP construction is one way to make a short argument. The lecture now turns to the method used by PLONK: instead of encoding a general proof into bits, encode the values of a calculation in a polynomial and check equations about those values.

Here is the lecture's example. Someone tells us that the hundredth Fibonacci number is

\[354\,224\,848\,179\,261\,915\,075.\]

Fibonacci numbers follow a simple rule: each is the sum of the previous two. With the standard convention \(F_0=0,F_1=1\), the first terms are \(0,1,1,2,3,5,\ldots\). Checking the claimed hundredth value directly would mean following the recurrence up to step 100. That is possible, but it is the very computation we'd like the prover to save us from doing.

Inconsistency in the provided notes: the lecture writes \(f(0)=f(1)=1\) but gives the value \(354224848179261915075\), which is \(F_{100}\) for the \(0,1\) convention. Both statements cannot simultaneously hold under the displayed indexing. We'll keep the stated numerical target and use \(f(0)=0,f(1)=1\) for a consistent example. The protocol and proofs are unchanged.

Suppose the prover could hand us one mathematical function \(f\) with a special property: asking for \(f(i)\) would reveal the value it claims for step \(i\). If we could check all the recurrence equations by examining only a few values of \(f\), we would have the kind of verification shortcut we want.

The lecture chooses \(f\) to be a polynomial: an expression such as \(f(X)=3X^2-7X+6\), built from sums of powers of an input \(X\). To evaluate it at 2, substitute \(X=2\), giving \(3\cdot4-7\cdot2+6=4\). The largest exponent with a nonzero coefficient is its degree, here 2.

Why do polynomial tests use a finite field?

The next task is to construct a polynomial through 101 prescribed values. That requires solving equations for its coefficients, including division by nonzero numbers. Later, to test whether the recurrence holds, the verifier will evaluate an equation at a random point and bound the chance of a false match. We therefore want a finite set from which to sample uniformly, with arithmetic that supports division and the usual polynomial factorization rules. That's why the protocol works over a finite field.

For a prime \(p\), the field \(\mathbb F_p\) contains the integers \(0,1,\ldots,p-1\). We add and multiply as usual, then keep the remainder modulo \(p\). For example, in \(\mathbb F_{17}\), \(15+5\equiv3\), since 20 leaves remainder 3 upon division by 17.

We can divide by any nonzero field element because it has a multiplicative inverse. In \(\mathbb F_{17}\), the inverse of 5 is 7, since \(5\cdot7=35\equiv1\). This will let us use the familiar rule: if \(ab=0\) and \(a\ne0\), then \(b=0\).

For the actual hundredth Fibonacci value, the prime field must be large enough that the integer target and intermediate sequence values are represented without unwanted wraparound if we mean to prove that exact integer value. The smaller fields in the interactive examples are only for learning the algebra.

The field is not an independent topic. We chose it because the prover must interpolate the claimed Fibonacci values, and the verifier later needs a sound randomized polynomial test. Let's first construct a polynomial through the familiar values \(0,1,1,2,\ldots\). That will also make the need for division concrete.

Lecture §3 · Preparing the polynomial IOP

Can one polynomial remember a hundred Fibonacci numbers?

Before checking the recurrence, the prover needs a way to represent its proposed sequence. It has a value for each position \(0,1,\ldots,100\). Can one polynomial be made to return precisely those values when we ask for them?

Use the first three Fibonacci values from our running calculation: \(F_0=0\), \(F_1=1\), and \(F_2=1\). We want one polynomial whose values at \(X=0,1,2\) are exactly 0, 1, 1. Try the simplest possibility first: a straight line \(f_2(X)=aX+b\). The first condition makes \(b=0\), and the second makes \(a=1\). Our line is therefore \(f_2(X)=X\). But at \(X=2\) it gives 2, not the required 1.

To correct the value at \(X=2\) without changing the first two values, add a term that is zero at 0 and 1. The product \(X(X-1)\) has precisely that property. So try

\[f_2(X)=X+cX(X-1).\]

At \(X=2\), the required value 1 gives \(2+2c=1\). Hence \(c=-1/2\), which we can calculate because we're working in a field and 2 has an inverse. Our polynomial is

\[\boxed{f_2(X)=X-\tfrac12X(X-1)=\tfrac12X(3-X).}\]

Check every condition: \(f_2(0)=0\), \(f_2(1)=1\), and \(f_2(2)=1\). We have represented the first three Fibonacci numbers, not proved their correctness. If the prover changed one of those numbers, another interpolating polynomial would still exist.

Fit the first three Fibonacci values

Start with 0, 1, 1. Change one value to see that a polynomial will also fit an incorrect sequence. The arithmetic is over \(\mathbb F_{17}\).

What if there are a hundred values?

Exactly the same trick continues. Suppose we've already fitted values at \(0,1,\ldots,j\). To fit the next point \(j+1\), add a multiple of

\[X(X-1)\cdots(X-j).\]

At every earlier position one of those factors is zero, so the previous values stay unchanged. At \(X=j+1\), the product is nonzero because all the points are distinct field elements. We can therefore choose the multiplier by dividing the required correction by that product. The field's inverses are what make this step possible.

Repeating the construction gives a polynomial of degree at most \(N-1\) through any \(N\) prescribed values at \(N\) distinct field points. This is called interpolation.

So the prover can encode the proposed Fibonacci values \(F_0,\ldots,F_{100}\) in one polynomial \(f_{\rm fib}\) of degree at most 100. Asking for \(f_{\rm fib}(i)\) is asking for the number it placed at position \(i\).

This does not mean a hundred values have magically been compressed into a few bits. The polynomial can still have 101 coefficients, and the prover must do the work of constructing it. The advantage will come later: the verifier can test equations involving those values from just a few polynomial evaluations instead of reading the entire list.

One question remains: could there be two different degree-at-most-100 polynomials fitting the same 101 values? We'll answer that after proving a key fact about polynomial roots. For now we have shown how a fitting polynomial can be constructed.

We now have an algebraic representation of the witness: one polynomial gives the claimed value at each Fibonacci index. But interpolation ignores the recurrence. The prover can choose any list and construct a polynomial through it. To certify the actual computation, we need to enforce the relation (f_{ m fib}(i+2)=f_{ m fib}(i+1)+f_{ m fib}(i)) at every required step. The next lesson turns the failure of this relation into a polynomial, and asks what a random evaluation can tell us about it.

Lecture §3 · EqualityTest, Theorem 1 and Lemma 1

If two polynomials agree once, are they equal?

Interpolation lets the prover create a polynomial \(f_{\rm fib}(X)\) through its claimed Fibonacci values, but that does not prove the values are correct. The actual rule is \(f_{\rm fib}(i+2)=f_{\rm fib}(i+1)+f_{\rm fib}(i)\) at each step \(i=0,\ldots,98\). Subtract the right side and call the result the recurrence discrepancy:

\[D(X)=f_{\rm fib}(X+2)-f_{\rm fib}(X+1)-f_{\rm fib}(X).\]

We need \(D(i)=0\) at every required step. Eventually we'll express those many requirements as one polynomial identity. But first we need to know whether a verifier can test any fixed polynomial identity without inspecting every coefficient. That is the simpler problem EqualityTest solves.

One matching value doesn't prove equality with certainty. For example, \(f(X)=0\) and \(g(X)=X-3\) differ as polynomials but both give zero at \(X=3\). The useful question is not whether they could match by accident; it is how many choices of \(r\) would make that accident happen.

Call \(h(X)=f(X)-g(X)\) the difference. The verifier is fooled exactly when \(h(r)=0\). A number that makes a polynomial zero is called a root. So we need to know how many roots a nonzero polynomial can have.

Theorem 1: a nonzero degree-\(d\) polynomial has at most \(d\) roots

Suppose \(h(a)=0\). Every expression \(X^j-a^j\) is divisible by \(X-a\): for example \(X^2-a^2=(X-a)(X+a)\). By applying this fact to each term, \(h(X)-h(a)\) is divisible by \(X-a\). Since \(h(a)=0\), we can write \(h(X)=(X-a)q(X)\).

If \(b\ne a\) is another root, substitute it into that equation:

\[0=h(b)=(b-a)q(b).\]

The factor \(b-a\) is nonzero. In a field, a product can be zero only if one factor is zero, so \(q(b)=0\). In other words, after removing the factor for root \(a\), the other roots remain roots of the quotient.

Each new distinct root therefore supplies another linear factor and reduces the degree by one. A nonzero degree-\(d\) polynomial cannot have more than \(d\) different linear factors.

Thus it has at most (d) distinct roots. The proof depends on being able to cancel the nonzero factor (b-a), which explains the field assumption. \(\square\)

HW3 · Problem 1(c)

Does the polynomial root bound hold modulo 6?

Consider \(f(X)=2X^2+4X\) with arithmetic modulo 6. It has degree 2. Could it have more than two roots (inputs where it evaluates to zero)? Test all six possible values of \(X\).

Find every root modulo 6

Change \(r\) and inspect the remainder of \(2r^2+4r\).

Work out the counterexample

The values 0, 1, 3 and 4 all make the polynomial zero modulo 6. So a degree-two polynomial has four different roots! Why doesn't that contradict the rule we want to use?

Because arithmetic modulo 6 is not a field. In particular \(2\cdot3\equiv0\pmod6\) although neither 2 nor 3 is zero. We cannot cancel nonzero factors here. The ordinary proof that a degree-\(d\) polynomial has at most \(d\) roots depends on being able to cancel such factors.

The root-count claim is false over \(\mathbb Z_6\), and this shows exactly which algebraic assumption fails. The later soundness proofs will work over fields instead. \(\square\)

Apply the theorem to EqualityTest

Let \(f\) and \(g\) both have degree at most \(d\), and let the verifier choose \(r\) uniformly at random from a finite field \(\mathbb F\). It accepts if \(f(r)=g(r)\).

Completeness: if \(f=g\), the equality holds at every point, so the verifier always accepts.

Soundness: if \(f\ne g\), then \(h=f-g\) is a nonzero polynomial of degree at most \(d\). The verifier accepts incorrectly only if it chooses one of the at most \(d\) roots of \(h\). There are \(|\mathbb F|\) equally likely field values, so

\[\boxed{\Pr[f(r)=g(r)\mid f\ne g]\le\frac{d}{|\mathbb F|}.}\]

That is Lemma 1 in the lecture: perfect completeness and soundness error at most \(d/|\mathbb F|\).

Find exactly which checks miss a false claim

Over \(\mathbb F_{17}\), compare \(f(X)=X^2+1\) with \(g(X)=f(X)+(X-1)(X-4)\). They're different, but agree at two points.

We can also settle the uniqueness question from interpolation. If two degree-at-most-\((N-1)\) polynomials agreed at \(N\) distinct points, their difference would have at least \(N\) roots while having degree at most \(N-1\). Unless the difference is zero everywhere, that contradicts Theorem 1. So the interpolation polynomial is unique.

There is one further condition that makes the probability argument work. The polynomials must be fixed before the verifier chooses \(r\). Otherwise a cheater who learns \(r\) could invent \(g(X)=f(X)+(X-r)\), which is a different polynomial but guaranteed to agree with \(f\) at that already-known point. Later we'll use commitments to enforce the correct order.

EqualityTest provides the missing testing method: if two low-degree polynomials are fixed before the challenge, one random evaluation can reveal a false identity with high probability. But Fibonacci's recurrence is required only at the 99 step positions, not at every field element. We still need to turn those 99 local conditions into a genuine polynomial identity. First, the lecture generalizes the same root argument to several variables; then we'll return to that exact Fibonacci obstacle.

Lecture §3 · Lemma 2, Schwartz–Zippel

What changes when the equation has more than one variable?

EqualityTest gives the bound we need when an identity depends on one variable. Before we apply it to Fibonacci, the lecture establishes the more general Schwartz–Zippel lemma for equations involving several variables. This is a generalization, not a new requirement of Fibonacci: our recurrence polynomial still has only one variable. We prove the general result because the same reasoning is useful in other polynomial verification problems.

Take \(h(X,Y)=XY\) over \(\mathbb F_7\). The polynomial is zero if \(X=0\) or \(Y=0\). If we choose each coordinate independently from the seven field elements, there are \(7\times7=49\) equally likely pairs. Seven have \(X=0\), seven have \(Y=0\), and \((0,0)\) was counted twice. So exactly 13 pairs make this nonzero polynomial zero.

For multivariable polynomials, we need a measure of degree. In each term, add the exponents of its variables, then take the largest result. For instance \(3X^2Y^3Z+2XY^2\) has total degree \(2+3+1=6\).

Now we can state Lemma 2, Schwartz–Zippel. Let \(h(X_1,\ldots,X_m)\) be a nonzero polynomial of total degree at most \(d\). Choose each \(r_i\) independently and uniformly from a finite subset \(\Omega\) of the field. Then

\[\boxed{\Pr[h(r_1,\ldots,r_m)=0]\le\frac{d}{|\Omega|}.}\]

It is the same sort of bound as before. The proof explains why the number of variables does not suddenly make the chance of a false acceptance large.

Proof: remove one variable at a time

For one variable, this is the root-count result we've already proved. Suppose the result holds for \(m-1\) variables. Collect the powers of the last variable \(X_m\):

\[h(X_1,\ldots,X_m)=\sum_{j=0}^{t}g_j(X_1,\ldots,X_{m-1})X_m^j,\qquad g_t\ne0.\]

The last coefficient \(g_t\) is nonzero, because \(t\) is the highest power that actually occurs. Since \(h\) has total degree at most \(d\), \(g_t\) has degree at most \(d-t\).

First choose random values for the first \(m-1\) variables. There is a chance that \(g_t\) evaluates to zero; by our induction assumption, that chance is at most \((d-t)/|\Omega|\).

Otherwise \(g_t\) remains nonzero. Once those first values are fixed, the original \(h\) becomes a nonzero polynomial of degree \(t\) in the single variable \(X_m\). The ordinary root bound says the last random choice \(r_m\) can make it zero with conditional probability at most \(t/|\Omega|\).

Every way the full expression can become zero falls into these cases. Adding their probability bounds gives

\[\Pr[h(\mathbf r)=0]\le\frac{d-t}{|\Omega|}+\frac{t}{|\Omega|}=\frac{d}{|\Omega|}.\]

We have proved the lemma by induction from the one-variable root theorem. As before, a soundness proof must first establish that a false claim produces a nonzero polynomial. \(\square\)

For the example \(XY\), the total degree is 2, so the lemma gives the bound \(2/7=14/49\). We counted 13 zeros. The bound is correct, and it applies to every nonzero polynomial with the stated total degree, not just this example.

II · Polynomial reasoning · 2025 midterm, Problem 3(c.1)

Exam problem: can a vector hide more than one vote?

This problem is important because the arithmetic is simple but the logic must be exact. You have to prove that every invalid vector gives a nonzero polynomial—not just the invalid examples you can think of.

Previous midterm · Problem 3(c.1) · Four marks

We work in \(\mathbb Z_p\), for an odd prime \(p\). A vector \(\mathbf x=(x_1,\ldots,x_N)\) is allowed to be either all zero, or a standard basis vector \(\mathbf e_i\), which has exactly one entry equal to 1 and all others zero.

The verifier chooses \(\mathbf r=(r_1,\ldots,r_N)\) uniformly at random and makes \(\mathbf r_{\mathrm{sq}}=(r_1^2,\ldots,r_N^2)\). It accepts if

\[ \langle\mathbf x,\mathbf r\rangle^2= \langle\mathbf x,\mathbf r_{\mathrm{sq}}\rangle. \]

The angle brackets mean \(\langle\mathbf x,\mathbf r\rangle=\sum_i x_i r_i\): multiply matching entries and add. Prove perfect completeness and soundness error at most \(2/p\).

Show every step of the proof

1. An allowed vector always passes

If \(\mathbf x=\mathbf0\), both sums are zero. If \(\mathbf x=\mathbf e_j\), the left inner product picks out \(r_j\), and squaring it gives \(r_j^2\). The right inner product also picks out \(r_j^2\). So every allowed vector passes for every choice of \(\mathbf r\). That's perfect completeness.

2. What would make an invalid vector pass?

Put both sides of the acceptance equation on one side:

\[ h(\mathbf r)=\left(\sum_{i=1}^N x_i r_i\right)^2 -\sum_{i=1}^N x_i r_i^2. \]

For the fixed vector \(\mathbf x\), this is a polynomial in the random numbers \(r_i\). The verifier accepts exactly when \(h(\mathbf r)=0\). It has total degree at most 2. We still need to show it is nonzero for every invalid vector.

3. Every invalid vector falls into one of two cases

Case A: exactly one entry is nonzero. Say \(x_j=a\). Since the vector is invalid, \(a\ne1\); since it's the nonzero entry, \(a\ne0\). Then

\[ h(\mathbf r)=(ar_j)^2-ar_j^2 =a(a-1)r_j^2. \]

Neither \(a\) nor \(a-1\) is zero, so their product is nonzero in a field. Thus \(h\) is not the zero polynomial.

Case B: two or more entries are nonzero. Choose two, \(x_i\ne0\) and \(x_j\ne0\), with \(i\ne j\). Squaring the first sum creates the term \(2x_ix_jr_ir_j\). The second sum contains only squared terms \(r_k^2\), so it cannot cancel a term containing \(r_ir_j\) with two distinct indices. Since \(p\) is odd, \(2x_ix_j\ne0\). Again \(h\) is nonzero.

These cases exhaust the invalid possibilities. The all-zero vector is valid; any other invalid vector has either one nonzero entry that is not 1, or more than one nonzero entry.

4. Apply Schwartz–Zippel

For every invalid vector we've proved that \(h\) is nonzero and has total degree at most 2. Each random coordinate comes from the \(p\)-element field. So

\[ \boxed{\Pr[\text{invalid vector passes}]= \Pr[h(\mathbf r)=0]\le\frac2p.} \]

That's the soundness proof. We established the precise polynomial whose zero means acceptance, showed it can't be identically zero for an invalid vote, and then used its degree to bound false acceptance. \(\square\)

The assumption that \(p\) is odd matters. If \(p=2\), the coefficient 2 in Case B becomes zero, and that argument no longer works.

Lecture §3 · Vanishing polynomial, Theorem 2

How can 99 equations become one equation?

Return to the Fibonacci discrepancy polynomial \(D(X)\) introduced before EqualityTest. We need \(D(i)=0\) at each of the 99 recurrence positions (i=0,ldots,98). EqualityTest cannot be applied directly to \(D(X)=0\) everywhere, because a valid Fibonacci interpolation need not satisfy the recurrence at points outside those positions. We need an identity that holds everywhere if and only if those 99 positions are correct.

Recall the exact discrepancy polynomial we already defined in the EqualityTest lesson:

\[D(X)=f_{\rm fib}(X+2)-f_{\rm fib}(X)-f_{\rm fib}(X+1).\]

At a step \(i\), the recurrence is correct exactly when \(D(i)=0\). So our 99 equations become the single statement “\(D\) is zero at every point of the set \(\Omega=\{0,1,\ldots,98\}\).” That is still many values to check—but now we can use polynomial algebra.

Make a polynomial with one factor for each required position:

\[\boxed{Z_\Omega(X)=\prod_{a\in\Omega}(X-a).}\]

The symbol \(\prod\) means “multiply all the factors.” For \(\Omega=\{1,2\}\), the result would be \((X-1)(X-2)\). For our Fibonacci steps, it is \(X(X-1)\cdots(X-98)\). This is called the vanishing polynomial because its value is zero at every point we want to check.

The key equivalence

Theorem 2: a polynomial \(D\) is zero at every point of \(\Omega\) if and only if some polynomial \(q\) satisfies \(D=Z_\Omega q\). That says the polynomial \(D\) is divisible by \(Z_\Omega\).

Prove both directions

If \(D=Z_\Omega q\): take any \(a\in\Omega\). One factor of \(Z_\Omega(a)\) is \(a-a=0\), so \(D(a)=Z_\Omega(a)q(a)=0\). Thus every recurrence step passes.

Conversely: suppose \(D(a)=0\) at all the distinct points \(a_1,\ldots,a_k\) of \(\Omega\). Since \(a_1\) is a root, the factor theorem gives \(D(X)=(X-a_1)q_1(X)\). Substitute \(a_2\):

\[0=D(a_2)=(a_2-a_1)q_1(a_2).\]

The points are different, so \(a_2-a_1\ne0\). The field's cancellation property forces \(q_1(a_2)=0\), which means \(q_1\) has the factor \(X-a_2\). Continue through all distinct required points. We obtain \(D=Z_\Omega q\). If \(D\) is the zero polynomial, simply take \(q=0\).

So the 99 recurrence equations are satisfied exactly when one polynomial identity \(D(X)=Z_\Omega(X)q(X)\) holds. That's not a heuristic: we've proved both implications. \(\square\)

Here's a small example that will also appear in the next interactive test. Let \(\Omega=\{1,2\}\) and \(D(X)=X^3-7X+6\). We can factor \(D(X)=(X-1)(X-2)(X+3)\). The first two factors are \(Z_\Omega\), so the quotient is \(q(X)=X+3\).

We now have the identity we were missing: all 99 recurrence constraints are equivalent to \(D=Z_\Omega q\) for some quotient polynomial \(q\). The question is no longer “does the recurrence hold at 99 separate places?” but “is this claimed identity true?” We've already proved how a random point can test a fixed polynomial identity. Applying that result to the vanishing-polynomial identity is precisely ZeroTest.

Lecture §3 · ZeroTest and Lemma 3

Can one random point check all the required zeros?

The vanishing-polynomial theorem gives the missing identity: all 99 Fibonacci steps are correct exactly when \(D(X)=Z_\Omega(X)q(X)\) for some quotient polynomial \(q\). Unlike the recurrence, this identity must hold at every field point. We can therefore use EqualityTest to check it at one random point rather than inspect every step.

Before building the full Fibonacci protocol, the lecture names this reusable operation ZeroTest. It handles any requirement that one polynomial vanish on a specified set of points. The exact same operation will later check public inputs and gate equations in PLONK, which is why we now state and prove it in general form.

We first describe the lecture's general protocol. Suppose a polynomial \(f\) of degree at most \(d\) should be zero on a set \(\Omega\) of \(k\le d\) field points. The prover puts the polynomial \(f\) and a claimed quotient \(q\) in our ideal polynomial oracle, with the enforced degree bound \(\deg q\le d\). The verifier chooses a uniform random field element \(r\), asks for \(f(r)\) and \(q(r)\), calculates the known \(Z_\Omega(r)\), and checks

\[\boxed{f(r)\stackrel{?}{=}q(r)Z_\Omega(r).}\]

We'll call this test ZeroTest. Why is it useful? Because the verifier checks two polynomial evaluations and a known product, rather than inspecting the entire list of required positions.

Make one ZeroTest pass or fail

In \(\mathbb F_{17}\), use \(\Omega=\{1,2\}\) and \(q(X)=X+3\). The honest \(f\) equals \(Z_\Omega q\); the dishonest version adds \(X-3\).

Lemma 3: ZeroTest completeness and soundness

Completeness. If \(f\) is truly zero at every required point, Theorem 2 gives an honest quotient \(q\) with \(f=Z_\Omega q\). The identity holds at every field element. The verifier therefore always accepts.

Soundness. Suppose \(f\) is not zero at every point of \(\Omega\). Then by Theorem 2 no quotient polynomial can make the identity true everywhere. For any cheating quotient \(q\) the polynomial

\[h(X)=f(X)-q(X)Z_\Omega(X)\]

must be nonzero. The verifier incorrectly accepts exactly when \(h(r)=0\).

We need a degree bound before invoking the root theorem. We know \(\deg f\le d\). The vanishing polynomial has degree \(k\le d\), and the allowed quotient has degree at most \(d\), so the product has degree at most \(d+k\le2d\). Therefore \(\deg h\le2d\).

Since a nonzero degree-at-most-\(2d\) polynomial has at most \(2d\) roots, a uniform random \(r\) lies among them with probability at most \(2d/|\mathbb F|\):

\[\boxed{\Pr[\text{false ZeroTest acceptance}]\le\frac{2d}{|\mathbb F|}.}\]

This proves Lemma 3: perfect completeness and soundness error at most \(2d/|\mathbb F|\). The reason the verifier can trust one random check is that a false claim creates one fixed, nonzero, low-degree difference polynomial. \(\square\)

Notice why the degree restriction and the timing matter. If the prover could choose a polynomial after learning \(r\), or use arbitrary degrees, the root-bound argument would not supply this error guarantee. We'll use a polynomial commitment scheme to enforce the oracle's behavior later.

Lecture §3 · Putting the polynomial IOP together

Have we really proved the hundredth Fibonacci number?

We can now answer the question that started this chapter. The prover claims a value for \(F_{100}\). We must establish that its sequence begins with the correct values, follows the recurrence at every required position, and ends at the claimed result. Interpolation represents the sequence; the vanishing-polynomial theorem turns the recurrence into one identity; ZeroTest checks that identity probabilistically. Now we combine these obligations and prove they force the original claim.

Let \(f_{\rm fib}(X)\) be the polynomial that the prover claims encodes the sequence at positions \(0,1,\ldots,100\). Its degree is at most 100. Let \(\Omega=\{0,1,\ldots,98\}\) be the positions where the recurrence must hold. Define

\[ D(X)=f_{\rm fib}(X+2)-f_{\rm fib}(X)-f_{\rm fib}(X+1), \qquad Z_\Omega(X)=\prod_{i=0}^{98}(X-i). \]

If the recurrence is correct at every step, the polynomial \(D\) is divisible by \(Z_\Omega\). The prover therefore places both \(f_{\rm fib}\) and a quotient polynomial \(q\) in our ideal polynomial oracle, claiming \(D=Z_\Omega q\).

What does the verifier actually ask?

First the verifier checks the two starting values and the claimed final value. In the consistent indexing used here, these requirements are

\[ f_{\rm fib}(0)=0,\qquad f_{\rm fib}(1)=1,\qquad f_{\rm fib}(100)=354\,224\,848\,179\,261\,915\,075. \]

Next it chooses one random field element \(r\). Instead of checking 99 recurrence positions, it requests exactly four evaluations: \(f_{\rm fib}(r)\), \(f_{\rm fib}(r+1)\), \(f_{\rm fib}(r+2)\) and \(q(r)\). It checks

\[ \boxed{ f_{\rm fib}(r+2)-f_{\rm fib}(r)-f_{\rm fib}(r+1) \stackrel{?}{=}q(r)\prod_{i=0}^{98}(r-i). } \]
See why the starting values force the sequence

Follow a shorter example: once two consecutive numbers are known, the recurrence fixes the next one. The same reasoning works all the way to step 100.

Why do these tests prove the original claim?

Suppose the oracle answers are honest and all the algebraic conditions hold. We know the values at 0 and 1. The recurrence at step 0 forces the next value to be \(0+1=1\). The recurrence at step 1 forces the next to be \(1+1=2\). After that each new value is forced by its two predecessors. By induction, all values at positions 0 through 100 must equal the Fibonacci sequence determined by the chosen starting conditions.

In particular, the value at position 100 cannot be invented independently: it is determined by the initial values and the recurrence. The separate final-value check makes sure it equals the public number being claimed.

If the claim is false, some condition must fail. Failure of a fixed endpoint is detected directly. Otherwise, at least one recurrence equation is false, so the ZeroTest difference polynomial is nonzero. Its degree bound gives the stated small probability that the random identity check accepts anyway.

So the protocol checks precisely what we needed: it ties the public result to a sequence forced by the recurrence, without reading every recurrence step. That's the reason the polynomial test can replace the long explicit computation. \(\square\)

Two problems remain

First, our polynomial oracle is imaginary. A real prover could wait for \(r\) and invent values that make the check pass. We need a commitment scheme that fixes the polynomials and authenticates their answers before the random point is chosen.

Second, there's still a cost hidden in the verifier's work. Directly evaluating \(Z_\Omega(r)\) means multiplying 99 factors. If our computation had a million steps, that would require roughly a million factors. The verifier would no longer be succinct. In PLONK we'll choose special evaluation positions, or use circuit-specific preprocessing, so the needed vanishing polynomials can be evaluated efficiently.

The first problem is a cryptographic one: how do we replace the ideal polynomial box with short authenticated evaluations? This is exactly what the next lecture section's polynomial commitment scheme is for.
