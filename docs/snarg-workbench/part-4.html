Lecture §5 · The PLONK IOP

How do we move from Fibonacci to an arbitrary computation?

The Fibonacci protocol worked because every step obeyed one recurrence. A general program may add, multiply, and reuse earlier results in different places. To use the same polynomial method, we first need to express any such computation as a collection of simple equations. The lecture uses an arithmetic circuit for this.

An arithmetic circuit \(C\) is a collection of gates connected by wires. Each gate takes two field elements and either adds or multiplies them. A wire carries a value from an input or earlier gate to a later gate. The circuit specifies which operations to perform and which values they use.

What statement will the prover prove?

Some inputs are public and known to the verifier; collect them in a vector \(\mathbf x\in\mathbb F^m\). Other inputs form the private witness \(\mathbf w\in\mathbb F^n\). A vector here is just an ordered list of field elements. The lecture defines the language

\[ L=\{\mathbf x\in\mathbb F^m:\exists\,\mathbf w\in\mathbb F^n,\ C(\mathbf x,\mathbf w)=0\}. \]

In words, the public statement \(\mathbf x\) is true if some private input \(\mathbf w\) makes the circuit output zero. The zero-output convention is convenient: to prove that a computation produces a public target \(y\), we can construct a circuit whose final result is the computed value minus \(y\), and ask whether that difference is zero.

Why does this cover the NP statements we started with? An ordinary NP verifier checks a public statement and a witness by performing elementary computational steps. Those steps can be represented by a circuit, and its acceptance condition can be expressed as a zero-output check. The circuit is therefore a structured representation of the original witness-checking problem.

In the field \(\mathbb F_2\), multiplication of bits is AND and addition is XOR, so Boolean circuits are a special case. This connects arithmetic circuits to familiar Boolean computation without changing the underlying proof goal.

We will keep the original three-gate example unchanged while learning the trace encoding.

What could a dishonest trace do?

Even if each gate performs its own operation correctly, a later gate might use a value different from the output of the gate wired to it. For example, gate 0 might output 8 while gate 2 uses 9 as its left input. So we will eventually need both gate arithmetic checks and wire consistency checks.

V · Examination workshop · HW2, Problem 4

Homework: prove that a Boolean circuit can output 1

Before PLONK, we already knew how to commit to values and prove simple relations about them. Could we use those tools to prove that a whole Boolean circuit has a satisfying input?

A Boolean circuit carries bits—0 or 1—rather than general field numbers. The homework uses XOR and AND gates. XOR, written \(\oplus\), returns 1 when the input bits differ. AND, written \(\wedge\), returns 1 only when both inputs are 1.

Call the set of satisfiable circuits \(C_{\mathrm{SAT}}\). A circuit belongs to this set if there is some input assignment making its final output 1. We assume a commitment scheme that is perfectly binding and computationally hiding, plus Sigma protocols that prove three committed bits satisfy the relation for a single XOR or AND gate.

We're about to build the full circuit proof out of those small gate proofs. Notice how close the idea is to PLONK: we need correct gates, consistent wires, and the right final output. Here, though, the proof will grow with the number of gates.

HW2 · Problem 4(a)

Build the three-message circuit proof

Let \(N\) be the number of gates. Construct a Sigma protocol by running \(N\) gate protocols in parallel. State the prover's first message, the verifier's challenge, the response, and the acceptance test.

Build the protocol step by step

Take a satisfying input assignment and calculate every wire value. For each logical wire \(w\), make one commitment \(c_w=\operatorname{Commit}(m_w;r_w)\), where \(m_w\) is the wire's bit and \(r_w\) is fresh randomness. Whenever two gates use the same wire, use the same commitment; otherwise we would lose the connection between them.

For each gate \(j\), take the commitments to its left input, right input, and output. Use the Sigma protocol for XOR or AND, whichever that gate represents, and calculate its first message \(a_j\). Send all wire commitments and all \(a_j\) values together.

The verifier sends independent random challenges \(e_1,\ldots,e_N\), one for each gate proof. The prover replies with all corresponding responses \(z_1,\ldots,z_N\), and opens the commitment to the circuit's final output as the bit 1.

The verifier accepts only if the final output opens to 1 and every gate Sigma proof verifies.

An honest satisfying assignment makes every committed gate relation true and the final output 1. Correct openings and perfect completeness of the gate protocols therefore make the circuit proof complete. \(\square\)

HW2 · Problem 4(b)

Why must an unsatisfiable circuit fail a gate check?

The preceding construction commits to each logical wire once and proves every gate relation. To establish soundness, we must show that a false circuit statement forces at least one of those gate relations to be false, then use the gate protocols' soundness guarantees.

HW2 · Problem 4(b)

Why can't this prove a false circuit?

Prove that if a dishonest prover convinces the verifier that an unsatisfiable circuit is satisfiable with non-negligible probability, one of the underlying gate Sigma protocols must violate its soundness guarantee.

Find the gate that must be lying

Perfect binding fixes the bit committed to on each logical wire. Since every gate refers to the same commitment whenever it uses the same wire, all gate triples describe one fixed assignment of values to the circuit's wires.

Suppose the output commitment opens to 1, but the circuit is unsatisfiable. If every gate relation were correct, these fixed wire values would describe an execution yielding 1—a satisfying assignment. That contradicts unsatisfiability. So at least one committed gate triple must violate its prescribed XOR or AND relation.

The full verifier accepts only if every gate proof accepts, including that false one. If the full false-acceptance probability were \(\varepsilon\), then among \(N\) gates at least one underlying gate proof would have to account for a failure probability of at least \(\varepsilon/N\). This follows by bounding the probability of the union of \(N\) possible gate-soundness failures by the sum of their probabilities.

Since \(N\) is polynomial in the input size, a non-negligible \(\varepsilon\) would give a non-negligible soundness failure for one gate proof.

Thus an accepted proof for an unsatisfiable circuit would break an underlying gate protocol. The reason we can reach this conclusion is that binding and shared wire commitments force a single wire assignment. \(\square\)

HW2 · Problem 4(c)

Could we simulate the proof without the satisfying assignment?

The homework asks for an informal honest-verifier zero-knowledge simulator. Explain the intended construction and where an additional justification is needed.

Show the simulation idea and its limitation

The official solution proposes making hiding commitments to convenient dummy wire values—for example, 1 on every wire, so the final output commitment can be opened to 1. It then proposes running the honest-verifier simulators for each gate Sigma proof and combining their transcripts.

The idea is that the commitments hide the dummy values and the simulated gate transcripts hide the witnesses. But we must check a crucial point. For an XOR gate with input bits 1 and 1, the correct output is 0, not 1. So the dummy commitment triple \((1,1,1)\) is actually a false statement for the XOR gate protocol.

The ordinary definition of honest-verifier zero knowledge only guarantees a simulator for true statements. It doesn't automatically say that the gate simulator produces accepting transcripts for false dummy triples. A rigorous proof would need an additional property of the particular gate protocol, or a justified simulation technique that handles those false dummy statements.

The homework's intended high-level strategy is to hide the wires and simulate the gate transcripts. The provided assumptions alone do not complete the simulation proof when the dummy gate statements are false. That missing condition must be stated rather than skipped. \(\square\)

Lecture §5.1 · Encoding a circuit trace

How many points must the trace polynomial store?

In the Fibonacci example, one value was stored at each integer position. A general circuit needs a value for every original input and for each gate's left input, right input, and output. We must give these occurrences distinct locations, even when two occurrences represent the same logical wire: their equality will be proved later.

Let \(|C|\) count the gates, and let \(|I|\) count all original inputs, public and private. Each gate contributes three trace entries, so the total number of required positions is

\[\boxed{d=3|C|+|I|.}\]

In our three-gate example, \(|C|=3\) and \(|I|=3\), hence \(d=12\). Interpolation can fit a polynomial through any twelve distinct field points, but the Fibonacci verifier already showed why arbitrary points are inconvenient: evaluating a large vanishing polynomial would be expensive.

We therefore choose \(\omega\) of multiplicative order \(d\), meaning \(\omega^d=1\) and no smaller positive power equals 1. Its first \(d\) powers are all distinct and form the domain

\[\Omega=\{1,\omega,\omega^2,\ldots,\omega^{d-1}\}.\]

Such a choice requires a field containing an element of order \(d\); for a prime field \(\mathbb F_p\), one convenient condition is \(d\mid(p-1)\). For \(d=12\), the figure uses \(\mathbb F_{97}\) with \(\omega=6\), which indeed has order 12. Negative powers are legitimate because \(\omega^{-j}=\omega^{d-j}\).

Verify the twelve distinct evaluation points

Change exponent \(j\). Each point is \(6^j\bmod97\). After exponent 11, the next power returns to 1.

These points are useful because their full-domain vanishing polynomial has the compact form \(X^d-1\), which we will derive shortly. First we must specify which trace values each power represents.

Lecture §5.1 · Exact trace encoding

Where do the inputs and gate values go?

We now use the domain of twelve powers of \(\omega\). Write \(f_{\rm trace}(X)\) for the polynomial that will store the values. Number the original inputs \(j=1,\ldots,|I|\). Their values occupy \(\omega^{-j}\). Number the gates \(l=0,\ldots,|C|-1\). Each gate's left input, right input, and output occupy three consecutive powers:

\[ \begin{aligned} f_{\rm trace}(\omega^{-j})&=\text{original input }j,\\ f_{\rm trace}(\omega^{3l})&=\text{gate }l\text{ left input},\\ f_{\rm trace}(\omega^{3l+1})&=\text{gate }l\text{ right input},\\ f_{\rm trace}(\omega^{3l+2})&=\text{gate }l\text{ output}. \end{aligned} \]

For the lecture's circuit, the public inputs are \(x_1=2,x_2=4\), the private input is \(w_1=3\), and the gates compute \(2\cdot4=8\), \(4+3=7\), then \(8\cdot7=56\). The complete encoded table is:

OccurrencesEvaluation pointsValues
Original inputs\(\omega^{-1},\omega^{-2},\omega^{-3}\)2, 4, 3
Gate 0\(\omega^0,\omega^1,\omega^2\)2, 4, 8
Gate 1\(\omega^3,\omega^4,\omega^5\)4, 3, 7
Gate 2\(\omega^6,\omega^7,\omega^8\)8, 7, 56

The powers \(\omega^{-1},\omega^{-2},\omega^{-3}\) are the same as \(\omega^{11},\omega^{10},\omega^9\), so they do not overlap the gate entries at powers 0 through 8.

We prescribed \(d=12\) values at 12 distinct points. Interpolation therefore gives a polynomial of degree at most \(d-1=11\) matching them. It is unique within this degree bound: two distinct degree-at-most-11 polynomials agreeing at twelve points would have a nonzero difference with twelve roots, contradicting the root theorem. The lecture allows the slightly looser bound \(\deg f_{\rm trace}\le d\).

Importantly, an incorrect execution also has a polynomial fitting its table. Interpolation is only a way of storing a proposed computation; the proof must still enforce all the correct relationships between its entries.

Before deriving those constraints, we will prove why the chosen points were helpful: for the complete domain, the vanishing polynomial is \(X^d-1\), whose value can be calculated using only logarithmically many field multiplications.

Lecture §§3 and 5.2 · Efficient vanishing polynomials

Why do the roots of unity make verification cheaper?

The Fibonacci verifier had to evaluate a product with one factor for every required recurrence position. That becomes expensive for a large computation. We chose the circuit's evaluation points as powers of a root of unity because their vanishing polynomial has a simpler form. We will prove that form rather than merely assert it.

Recall the set \(\Omega=\{1,\omega,\ldots,\omega^{d-1}\}\), where \(\omega\) has multiplicative order \(d\). The polynomial that vanishes at precisely these \(d\) points is

\[Z_\Omega(X)=\prod_{j=0}^{d-1}(X-\omega^j).\]

By the definition of \(\omega\), each point \(\omega^j\) satisfies \((\omega^j)^d=(\omega^d)^j=1\). Therefore every point of \(\Omega\) is also a root of \(X^d-1\). That observation suggests a much shorter expression for the vanishing polynomial, but we still need to show the two polynomials are equal.

Prove \(Z_\Omega(X)=X^d-1\)

Both polynomials have degree \(d\) and leading coefficient 1. Their difference therefore has degree at most \(d-1\), because the leading \(X^d\) terms cancel.

At every one of the \(d\) distinct points of \(\Omega\), both polynomials are zero. Their difference consequently has at least \(d\) roots. The root theorem says a nonzero polynomial of degree at most \(d-1\) cannot have \(d\) distinct roots. Thus the difference must be the zero polynomial, and

\[\boxed{Z_\Omega(X)=X^d-1.}\]

We have proved the identity, not just checked it on a numerical example. \(\square\)

How much work does this save?

Evaluating the original product at a point \(r\) requires roughly \(d\) factors. Evaluating \(r^d-1\) is much faster using repeated squaring. For example, \(r^{12}\) can be obtained by computing \(r^2\), \(r^4=(r^2)^2\), \(r^8=(r^4)^2\), and then \(r^{12}=r^8r^4\). The number of multiplications grows as \(O(\log d)\), rather than \(O(d)\).

This formula applies to the complete roots-of-unity domain. The public-input positions and gate-start positions are subsets of that domain. Their vanishing polynomials require their own structure or preprocessing; we must not substitute \(X^d-1\) for an arbitrary subset.

The trace polynomial is now represented on a domain whose full vanishing polynomial is inexpensive to evaluate. But interpolation does not certify the trace. We must still prove that the stored values are the right public inputs, that each gate performs the correct operation, that wire copies agree, and that the output satisfies the claim. The next lessons derive these four checks.

Lecture §5.2 · Constraint 1: output

Does the final gate certify the claimed result?

The prover has interpolated a trace polynomial, but any table has an interpolating polynomial. The verifier must now rule out four ways the trace might be false: a wrong final output, wrong public inputs, incorrect gate arithmetic, or inconsistent values across wires.

Start with the last output. Gate \(l\) stores its result at \(\omega^{3l+2}\). As gates are numbered \(0,\ldots,|C|-1\), the last output position has exponent \(3(|C|-1)+2=3|C|-1\). Our formal statement asks for a witness such that \(C(\mathbf x,\mathbf w)=0\), so the first constraint is

\[\boxed{f_{\rm trace}(\omega^{3|C|-1})=0.}\]

The verifier can authenticate this one polynomial evaluation directly. We are checking the output of the final gate of the chosen circuit, not a generic row of the trace.

The lecture's pictured three-gate circuit instead produces 56, stored at \(\omega^8\). For that illustrative computation, the corresponding target check is \(f_{\rm trace}(\omega^8)=56\). It is not an instance of the zero-output requirement. To prove that its result equals the public target 56 under the formal convention, we must modify the circuit to test that result minus 56 equals zero; the modified circuit has an additional output constraint and a different trace.

Even a correct final result can come from an invented computation. We must also make sure that the trace used the public inputs supplied by the verifier, rather than convenient values chosen by the prover.

The next constraint compares the trace's public-input positions with the public statement, without opening every input position individually.

Lecture §5.2 · Constraint 2: public inputs

How do we know the trace used the stated inputs?

The verifier knows the public inputs \(x_1,\ldots,x_m\), but the trace polynomial might store different values at their assigned positions \(\omega^{-1},\ldots,\omega^{-m}\). Opening all \(m\) positions separately would make the proof size grow with \(m\), contrary to the succinctness requirement.

We can instead make a polynomial \(f_{\rm in}(X)\) from the public inputs alone, satisfying \(f_{\rm in}(\omega^{-j})=x_j\) for \(j=1,\ldots,m\). The verifier can construct this polynomial because none of its values depend on the private witness. Define

\[ g(X)=f_{\rm trace}(X)-f_{\rm in}(X),\qquad \Omega_I=\{\omega^{-1},\ldots,\omega^{-m}\}. \]

At a public-input point \(a=\omega^{-j}\), the condition \(g(a)=0\) is exactly \(f_{\rm trace}(a)=x_j\). Thus the trace matches all public inputs if and only if \(g\) vanishes on \(\Omega_I\). Theorem 2 changes this into the existence of a quotient \(q_I\) satisfying \(g(X)=q_I(X)Z_{\Omega_I}(X)\).

The verifier needs two logically different checks. First it compares authenticated evaluations of \(g(r)\) and \(f_{\rm trace}(r)-f_{\rm in}(r)\) at a random point \(r\), establishing that the prover's \(g\) really is the required difference polynomial. Then it uses ZeroTest to establish that \(g\) vanishes on \(\Omega_I\). Otherwise the prover could pass ZeroTest using an unrelated zero polynomial as its supposed difference.

Why both checks establish the correct inputs

If the first polynomial identity holds, then \(g=f_{\rm trace}-f_{\rm in}\) at all points, except for the soundness error of the equality test. If ZeroTest also succeeds as a polynomial identity, \(g(a)=0\) for every \(a\in\Omega_I\). Therefore \(f_{\rm trace}(a)=f_{\rm in}(a)=x_j\) at each required position. In the other direction, honest public inputs make the genuine difference polynomial vanish there, giving the honest quotient. \(\square\)

The input difference and quotient are committed before the random challenge. Their degree bounds and the cost of evaluating the subset vanishing polynomial still matter; the full-domain identity \(X^d-1\) must not be used as though it were the vanishing polynomial of \(\Omega_I\). The lecture proposes preprocessing or exploiting structure for the required efficient evaluations.

The trace now refers to the correct public inputs and claims the required output. The next check enforces every intermediate addition or multiplication, without examining each gate separately.

Lecture §5.2 · Constraint 3: gate arithmetic

One equation for addition and multiplication gates

A trace could contain the right public inputs and final output but invent intermediate results. Each gate must apply the operation specified by the circuit. For a gate with left input \(L\), right input \(R\), and output \(O\), the correct relation is \(L+R=O\) for addition and \(LR=O\) for multiplication.

Since the gate type is public, encode it using a selector bit \(s\), equal to 1 for addition and 0 for multiplication. The two cases combine into the single equation

\[\boxed{s(L+R)+(1-s)LR-O=0.}\]

At \(s=1\), the multiplication term disappears, giving \(L+R-O=0\). At \(s=0\), the addition term disappears, giving \(LR-O=0\). Thus the same equation enforces the correct operation for either gate type.

For each gate \(l\), build a selector polynomial \(f_{\rm sel}(X)\) such that \(f_{\rm sel}(\omega^{3l})\) equals that gate's public selector. The three-gate example uses multiplication, addition, multiplication, so its selector values at \(\omega^0,\omega^3,\omega^6\) are \(0,1,0\).

At the beginning of a gate, represented by \(X=\omega^{3l}\), the trace polynomial stores \(L=f_{\rm trace}(X)\), \(R=f_{\rm trace}(\omega X)\), and \(O=f_{\rm trace}(\omega^2X)\). Substituting these into the equation defines

\[ \begin{aligned} f_{\rm gates}(X)={}& f_{\rm sel}(X)\left[f_{\rm trace}(X)+f_{\rm trace}(\omega X)\right]\\ &+\left[1-f_{\rm sel}(X)\right]f_{\rm trace}(X)f_{\rm trace}(\omega X)\\ &-f_{\rm trace}(\omega^2X). \end{aligned} \]

This expression is not arbitrary: each of its three terms comes directly from the addition/multiplication selector equation. At \(X=\omega^{3l}\), it evaluates to zero precisely when gate \(l\) performs its prescribed operation.

We have built a polynomial whose zeros correspond to correctly evaluated gates. The next card turns that observation into a ZeroTest over all gate-start positions, and explains why the selector is preprocessed.

Lecture §5.2 · Gate ZeroTest and preprocessing

How can one random identity check every gate?

The gate polynomial \(f_{\rm gates}\) was constructed so that its value at the start of gate \(l\) is that gate's arithmetic error. Our required positions are therefore

\[ \Omega_{\rm gates}=\{\omega^0,\omega^3,\omega^6,\ldots, \omega^{3(|C|-1)}\}. \]

Every gate obeys its addition or multiplication rule if and only if \(f_{\rm gates}\) is zero at each position in this set. By the vanishing-polynomial theorem, that is equivalent to the existence of a polynomial \(q_{\rm gates}\) such that

\[ f_{\rm gates}(X)=q_{\rm gates}(X)Z_{\Omega_{\rm gates}}(X). \]

That is exactly the kind of global identity ZeroTest can verify at a random field point. The verifier authenticates the relevant evaluations of \(f_{\rm trace}\), \(f_{\rm sel}\), and \(q_{\rm gates}\), then constructs the left-hand side using the selector formula. For an honest trace, each gate equation holds and the quotient exists. For an incorrect trace, the proposed identity is false, so a low-degree random evaluation rejects it except with the polynomial-root error.

The degree restriction is important. If \(\deg f_{\rm trace}\le d-1\) and \(\deg f_{\rm sel}\le d-1\), the product of three such terms shows \(\deg f_{\rm gates}\le3(d-1)\). The exact ZeroTest bound must use this gate-polynomial degree, not automatically the degree of the trace itself.

But the verifier must not construct \(f_{\rm sel}\) from every gate during each proof; that would require work proportional to \(|C|\). Since the selector depends only on the public circuit and not on the witness, the lecture computes and commits to it once in circuit-specific preprocessing. Its committed evaluations can then be reused across proofs for that circuit.

Finally, the gate-start set is only a subset of the roots-of-unity domain. Its vanishing polynomial is not automatically \(X^d-1\); efficient evaluation may require additional structure or preprocessing.

Correct gate arithmetic is still insufficient. One gate can output 8 while another gate, supposedly connected to it, uses 9. The missing requirement is equality between every occurrence of the same logical wire.

Lecture §5.2 · Condition 4: wiring

Why can correct gate equations still describe the wrong circuit?

The gate polynomial checks each gate independently. But a circuit is more than a list of independent gates: the output of one gate must become the input of the gates connected to it. If the prover changes a value between two occurrences of the same wire, all local gate equations could still pass. We need to enforce those equalities separately.

In the lecture's three-gate circuit, gate 0 outputs 8 and gate 2 must use that 8 as its left input. Gate 1 outputs 7 and gate 2 must use 7 as its right input. In trace notation these requirements are

\[ f_{\rm trace}(\omega^2)=f_{\rm trace}(\omega^6),\qquad f_{\rm trace}(\omega^5)=f_{\rm trace}(\omega^7). \]

The original inputs also appear again inside gates. For example, public input \(x_2=4\) occurs at \(\omega^{-2}\), gate 0's right input at \(\omega^1\), and gate 1's left input at \(\omega^3\). All three positions must have the same value. The private input \(w_1\) likewise appears both in its original input position and as an input to gate 1.

See a false trace that passes the gate checks

Suppose gate 0 still computes \(2\cdot4=8\) and gate 1 still computes \(4+3=7\). But the prover gives gate 2 inputs 9 and 17 and output 56. In \(\mathbb F_{97}\), \(9\cdot17=153\equiv56\pmod{97}\). So gate 2's multiplication is locally correct, and the public output still equals 56. The trace is false because gate 2 did not use the values 8 and 7 from the wires connected to it.

Which constraint detects each dishonest trace?

Lecture §5.2 · Rotation polynomial

How can one constraint enforce all wire copies?

The previous example failed because two occurrences of the same logical wire carried different numbers. We need a mathematical rule connecting every occurrence of each wire. The rotation polynomial expresses those required equalities.

How does the rotation polynomial express every wire equality?

For each logical wire, list all positions where its value appears and arrange those positions in a cycle. For the copies of \(x_2\), one such cycle is \(\omega^{-2}\to\omega^1\to\omega^3\to\omega^{-2}\). Define a map sending each position to the next position that carries the same logical wire. The lecture represents that map by the rotation polynomial \(f_{\rm rot}\), which depends only on the public wiring of the circuit.

The intended constraint is

\[\boxed{f_{\rm trace}(a)=f_{\rm trace}(f_{\rm rot}(a)) \quad\text{for every }a\in\Omega.}\]
Inspect the rotation cycle of one wire

Select a logical wire. The arrows show the positions that \(f_{\rm rot}\) maps to each other. Change one occurrence to see which equality fails.

Why do these equalities force consistent wires?

Take one wire whose occurrences form the cycle \(a_1\to a_2\to\cdots\to a_k\to a_1\). The constraint gives equality of the values at \(a_1,a_2\), then at \(a_2,a_3\), and so on. By transitivity, all occurrences carry one value. Conversely, if every occurrence already carries that same value, every equality in the cycle holds. Thus the rotation constraints are equivalent to correct wire copying. \(\square\)

The lecture does not derive the full polynomial IOP that checks this rotation condition efficiently. It states the condition and explains that the required polynomial depends only on the circuit, so it can be committed to during preprocessing. We should not mistake the condition itself for a complete cryptographic security proof.

Lecture §6 · Why the constraints are sufficient

Why do the four constraints prove the circuit statement?

We have four requirements for the trace polynomial: correct public inputs, correct final output, correct arithmetic at every gate, and equal values at every occurrence of a wire. Before combining them into a proof system, we must establish that these conditions actually imply the public statement \(C(\mathbf x,\mathbf w)=0\).

From four valid constraints to a genuine computation

Assume the trace satisfies all four conditions. The public-input condition fixes the values supplied by the verifier. The remaining original-input positions specify a candidate private witness \(\mathbf w\).

Process the circuit in gate order. The first gate receives its designated input values. Its gate equation forces its output to be the correct sum or product. The wiring condition forces every later occurrence of that output wire to carry the same value. Therefore the next gate receives the values dictated by the circuit rather than values chosen independently by the prover.

Repeat this reasoning through the gates. By induction, every stored gate output equals the value obtained by genuinely evaluating the circuit on \((\mathbf x,\mathbf w)\). The final-output condition says this genuine evaluation equals zero. Hence

\[\boxed{C(\mathbf x,\mathbf w)=0.}\]

We have proved that a trace satisfying the four constraint families supplies an actual witness for the public statement. Conversely, an honest evaluation produces values satisfying all four families. This is the logical correctness argument the polynomial checks must implement. \(\square\)

Follow the circuit-correctness proof

At each stage, the gate equation and wiring constraints force the next value. This example illustrates the induction proved above; it does not replace the general argument.

We have proved that the four conditions force a genuine satisfying circuit execution. That is the mathematical claim PLONK must establish. The next lesson explains how the prover commits to the required polynomials and how the verifier checks those conditions without reading the full trace.

Lecture §6 · A PLONK SNARG

How does PLONK verify those constraints succinctly?

The previous lesson proved that satisfying all four circuit constraints implies a valid witness. We now need a practical argument: the prover must authenticate the relevant polynomial values, while the verifier checks the constraints without examining the entire circuit trace.

How does the final SNARG organize the work?

The lecture separates work that can be reused from work that depends on a particular witness. This matters because computing the full circuit-specific polynomials during every verification would destroy succinctness.

Universal setup. Run the polynomial commitment scheme's \(\operatorname{Setup}\) algorithm to produce public parameters \(pp\) for a supported maximum degree or circuit size. This setup does not depend on the particular circuit \(C\).

Circuit-specific preprocessing. From the public circuit, compute the selector polynomial \(f_{\rm sel}\) and rotation polynomial \(f_{\rm rot}\), then commit to them. Their commitments become part of the circuit's public verification information. This preprocessing takes \(O(|C|)\) time but can be reused for many proofs about the same circuit.

Proof for a particular instance. Given public input \(\mathbf x\) and private witness \(\mathbf w\), the prover evaluates the circuit, interpolates the trace polynomial \(f_{\rm trace}\), and commits to it. The remaining checks use polynomial identities and authenticated evaluations rather than revealing the whole trace.

The universal setup prepares the commitment system, while preprocessing fixes the public circuit's selector and wiring polynomials. We can now describe the four proof components for a particular statement and see how the verifier checks them without reading the entire trace.

Lecture §6 · The final SNARG protocol

What does the prover send, and what does the verifier check?

We already proved that four circuit constraints imply a valid witness, and the setup stage has fixed the public selector and wiring polynomials. We now need to authenticate the trace and the polynomial identities that enforce those constraints.

The four checks in the final protocol

1. Output. Authenticate the trace evaluation at the last gate's output position and require it to be zero.

2. Public inputs. Build \(f_{\rm in}\) from the public statement. The prover commits to \(f_{\rm trace}-f_{\rm in}\) and the quotient for its ZeroTest over the public-input positions. The verifier checks consistency and the vanishing identity at random points.

3. Gate arithmetic. Use the preprocessed selector polynomial and the trace to form the gate polynomial \(f_{\rm gates}\). The prover commits to its vanishing-polynomial quotient over the gate-start positions. The verifier checks the corresponding identity using authenticated random evaluations.

4. Wiring. Use the preprocessed rotation polynomial to check that every occurrence of a logical wire has the same value. The lecture states this requirement but does not derive its full polynomial IOP; the detailed protocol is another polynomial-checking component.

Where does succinctness come from?

The prover still performs the computation and constructs the required polynomials. The verifier, however, checks a small number of authenticated polynomial evaluations rather than every gate. The structured domain makes important vanishing-polynomial evaluations efficient, while circuit-specific preprocessing avoids rebuilding the selector and rotation polynomials for each proof.

Let \(|C|\) be the number of gates, \(|\mathbf x|\) the public-input length, \(|\pi|\) the proof length, \(T_V\) the verifier's time, and \(\lambda\) the security parameter. The lecture's intended succinctness bounds are

\[ |\pi|=O\bigl(\lambda,\operatorname{polylog}|C|\bigr),\qquad T_V=O\bigl(\lambda,|\mathbf x|,\operatorname{polylog}|C|\bigr). \]

These are target bounds for suitable polynomial commitment implementations, not numerical costs established by our three-gate example. The verifier may spend time proportional to the public input because it must read the statement; the proof length should not grow linearly with the circuit.

What makes the argument non-interactive?

The polynomial IOP originally requires random evaluation challenges after the prover's commitments. Fiat–Shamir derives these challenges from the committed first messages and public data in the random-oracle model. The prover can then publish one proof string containing the commitments and authenticated responses.

Different polynomial commitment schemes lead to different setup and security properties, including whether a trusted setup is required or whether post-quantum security is available. The lecture does not give a concrete commitment construction, the full wiring IOP, or the zero-knowledge randomization of PLONK; we should not claim those missing details have been proved here.
